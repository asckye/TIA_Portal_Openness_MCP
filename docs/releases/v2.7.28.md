# v2.7.28

引擎 **2.7.28.0**（V20/V21 均重建）。工具 364 → **367**，默认 lite 56 项不变。WinCC Unified 阶段（[路线图 §2.0](../development/roadmap.md#20-官方-api-全量对齐计划) 阶段 2）子批次 ⑤：剩余 21 个功能类型里真正缺工具的三处——变量 WinCC ML 导入导出、全局脚本模块导入导出、OPC UA 报警 xml 导入；其余（阈值、替代值、系统变量、驱动属性、审计类、列表、Cpm）由已有通用工具到达，真机验证后登记。

## 新增

| 工具 | 内容 | 官方入口 |
|---|---|---|
| `ExchangeUnifiedTags`（新） | 变量的 WinCC ML（YAML）交换：`export` 经 `HmiTagComposition.Export(DirectoryInfo[, name])` 写入新目录（`<name>.hmi.yml` + TIA 的 `NameData.yml` / `.ile` / `*.def.hmi.yml` 副文件），每个文件哈希；`import` 经 `Import(DirectoryInfo[, name])` 读现有目录，导入后核对 `expectedTagNamesJson`。`tagTable` 可为唯一表名或 `/组/子组/表`，空则为设备根 `Tags`。此前 `ExportHmiTagTable` 对 Unified 报 "unsupported"——Unified 变量表没有 SimaticML `Export(FileInfo)`，只有这条 WinCC ML 路径 | 官方 "TagTable.Tags.Export() / Import()"（RT Unified） |
| `ExchangeUnifiedScriptModules`（新） | 全局脚本模块：导出全部（`Scripts.Export(dir)`）或单个（`HmiScriptModule.Export(dir[, name])`，即 `IChromDataExchangeExport`），导入 `Scripts.Import(dir[, name])`，前后列出模块名 | `HmiScriptModuleComposition` / `HmiScriptModule` |
| `ImportUnifiedOpcUaAlarms`（新） | 连接上的 `OpcUaAlarm` 服务：`read` 列 `DisplayNames` 并可 `GetNodeId(displayName)`；`import` 从 .xml 读入 OPC UA 报警信息（原生 bool）。非 OPC UA 连接返回 `NotSupportedOnVersion` | `HmiConnection.GetService<OpcUaAlarm>()` |

## 顺带修复

`Object` 类型属性（变量范围 `LowerRange.Value`、替代值、阈值 `Value`…）写入后读回差异：TIA 把 JSON 数字 `0` 存成字符串 `"0"`，此前按 CLR 类型相等判定报"readback differs"（值其实已写入）。现在跨类型按不变文化文本与数值比较（`EngineeringScalarProperties.SameValue`），所有嵌套/标量写入路径共用。2.7.27 引擎真机上还确认：变量删除可经 `ManageUnifiedObjectParts`（`collectionProperty=Tags`，`partName` 精确变量名）。

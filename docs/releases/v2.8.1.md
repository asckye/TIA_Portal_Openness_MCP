# v2.8.1

发布模型改动（PATCH，引擎与工具不变：453 / lite 59 / 离线 2456 / 形状 V20 2805 · V21 3097）。维护者对 2.8.0 记下的“继续提交 exe、不用自托管 runner”说不同意，定为：**不提交 exe，发布 ZIP 由本机 `Release.ps1` 直接上传**。本版就是这件事，外加同一天的两条整理要求（只保留 master 分支；英文文档不含中文）。

## 二进制不入库

- `.gitignore`：`/runtime/v20/`、`/runtime/v21/`、`/TiaMcpConfigurator.exe`；`git rm --cached` 把索引里的 133 个二进制文件去掉（磁盘和历史都还在）。`runtime/README.md` 保留并说明。
- 哈希仍然提交：`manifest/release-build.json`（两版 runtime 逐文件 sha256 + 源码哈希 + 验证计数）、`manifest/configurator-build.json`（配置器 EXE sha256 + 源文件哈希）、`manifest/delivery.json`（包名、两份记录的哈希）。这三份就是“可审的真相”。
- `Package-Release.py`：Git 树（`git ls-files`）+ 本机 `runtime/v20`、`runtime/v21` 全部文件 + `TiaMcpConfigurator.exe`；任何二进制被跟踪、缺失、或哈希对不上清单都拒绝；其余校验（源码哈希、版本、验证计数、包内 Validate-Bundle）不变。
- 新脚本 `scripts/checks/Verify-ReleaseAsset.py <zip>`：sidecar 的 SHA-256 = ZIP；checkout 里每个被跟踪文件都在 ZIP 里且字节相同；ZIP 里的 runtime 清单与哈希 = `release-build.json`；`TiaMcpConfigurator.exe` = `configurator-build.json`；多出来的只能是 `RELEASE_STATUS.txt` 与 `manifest/release-file-hashes.json`，二者的源码提交 = HEAD；`delivery.json` 的包名 = ZIP 名。本机上传前跑一次，工作流发布后再跑一次。

## 本机上传：`Publish-Release.ps1`

`scripts/build/Publish-Release.ps1 -Version X.Y.Z`（Release.ps1 自动调用，也可单独跑）：

1. 令牌：`-Token` → `GITHUB_TOKEN` → Git Credential Manager 存的 github.com 凭据（`git credential fill`；PowerShell 管道和 .NET 重定向 stdin 都会让 git 报 “missing protocol field”，改由 cmd 从临时文件管进去）。令牌从不打印。
2. `bin-build/releases/vX.Y.Z/package-result.json` 的 ZIP：大小、sha256、`sourceCommit` = GitHub 上的 master HEAD = tag `vX.Y.Z` 指向的提交（注解 tag 解引用）；`manifest/delivery.json` 的版本与包名一致。
3. 草稿 Release（已有草稿则复用；已发布的 Release 一律拒绝，资产永不改动），正文 = `docs/releases/vX.Y.Z.md`（相对链接改为 blob URL）+ 包名 / 文件数 / 字节 + 源码提交 + SHA-256。
4. 上传 ZIP 与 `.sha256`：草稿上同名的残留资产先删；每个资产上传后从 API 回读，必须 `state=uploaded`、大小相同、`digest` = `sha256:<本地>`；失败退避重试最多 6 次。
5. 发布（`draft=false`、latest），再次列资产确认两项都在，写 `published-release.json`。`-DraftOnly` 停在上传后，`-DeleteDraft` 删草稿。

在真仓库上用一次性草稿（tag `v0.0.0-upload-probe`，草稿不建 tag、外部不可见）验证过：建草稿 → 上传 → 回读 `digest` 一致 → 删资产 → 删草稿，全程无残留。

## `Release.ps1` 的新顺序

前置检查 → 版本号 8 处 → Build-Release → 本地闸门 → **一次提交** `Release X.Y.Z: <summary>`（暂存时若出现 `runtime/` 或 exe 直接失败）→ `Package-Release.py` → `Verify-ReleaseAsset.py` → 推送 master → 带令牌查 Actions API 等 `validate-bundle` / `offline-checks`（不再抓网页）→ 注解 tag → `Publish-Release.ps1` → 等 `Verify published release` 绿 → DONE。`-Resume`：提交已在时从打包 / 推送接着走（包的 `sourceCommit` ≠ HEAD 就重新打包）。`Publish-Release.cjs` 删除。

## 工作流

- `validate-bundle`：`Check-Repository.py --no-binaries`、`Validate-Bundle.ps1 -Strict -NoBinaries`（清单、版本、启动器语法、源码哈希照查；`runtime/` 与配置器 EXE 的存在 / 版本 / 哈希跳过）、`Build-Configurator.ps1 -Test`。
- `Verify published release`（`release.yml`，`release: published` 触发，`run-name: Verify vX.Y.Z`）：tag = `v` + `delivery.json` 且指向 master HEAD → `gh release download` ZIP + `.sha256` → `Verify-ReleaseAsset.py` → 解包后 `Validate-Bundle.ps1 -Strict` + `Check-Repository.py` → 摘要。红了表示发布的资产与审过的源码不符：不改 Release，出补丁版本。

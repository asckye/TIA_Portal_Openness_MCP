# v2.7.30

引擎 **2.7.30.0**（V20/V21 均重建）。工具 367 → **380**，默认 lite 清单 56 项不变。本版是"官方 Openness API 全量对齐"计划 [路线图 §2.0](../development/roadmap.md#20-官方-api-全量对齐计划) **阶段 3 的第一个子批次 ③-①：Base 硬件网络深层**——把官方章节 "Functions on networks"（IO 系统 / 域设置 / 传输区 / 端口互连）和 "Functions on device items"（通道 / 地址 / 硬件标识符）以及 PLC 服务章节里的 Web 服务器 / OPC UA 用户管理逐页对照 `Siemens.Engineering.Base.xml` 封装成 13 个强类型工具。

## 为什么先做硬件网络

2.7.29 的审计里 Base 程序集还有 89 个功能类型 / 332 个成员没有专用封装，其中 `IoSystem` / `IoConnector` / `SyncDomain` / `MrpDomain` / `TransferArea` / `Channel` / `WebserverUser` 这一族约 100 个成员是 TIA 界面里最常手工做、而现有工具只能"探针式"触碰的部分（`GetDeviceItemNetworkInfo` 只列服务名）。这一批全部在 `Siemens.Engineering.dll`（V21 为 `Siemens.Engineering.Base.dll`），V20/V21 都有，唯一的版本差异是 `TransferAreaType.F_CD`（V21 新增）、`Channel.GetService<T>` / `Address.GetService<T>`（V21 新增）和 `Address.AssignProcessImageToOrganizationBlock(OB)`（V21 移除）。

| `ManageIoSystem` | `create`（`IoController.CreateIoSystem(name)`，接口须已连子网且无 IO 系统）、`delete`、`update`（Name/Number + 动态属性）、`connect` / `disconnect`（`IoConnector.ConnectToIoSystem` / `DisconnectFromIoSystem`，含 DP 主站系统） | `IoController.CreateIoSystem`、`IoSystem.Delete`、`IoConnector.*` |
| `ReadNetworkDomains` | 子网的 `SyncDomainOwner.SyncDomains`（Name、ConvertedName、IsDefault、参与者、`HighPerformanceActive` / `FastForwardingActive`）、`MrpDomainOwner.MrpDomains`（参与者、`IsDefault` / `ManagerOutsideOfProjectActive`）与子网各接口项的 `MrpInstances`（`ConnectedMrpDomain`、`RingPort1/2`） | `SyncDomainOwner`、`MrpDomainOwner`、`MrpInstancesOwner` |

| `UpdateDeviceItemChannel` | 对一个精确通道 `SetAttribute`，CLR 类型取自当前值并读回 | `Channel.SetAttribute` |
| `ReadDeviceAddressing` | 设备或设备项的 `HwIdentifiers`（Identifier、控制器归属）、`DeviceItem.Addresses`（StartAddress / Length / IoType / `AddressControllers` / `Context` / `ProcessImage` / `IsochronousMode` / `InterruptObNumber`）；作为控制器时附 `AddressController.RegisteredAddresses`、`HwIdentifierController.RegisteredHwIdentifiers` | `Address`、`HwIdentifier`、`AddressController`、`HwIdentifierController` |
| `UpdateDeviceAddress` | 按 IoType + 当前 StartAddress 定位一个地址：StartAddress / Length + 动态属性；`processImageObName` 在 V20 调 `AssignProcessImageToOrganizationBlock(OB)`，V21 明确拒绝 | `Address.StartAddress`、`Address.SetAttribute` |
| `ManageDeviceUserGroup` | `read`（根设备、顶层组、`UngroupedDevicesGroup`）、`create`（缺失父级自动创建）、`rename`、`deleteEmpty` | `DeviceUserGroupComposition.Create/Find`、`DeviceUserGroup.Delete/Groups/Devices`、`DeviceGroup` |
| `ManageDeviceUsers` | `family=webserver`（CPU `WebserverUserManagement`：read / create（权限标志名 + 密码）/ delete / setPermissions / setPassword）、`simpleWebserver`（SIWAREX 固定用户槽：setActive / rename / setPermissions None·ReadOnly·ReadWrite / setPassword）、`opcUa`（`OpcUaUserManagement`：read / create / delete / setPassword）；密码转 `SecureString`、绝不回显 | `WebserverUserComposition.Create/Find`、`WebserverUser.*`、`SimpleWebserverUser.*`、`OpcUaUserComposition.Create/Find`、`OpcUaUser.*` |
| `ManagePortInterconnection` | 端口设备项的 `NetworkPort`：`read`（`ConnectedPorts`）、`connect` / `disconnect`（`ConnectToPort` / `DisconnectFromPort`），按 `ConnectedPorts` 计数核对 | `NetworkPort` |

所有写入默认 `dryRun=true`，删除需 `confirmDelete=true`，执行后按原生对象读回（计数、`Find`、属性值）；动态属性逐名读取、失败逐条列出，不假定存在。实现约定：`ExactEngineeringHardware(devicePathJson, itemPathJson)` 定位设备项，`Project.Subnets.Find` 定位子网，`EngineeringScalarProperties` 写标量、`SetAttribute` 写动态属性。

只在 API 上学到的事实（真机未验证，见下）：`WebserverUserPermissions` 的值是独立单比特却**没有** `[Flags]`，组合值 `ToString()` 出来是数字，本版按位手工解码；`SimpleWebserverUserComposition` 没有 `Create`、`SimpleWebserverUser` 没有 `Delete`（SIWAREX 用户是固定槽位）；`ISyncDomainParticipant` 由 `NetworkInterface` 与 `IoSystem` 实现，本版只支持接口作为参与者；`Subnet.Nodes` / `Subnet.IoSystems` 是关联而非组合。

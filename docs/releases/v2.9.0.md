# v2.9.0

删除类工具的交叉引用查询改为显式开关。MINOR（`DeletePlcBlock` / `DeletePlcType` / `DeletePlcTagTable` 各加一个可选参数，默认行为变了：不再自动查交叉引用）；工具 453、lite 59、离线 2456、形状 V20 2805 / V21 3097 不变。

## 起因

维护者 2026-09-21 真机：“`DeletePlcBlock` 干跑（它会做交叉引用查询）把 TIA 搞挂了。”干跑路径里唯一会让 TIA 做重活的调用是 `CrossReferenceService.GetCrossReferences(AllObjects)`——2.7.46 / 2.7.47 在 `项目1` 的小块上通过过，在维护者的真实工程上让 TIA Portal V21 整个退出（现象同 handoff §4 的其它退出点：进程消失、`EngineeringObjectDisposedException`，未保存的改动随之丢失）。工程 / 块 / TIA 日志待维护者补充；在查明之前，引擎不能再在“默认、干跑、号称无副作用”的路径上触发它。

## 改动

- `Portal.DeletePlcBlock / DeletePlcType / DeletePlcTagTable(..., bool crossReferences = false)`：`crossReferences=false` 时跳过查询，结果 `crossReferenceQueried=false`、`crossReferenceAvailable=false`、`crossReferences=null`，警告“交叉引用未查询（默认）……要看谁在引用它，先 SaveProject，再传 crossReferences=true 或单独调 GetCrossReferences”；`true` 时行为同以前（查不到时仍是“查不到 ≠ 没人用”）。
- 三个 MCP 工具新参数 `crossReferences`（描述写明真机退出事实）；干跑消息区分“未查询”与“查不到”。`DeletePlcBlock` 描述不再说干跑“报告交叉引用”。
- `GetCrossReferences` 描述加 KNOWN RISK：同一查询在维护者工程上让 TIA 退出，先存盘、做好重启 TIA 的准备。
- 台账 `GetCrossReferences` / 三个删除工具的备注、handoff §4 退出点 ⑧。

# v2.7.38

引擎 **2.7.38.0**（V20/V21 均重建）。工具 413 → **421**，默认 lite 清单 56 项不变。本版是"官方 Openness API 全量对齐"计划 [路线图 §2.0](../development/roadmap.md) 阶段 6（选件包）的第一批 ⑥-①：**SiVArc**（`Siemens.Engineering.Sivarc.dll`，V20 在 `Siemens.Engineering.dll` 里）——**SiVArc 的功能类型缺口 33 / 198 归零**；另补 2.7.37 真机发现的 `ReadLibraryType typeKind` 四个子类。虚拟机没有 SiVArc 许可，本族只做形状检查（V20 / V21 逐成员核对），所有工具在服务缺席时明确回 NotSupported。

## 新增工具（域 HMI / PLC，SiVArc）

| 工具 | 动作 | 官方入口（SiVArc 手册 "SiVArc Openness" 章） |
|---|---|---|
| `ReadSivarcRuleTree` | 六个规则族（`category` screens / tags / advancedTags / alarms / copies / textLists ↔ `Sivarc.ScreenRules` … `TextlistRules`）的类型化层次：不给 `tablePath` 时读 `folderPath` 下的用户文件夹树与规则表（`IsDefault`、组 / 规则计数、`LibraryTypeInstanceInfo.LibraryTypeVersion` 连接的库类型版本）；给 `tablePath` 时读该表的顶层规则（分页）与嵌套规则组（到 `maxDepth`，每组 200 条）；规则行按族类型化（条件 / 运算符 / 启用 / 布局字段 / 循环计数 / 变量表 / 文件夹结构 / 程序块与库对象引用） | "Working with screen rule tables and folders"、"Accessing screen rules and groups"、"Accessing rule table in library type" |
| `ManageSivarcRuleContainer` | `kind` folder（`*RuleFolderComposition.Create` / `Delete`，只删空文件夹）或 table（`*RuleTableComposition.Create(name)`、`createFromType` = `CreateFrom(*RuleTableTypeVersion)`（`typePath` + `typeVersion`，工程库或已打开的全局库）、非默认表 `Delete`）；`path` 相对族系统文件夹；删除按 `Find` 核对 | "Creating screen rule table / folder"、"Deleting screen rule table and user defined rule folder"、"Creating an instance of rule table" |
| `ManageSivarcRule` | 表内的规则或规则组（`kind` rule / group，`rulePath` 相对表）：read / create（`Create(name)`）/ createFromMasterCopy（`CreateFrom(MasterCopy, CreateOptions.Replace|Rename)`）/ update / delete；`propertiesJson` 类型化标量（Name / Comment / Condition / ConditionOperator / Enabled，screens 加 LayoutField / LoopCount，tags 加 TagGroupHierarchy / TagTable，copies 加 FolderStructure）；`referencesJson` 给 `ProgramBlock` / `LibraryScreen` / `ScreenObjectLibraryItem` / `TagLibraryItem` / `AlarmLibraryItem` / `TextlistLibraryItem` / `LibraryObject` 赋 PLC 块、母本、库类型或库文件夹（`null` 清空）；`deviceSelectionJson` 经 `SetAttributes` 写 PLC / HMI 设备列，`deviceNamesJson` 经 `GetAttribute` 读；画面规则回报 `GetLayoutFields()` | "Creating rule object and rule group"、"Assigning properties for rules and rule groups"、"Copying rules or groups from library"、"Accessing library objects"、"Accessing folders in Master copy/Type of a Screen"、"Configuring PLC and HMI device"、"Configuring Tag rules" |
| `ReadSivarcBlockDefinitions` | 代码块的 `SivarcDataProvider`：`TagDefinitions`（名 / 值 / 注释）、`TextDefinitions`（名 / 表达式 / 注释 / 多语言文本）、V21 `TagMemberSettings`（`UseCommonConfiguration`、`CommonParameters`、`BlockParameters` 的采集周期 / 模式） | "Configuring Tag/Text definitions"、"Configuring Tag Member Settings" |
| `ManageSivarcBlockDefinition` | `kind` tagDefinition / textDefinition（create / update / delete，文本定义的 `textsJson` 按工程语言写 `MultilingualTextItem.Text`）、tagMemberSettings / commonParameters / blockParameter（update，V21） | 同上 |
| `ResolveSivarcExpression` | `Sivarc.GetExpressionResolver(codeBlock, hmiDeviceItem, libraryItem).Resolve(expression)` → 每个块实例一行（`instanceName` / `callPath` / `result`）；只读，要求 PLC 已编译 | "Openness API for expression resolver" |
| `ManageSivarcScreenLayout` | V21 `LayoutData` 画面服务（经典 `Screen` 与 Unified `HmiScreen` 都是服务提供者）：export 写 YML（新文件，回报大小与 SHA-256）、import 回报 `State` / `NumberOfLayouts`；V20 回 NotSupported | "Export and Import of layout fields in screen" |
| `UpgradeSivarcDefinitions` | `PlcSoftware.GetService<SivarcDefinitionsUpgrader>().Upgrade()` → `WarningCount` + 递归反馈消息；默认预览 | "Openness API for Upgrade SiVArc definitions" |

类型化改造（签名兼容）：`GenerateSiVArc` 改走类型化 `Sivarc.Generate`（新增可选 `additionalHmiDeviceNamesJson` 走多设备重载 `Generate(IEnumerable<string>, IEnumerable<string>, GenerationOptions)`），`generationOptions` 按官方 `[Flags]` 名解析（`AllTags|FullGeneration`），返回类型化 `SivarcGenerationResult`（`IsGenerationSuccessful` / `ErrorCount` / `WarningCount`）与递归的 `SivarcFeedbackMessage` 行（`Path` / `Description` / `MessageType` / `DateTime` / 计数 / 子消息）；`ReadSiVArcRules` / `ManageSiVArcRule` 的锚点改为类型化 `project.GetService<Sivarc>()`；`ReadLibraryType typeKind` 新增 `hmiFaceplate` / `hmiVbScript` / `hmiCScript`（经典 `FaceplateLibraryType` / `VBScriptLibraryType` / `CScriptLibraryType`）、`unifiedScriptModule`（`HmiUnified.Library.ScriptModuleType`，2.7.37 真机 8 个）、`sivarc*RuleTable` / `sivarcExpressionTable`（SiVArc 7 个规则表类型）与 `dccBlockType`（`DcbBlockTypeLibraryType`）；`ManageUnifiedScreenLayout` 文案不再说"布局字段导入导出官方无 API"——那是 SiVArc 选件的 `LayoutData`。

只在 PublicAPI 上核实的事实：`Sivarc` 是工程服务（`IUpdateProjectScope`，可作 `UpdateProject` 的范围），`SivarcDataProvider` 是代码块服务，`SivarcDefinitionsUpgrader` 是 `PlcSoftware` 服务，`LayoutData` 是画面服务；六个规则族没有公共基类，每族 `Rules` 锚点 → `Folders` / `Tables` → 表 `Groups` / `Rules` → 组再 `Groups` / `Rules`，结构相同但类型各异（引擎按族做类型化开关）；`ScreenRule` / `ScreenRuleGroup` 才有 `LayoutField` / `LoopCount` / `GetLayoutFields` / `LibraryScreen` / `ScreenObjectLibraryItem`，`TagRule` / `AdvancedTagRule` 有 `TagGroupHierarchy` / `TagTable`，`CopyRule` 有 `FolderStructure` / `LibraryObject`，`AlarmRule` / `TextlistRule` 有 `*LibraryItem`；V20 用标记接口 `ISivarcProgramBlockSource` / `ISivarcDataBlockSource` / `ISivarcLibraryItem` / `ISivarcLibraryMasterCopy` 声明这些引用属性，V21 改为 `IEngineeringObject`（`GetExpressionResolver` 同理）；`TagMemberSetting` / `TagMember` / `AcquisitionMode` / `LayoutData` 仅 V21；`GenerationOptions` 是 `[Flags]`；PLC / HMI 设备列是以 PLC / HMI 运行系统名命名的动态属性（`GetAttribute` / `SetAttributes`），变量与文本列表规则不支持。SiVArc 的官方页面在 SiVArc 手册的地图（`TOFaq6RHmuKvo0~qDLnlOg`），不在 Openness 地图里。

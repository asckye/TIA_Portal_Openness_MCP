# v4.0.0-rc.8 — eighth 4.0 release candidate

## 中文

这是自动化工程工作台（适用于 TIA Portal）4.0 的第八个发布候选，发布日期 2026-11-26。它在 GitHub 上标为预发布，不是最新版。GitHub 的最新版仍是 3.3，3.3 的更新器不会提示这一版，请手动下载。rc.1 到 rc.7 安装中的更新器能识别本版。
[GitHub 发布页](https://github.com/asckye/automation-engineering-workbench/releases)

本版修复 rc.7 真机复验发现的问题：V18/V19 上连接工作区时覆盖内容不同的已有工作区文件（HIGH），V20/V21 上普通 FB/FC 的 SIMATIC SD 覆盖导入误报属性丢失（MEDIUM），以及复验中的 LOW 问题；另外修复审查积累的一批 LOW 问题，让更多拒绝和失败给出原因。**本版的代码改动尚未在任何真实 TIA Portal 上运行。** 除非写明版本，下列变化适用于全部八个支持的 TIA Portal 版本：V14 SP1、V15.1 和 V16–V21。

各版本的工具数与 rc.7 相同：V14 SP1 287、V15.1 328、V16 354、V17 377、V18 402、V19 478、V20 499、V21 518。工具名称、参数名和参数类型没有变化。改变的说明文字：全部八个版本上 `CloseProject`、`GenerateBlocksFromExternalSource`、`ImportPlcBlocksFromDirectory` 和 `PatchPlcBlockDocument` 的说明；V16–V21 上 `ConnectProjectToWorkspace` 的说明；V18–V21 上 `ManagePlcSimAdvancedInstance` 的 `cpuType` 参数说明；V19–V21 上 `EnsureUnifiedHmiButtonAction` 的 `targetTag` 参数说明。

### 必须了解的变化

- **连接工作区不再覆盖内容不同的已有文件（V16–V21）。** `ConnectProjectToWorkspace` 在写入前检查目标文件。已有文件只有与对象的官方导出一致时才复用；不一致时，该对象在任何原生写入之前被拒绝，错误写出文件名和处理办法。预览用 `willCompare` 单列这些文件，比较在执行时进行。V20/V21 遇到无法用 XML 核验的已有目标或配套文件时拒绝该对象。rc.7 在 V18/V19 上会直接覆盖这类文件，没有警告。
- **覆盖导入同名对象后，重新连接前要先移走旧文件。** 覆盖导入使原映射断开，旧 XML 属于这个断开的映射，内容与新对象不同，重新连接会被拒绝。请核对文件名，备份旧 XML，把它从工作区移走，再对同一对象连接。重新连接后旧映射仍留在工作区，连接结果和状态中的 `duplicate mapping` 行列出名称、文件和数量；没有删除它的工具。
- **几个错误码和结果改了。**
  - `MonitorPlcWatchTableS7` 连不上目标 PLC 时报 `PRECONDITION_FAILED`，条件为 `plc-online`，`details.target` 写出目标地址；rc.7 报 `NATIVE_OPERATION_FAILED`。连接成功后的读取失败仍报 `NATIVE_OPERATION_FAILED`。
  - `ManagePlcTestLibrary` 不带 `overwrite=true` 保存已存在的测试用例时报 `PRECONDITION_FAILED`，条件为 `case-exists`，参数为 `overwrite`。
  - 移动块失败、但留下了本次创建的目标组时，结果为未知（`unknown`）。
  - TIA 因文本列表不存在而拒绝导出报警文本列表、且没有写出文件时，执行记为已完成；目标可能已改变时，结果仍为未知。
  - `ImportPlcTagTablesFromDirectory` 没有匹配的文件时，预览报 `canApply=false`。
- **`SeedProjectFromReference` 拒绝更多路径。** 种子清单中的目录覆盖必须位于 `referenceDir` 内；`referenceDir` 或种子目录经过联接点或符号链接时被拒绝，并说明是哪一个；设备路径在解析之前被拒绝。
- **放弃更改的 `CloseProject` 可能释放绑定。** 原生关闭已返回、但 TIA 无法确认工程已关闭时，worker 释放本地绑定，关闭结果仍为未知。再次绑定前请检查已打开的工程。
- **预览会阻止更多注定失败的执行。** `SetDeviceItemAttribute` 的预览读到只读属性时给出警告并阻止执行（读取属性信息失败时预览照常）。`PatchPlcBlockDocument` 的预览在 `exportFile` 已存在时阻止执行。

### 自 rc.7 以来的变化

#### 版本控制工作区（V16–V21）

- 连接规则见上文。比较用的导出失败（例如块不一致）时，拒绝或未验证的结果带比较的原生原因，块不一致时提示先编译该块再重试，不只是“目标文件已存在”或 TIA 拒绝刷新 Equal 的原文。工作区路径被一个文件占用或工作区文件夹不存在时，错误消息直接说明。
- 工作台在最终内容比较中断时报告中断，同步无法确认的对象在失败汇总中只计一次。工作台的只读版本控制提示用中英文写明是 MCP 服务，未识别的版本键也能显示。
- 连接期间请确保只有 TIA 写入该工作区，原因见已知限制。

#### SIMATIC SD（V20/V21）

- 普通 FB/FC 的覆盖导入不再只因 `LibraryConformanceStatus` 改变而报 `BlockPropertiesNotPreserved`。这个值和 `IsConsistent` 一样是编译会重新计算的派生状态，列在 `notCompared` 中。其他属性的真实差异仍报失败。
- 覆盖库类型实例在写入前被拒绝，因为 SD 不能保留它的 `LibraryTypeVersion`。
- DB 的拒绝列出全部不能保留的属性，不只第一个。新建 OB 的拒绝直接说明 SD 总是创建程序循环 OB，不再写 `SecondaryType=<absent>`。

#### PLC 软件、验证导入和编译

- 验证导入还比较恢复的叶元素上的 XML 属性，并指出补充的 None 导出中不一致的块。
- 文档比较能区分继承成员和名为 `Base` 的声明成员，包括段顶层的继承。离线 DB 清单接受展开的 UDT 中带版本的系统类型（例如 `IEC_TIMER`）。
- 块编译报告其他块中的错误。编译诊断不完整、无法逐条计数时，保留 TIA 报告的 Error 状态。旧版安全程序编译遮蔽连接丢失的诊断。
- `GenerateBlocksFromExternalSource` 在 V14 SP1 上也在 `generatedObjects` 中列出生成的对象。
- `ImportPlcBlocksFromDirectory` 的预览返回 `data.importOrder`，执行时照抄；缺少顺序时的拒绝说明这一点。`PatchPlcBlockDocument` 接受编辑能力读出的段（V14 SP1 上展开的嵌套 UDT 成员是 `None`），示例按文档分开。
- `ExportPlcBlockDocuments` 的预览提示块不一致。
- `DeletePlcTagTable` 的预览和删除报告列出用户常量和系统常量。`ListTechnologyObjects` 说明不一致的对象为什么没有编译后的元数据。`DecodePlcSimaticMl` 的消息带去敏的解码器拒绝原因。LAD 生成器拒绝把 TCON、TDISCON、TSEND、TRCV、TUSEND、TURCV、RDREC 和 WRREC 当作用户 FC/FB 调用。
- `GetCallResult` 对重复的请求 ID 返回保留的最新普通结果。

#### 硬件、HMI、库和安全

- `CreateDevice` 的预览只在调用者传入 `family` 时列出它，HMI 面板不再显示 `S7-1500`。设备创建的兼容入口在结果中写明被调用的工具。
- 把设备项名称设为空或只有空白时（复验见于 V14 SP1），错误消息带西门子原因；TIA 没有给出原因时说明不允许空名称。
- CPU 设置报告每个被拒属性的原因。返回 `false` 的 CAx 导出（例如 `ExportDeviceAml`）写出 AML 文件、它是否存在和原生日志。
- Unified 变量导入失败时，除导出的变量文件外还核对组和表的路径，再报告没有变化。库版本导入失败时也比较依赖版本，包括其他库文件夹中的依赖。
- 一些写入（包括返回不支持操作的回复）在缺少或无法读取变更证据时报结果未知。Unified 事件和动态化的读取与预览在 `token` 之外返回执行用的 `previewToken`。
- 多用户锁状态和安全属性的错误指出调用者的输入。库发布指出无效的 `newVersion`，库比较路径使用对象所在一侧的名称。
- SiVArc 定义操作需要 V21。缺少或无法加载的工程选件指出要检查的安装。
- 报警文本列表母版的拒绝指出需要的全局库。`EnsureUnifiedHmiButtonAction` 说明只在执行时检查目标变量。PLCSIM Advanced 注册的 `cpuType` 说明使用仿真器的枚举名，不是 `SearchHardwareCatalog` 的类型标识。

#### 会话、恢复和参数

- 会话恢复能结算 worker 得知 TIA 进程启动时间之前记录的调用。嵌套的工程搭建调用保留写入被中断的证据，worker 失败保留原来的请求已发送标记。
- 恢复时附加到 TIA 后绑定工程失败，下一次需要绑定的调用会在已附加的 worker 上重试绑定。
- 同时含有无效参数和未知参数时，错误列出声明的参数名。
- 安装就绪检查明确列出依赖 worker 的测试和报告工具。`ManagePlcTestLibrary` 的全部操作都只处理本机文件。在线目标设置可以在另一读者读完旧列表时被替换。
- 环境检查中没有可用操作的行不再带操作按钮文字。工作台标题栏和“关于”页的图标对辅助功能是装饰性的，高对比度轮廓与图块圆角一致。

#### 文档

- [Openness 覆盖](../reference/openness-coverage.md)的八行数字都在各版本的 PLC worker 上重新测得，V21 直接引用 1768、待复核 2555，复现命令改为 `prepare -BuildOnly` 后运行 `audit-version-tools`。

完整变化见[更新日志](../../CHANGELOG.md)。

- **V16/V17 连接时的已有文件：检查通过。** 内容不同的文件被拒绝并点名、没有被覆盖，内容一致的文件被复用。
- **GlobalDB 文档导入拒绝覆盖并说明原因、新建 OB 在写入前被拒：V20、V21 确认修复。**
- **只读属性的原因和源文件生成失败的编译器文字：已确认修复。** V19 的汇总没有单独记录这两项。
- TP700 在 V15.1 和 V16 的目录中存在，可以直接创建。

复验发现、本版已修复、尚未复验的问题：

- **连接工作区覆盖内容不同的已有文件（HIGH，V18、V19）。** 连接前目标位置已有内容不同的文件，`ConnectProjectToWorkspace` 直接覆盖，预览只写将要映射，没有警告。工作区文件属于工程外的数据，被静默丢失。V16/V17 已按规则拒绝。
- **普通 FB/FC 的 SD 覆盖导入误报属性丢失（MEDIUM，V20、V21）。** 导入实际成功、编号不变，却报 `BlockPropertiesNotPreserved`；唯一差异是 `LibraryConformanceStatus`，编译后恢复。
- **LOW：** DB 拒绝只列第一个属性（V20、V21）；新建 OB 的拒绝写成 `SecondaryType=<absent>`（V20、V21）；V20 启动 OB 的 SD 导出只有通用文字；生成失败后 `objectsAfter` 为空（多个版本）；V14 SP1 的 `generatedObjects` 为空、空名称没有西门子原因、嵌套 UDT 成员的补丁段与示例不符；只读属性的预览没有警告（多个版本）；`PatchPlcBlockDocument` 预览不检查 `exportFile`（V18、V19）；连接预览的 `wouldRefuse=0` 而执行拒绝（V16、V17）；断开的旧映射残留（V17、V19）；工作区文件夹不存在时消息不说原因（V16）；`ImportPlcBlocksFromDirectory` 示例的 `importOrder` 为空（V17）；HMI AML 导出失败的顶层消息没有说明（V19；现在写出是否留下 AML 文件和原生日志的位置）；不一致块的内容核对没有说要编译（V18）；HMI 面板的预览写 `S7-1500`（V15.1、V16）。

没有测到的情况：

- V18、V19 的全新附加、在 TIA 之外修改或删除工作区文件、从未存在过文件的映射。
- V20 启动 OB 的 SD 导入。
- 工作台的 SD 还原。
- 在线、下载、强制和仿真执行。

### 已知限制

- **本版的改动尚未在真机上运行。** V16–V21 的连接已有文件规则、V20/V21 的 SD 覆盖导入核对，以及本版的其他修复，在真机上的行为都没有验证，发布后在虚拟机上复验。
- **连接期间另一进程创建的文件仍可能被覆盖。** 连接在原生写入前检查目标文件；如果另一进程在 TIA 写入期间创建同名文件，TIA 仍可能覆盖它。连接完成之前，只让 TIA 写入该工作区。
- **断开的旧映射不会被删除。** 覆盖导入后重新连接，旧映射仍留在工作区，状态中以 `duplicate mapping` 列出；没有删除它的工具。
- **V16–V19 编辑后的状态只验证过部分情况。** 原地添加变量后状态及时变为 Unequal；在 TIA 之外改动或删除工作区文件、全新附加的情况尚未在真机上验证。
- **SIMATIC SD 不是无损格式。** 即使通过核对，报警、监控、SiVArc 和成员属性仍可能丢失。`verifyDocumentReadback` 只比较 `.s7dcl` 和 `.s7res` 文本（`sdDocumentsMatch`）。V21 的 SD 导出不带块编号，作为新块导入时由 TIA 分配编号（复验中得到 FB1），只有通用警告。
- **结果判定尚未统一。** 各工具共用的宿主默认判定规则没有改，移到 4.1。普通情况仍可能报结果未知，也可能在没有证据时报确定失败。
- **`ConnectOnlinePlc` 和 `DisconnectOnlinePlc` 的结果判定与 rc.6 相同。**
- **没有连接过真实 PLC。** 在线、下载、强制和仿真执行都未经真机验证。
- **一些失败的写入仍报结果未知。** 包括删除块、类型和变量表，从源生成块（TIA 明确说明的生成失败除外），以及 `ManagePlcGitRepository` 的暂存和提交。名称或版本没有变化，不足以证明没有副作用。
- **导入遇到未能识别的异常时报结果未知。** 例如报警类、报警文本列表和 OPC UA 接口的文件格式错误。
- **嵌套 UDT 旧值的核对有条件。** 只有标准导出可用时才能判为一致。真机上 TIA 导入时重置了嵌套值，保留旧值的情况尚未出现过。
- **被拒导入的证据有边界。** 证据只覆盖目标块和目标组的块名，不包括其他对象、UDT 和库。
- **带级别标签的诊断可能被整体遮蔽。** `[Error]` 等标签后的文字若含有像凭据的内容或 JSON 片段，整段显示为圆点，即使没有秘密。
- **验证导入有未覆盖的情况。** UDT 展开内部的成员属性和注释不参与比较，新文档省略的块属性和成员设置从原块恢复。UDT 数组的展开不做归一化，未展开 UDT 实例的标志没有恢复。
- **工作区导出的判定有限制。** 快照遇到重解析点、超过 10,000 项或无法读取时报结果未知，快照之后的延迟写入和时间戳精度内的等长改写可能看不到。旧的 XML 导出路径同样适用这些规则。没有对象导出成功、但已保留映射或写入了文件时报 `PARTIAL_FAILURE`，`error.details` 中的三项计数都是 0，实际失败数见 `data.evidence.failed`。
- **`CreateDevice` 仍拒绝创建 TP700 面板（V18–V20）。** 拒绝给出原因。在 V18 和 V19 上，`CreateHardwareCatalogDevice` 的关键字方式可用。
- **`ExportDeviceAml` 不能导出部分 HMI 设备。** 这是 TIA 的限制：V19–V21 上 TIA 报 TypeIdentifier 错误并留下部分文件，V15.1–V18 上 TIA 的导出返回失败。V17 导入 HMI AML 报“wrong type”，原因尚未查明。
- **V17–V20 上固件 V2.9 的 CPU 证书模板不可用。** 这是 TIA 的已知限制，rc.7 复验在 V17–V20 上再次记录。
- **OPC UA 的 ReferenceNamespace 不能新建。** `ImportOpcUaInterface` 选择 `ReferenceNamespace` 新建时总是被拒绝，因为 SDK 的创建方法与本工具的调用方式不同。
- **多数示例没有在真机上运行过。** rc.4 复验的 104 处真机标记只涉及 V18–V21，rc.5 到 rc.7 复验的记录没有补入示例标记。
- **按最终设计改版的工作台尚未在真机上逐页手动检查。** 它只经过自动化界面测试和离线截图检查。
- **“关于”页的图标在高对比度下仍是彩色的。** 标题栏图标已随主题变化。
- **窄窗口中的调用详情仍是抽屉。** 窗口较窄时，调用详情以 520 像素宽的模态抽屉打开；设计稿中是页面内的面板。

### Changes you must know

- **Connecting a workspace no longer overwrites an existing file with different content (V16–V21).** `ConnectProjectToWorkspace`
  checks the target file before it writes. An existing file is reused only when it matches the object's official export. Otherwise
  the object is refused before any native write, and the error names the file and the remedy. The preview lists these files in
  `willCompare`; the comparison runs on apply. On V20/V21, an object is refused when an existing target or companion file can't be
  verified as XML. In rc.7, V18/V19 overwrote such a file without a warning.
- **After an override import of an object with the same name, move the old file before you reconnect.** The override import
  disconnects the old mapping. The old XML belongs to that disconnected mapping, its content differs from the new object, and a new
  connect is refused. Check the file name, back up the old XML, remove it from the workspace, then connect the same object again.
  After a reconnect, the old mapping stays in the workspace. The connect result and the status list it in a `duplicate mapping` row
  with the name, file and count. No tool deletes it.
- **Some error codes and outcomes changed.**
  - `MonitorPlcWatchTableS7` reports `PRECONDITION_FAILED` with condition `plc-online` when it can't reach the target PLC, and
    `details.target` names the address. rc.7 reported `NATIVE_OPERATION_FAILED`. A read failure after a successful connection still
    reports `NATIVE_OPERATION_FAILED`.
  - `ManagePlcTestLibrary` reports `PRECONDITION_FAILED` with condition `case-exists` and parameter `overwrite` when it saves an
    existing test case without `overwrite=true`.
  - A failed block move that leaves behind target groups it created reports an `unknown` outcome.
  - When TIA refuses an alarm text-list export because the list is missing and no file was written, execution is reported as
    completed. If the target may have changed, the outcome stays unknown.
  - `ImportPlcTagTablesFromDirectory` previews report `canApply=false` when no files match.
- **`SeedProjectFromReference` refuses more paths.** Directory overrides in a seed manifest must stay inside `referenceDir`. A
  junction or symbolic link in `referenceDir` or a seed directory is refused, and the refusal names where it is. Device paths are
  refused before they are resolved.
- **`CloseProject` with discarded changes can release the binding.** When the native close returned but TIA can't confirm that the
  project is closed, the worker releases its local binding, and the close outcome stays unknown. Check the open projects before you
  bind again.
- **Previews block more applies that would fail.** The `SetDeviceItemAttribute` preview warns about a read-only attribute and blocks
  apply; when the attribute information can't be read, the preview stays as before. The `PatchPlcBlockDocument` preview blocks apply
  when `exportFile` already exists.

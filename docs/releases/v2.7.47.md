## 宽松绑定：AI 调用时的"格式错误"

2.7.46 的全量真机重测里，引擎自己的调用方也犯了同样的错：`*Json` 参数直接给了数组、`action` 大小写不对、数字写成字符串、`argumentsJson` 直接给对象。这些在 2.7.47 起由 `CallTool` 桥接自动纠正：

| 调用方写法 | 2.7.46 | 2.7.47 |
|---|---|---|
| `argumentsJson` 直接是对象 `{"softwarePath":"PLC_1"}` | SDK 绑定失败 | 接受（也接受字符串） |
| `devicePathJson: ["MCP_PLC"]`（数组而不是字符串） | "could not be read as string" | 自动转成 `"[\"MCP_PLC\"]"` |
| `positionNumber: "2"`、`dryRun: "false"`、`dryRun: 0` | 绑定失败 | 解析为数字 / 布尔 |
| `version: 4.6`（数字） | 绑定失败 | 取文本 `"4.6"` |
| `action: "Export"`（合法值是 `export`） | "action must be one of: export/import (case-sensitive)" | 按拒绝信息改成 `export` 重试一次 |

每次规范化都写进 `Meta.bridgeNormalizedArguments`，调用方能看到自己哪里写错了。直接调用（lite 名单的 56 个）走 MCP SDK 的 JSON Schema 绑定，客户端按 schema 生成参数，格式错误本来就少。

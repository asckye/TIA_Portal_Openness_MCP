# v2.7.36

引擎 **2.7.36.0**（V20/V21 均重建）。工具 408 → **409**，默认 lite 清单 56 项不变。本版做两件事：修 2.7.35 真机暴露的监控表注释行计数缺陷，以及"官方 Openness API 全量对齐"计划 [路线图 §2.0](../development/roadmap.md) 阶段 4 子批次 ④-③：工艺对象映射——**`Siemens.Engineering.Step7.dll` 的功能类型缺口归零，阶段 4 收口**。

| `ManagePlcTableEntries createComment`：`PlcTableCommentEntryComposition.Create()` 原生成功，但同一组合代理的 `Count` 仍是旧值，工具报"条目数没有加一" | 计数改为从监控表重新导航（和单元关系、硬件组合一样的陈旧代理规律） |

## 新增工具（域 PLC-TechnologyObjects）

| 工具 | 动作 | 官方入口 |
|---|---|---|
| `ReadTechnologyObjectTree` | `PlcSoftware.TechnologicalObjectGroup`（或 `groupPath` 下的用户组）的类型化树：`TechnologicalInstanceDBGroup` Name / `TechnologicalObjects`（`TechnologicalInstanceDB` Name / Number / OfSystemLibElement / OfSystemLibVersion / IsConsistent / 参数数）/ `Groups` 递归；`includeParameters` 加 `TechnologicalParameter` Name / Value 行；`includeMotionView` 加根组对象的类型化 Motion / Ident 视图（执行器 / 传感器 / 扭矩 / 编码器接口的模块、地址、DB 成员路径、变量、通道；测量输入与输出凸轮连接；主值耦合；V21 的解释器 TO / DB 成员映射、叠加轴、Ident 设备） | `Siemens.Engineering.Step7.xml` 的 `SW.TechnologicalObjects(.Motion / .Ident)` 摘要（官方 Openness 地图的 Motion Control 章节不在文档站搜索索引里） |

类型化改造（不改工具签名）：`ReadMotionAxisConfiguration` 的 `object` 改为 `TechnologicalInstanceDB` 行、新增 `typed` 视图、参数为 `TechnologicalParameter` 行；`ManageMotionAxis` 的主值耦合走 `TechnologicalInstanceDBAssociation.Add / Remove / Contains`，映射走 `TOMappingComposition` / `DBMemberMappingComposition` 的 `Find` / `Create` 与 `TOMapping.Alias / TechnologicalObject / Delete`、`DBMemberMapping` 类型化行（V21），`connectIdent` 走 `IdentTechnologicalObjectProvider.Connect`，硬件连接走 `AxisHardwareConnectionProvider.ActorInterface / SensorInterface[i] / TorqueInterface` 与 `EncoderHardwareConnectionProvider.SensorInterface`，`Connect` / `Disconnect` 对 `AxisEncoderHardwareConnectionInterface`（7 个重载）/ `TorqueHardwareConnectionInterface`（5 个）/ `MeasuringInputHardwareConnectionProvider`（3 个）/ `OutputCamHardwareConnectionProvider`（3 个）类型化调用、读回为类型化行；`targetJson` 新增 `channelType` + `channelIoType` + `channelNumber`（`Connect(Channel)`，`ChannelComposition.Find(type, ioType, number)`），扭矩接口没有该重载；`ManageTechnologyObject` 的 `create` 走 `TechnologicalInstanceDBComposition.Create(name, typeIdentifier, version)` + `Find` 回读，参数走 `TechnologicalParameterComposition.Find`；`ConfigureMotionHardwareConnection` 走类型化提供者与位地址 `Connect(int, int, ConnectOption)`。V20 的 `Connect(Telegram[, ConnectOption])` 重载保留反射回退（V21 没有 `Telegram`）。

只在 PublicAPI 上核实的事实：`PlcSoftware.TechnologicalObjectGroup` 声明类型是 `TechnologicalInstanceDBGroup`（不是 `…SystemGroup`）；`TechnologicalParameter.Value` 是可写 `Object`；`TOMapping` / `DBMemberMapping` / `InterpreterMappings` / `SuperimposingAxes` / `IdentTechnologicalObjectProvider` 仅 V21；`TorqueHardwareConnectionInterface` 没有 `Connect(Channel)` / `Connect(PlcTag)`。

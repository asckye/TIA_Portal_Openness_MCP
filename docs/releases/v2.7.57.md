# v2.7.57

引擎 **2.7.57.0**（V20/V21 均重建）。工具 **452**（+`PreflightToolCall`、`CheckForUpdate`），默认 lite **58**。维护者 2026-09-21 定下的顺序里的第二件事：更新器 + 规范 AI 调用。

## 更新器（不做热更新：引擎在运行就要求先关）

`scripts/operations/Update-Engine.ps1` 随交付包分发，在解压好的交付目录里运行：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File scripts\operations\Update-Engine.ps1 -Check      # 只比版本
powershell -NoProfile -ExecutionPolicy Bypass -File scripts\operations\Update-Engine.ps1             # 在线更新到最新 Release
powershell -NoProfile -ExecutionPolicy Bypass -File scripts\operations\Update-Engine.ps1 -ZipPath D:\Downloads\TIA_MCP_Delivery_v2.7.57_20260921.zip   # 离线（.sha256 放在旁边）
powershell -NoProfile -ExecutionPolicy Bypass -File scripts\operations\Update-Engine.ps1 -Rollback   # 换回上一版
```

- 读 `manifest\delivery.json` 得到当前版本；`TiaMcpServer.exe` / `TiaMcpConfigurator.exe` 在运行就**拒绝并列出 pid**（提示是哪个 MCP 客户端启动的），从不杀进程。
- 最新版来自 GitHub API `releases/latest`（`-Version vX.Y.Z` 指定）；API 被限流（未登录 60 次 / 小时）时改读 `releases/latest` 的重定向拿 tag、`releases/expanded_assets/<tag>` 拿下载链接。
- 下载 ZIP + `.sha256`（SHA-256 不符即停，什么都不改；没有 sidecar 需显式 `-SkipHashCheck`）→ 解压并检查包结构（两版 exe、配置器、清单）→ 备份当前安装到 `.previous\<包名>\`（只留两份）→ 整体替换 `runtime\` 与 `manifest\`、覆盖其余文件 → 打印新版本。之后重启引擎，`Bootstrap` 的 `serverVersion` 应为新版。
- 不碰 TIA、工程与客户端配置；`.previous` / `.update` / `TiaMcp_Output` / `*.log` 不进备份。
- 本机验证（2.7.55 解压包）：离线更新到 2.7.56（SHA 校验、备份、`runtime\v21\TiaMcpServer.exe` 2.7.56.0）→ `-Rollback` 回 2.7.55 → `-Check` 在 API 403 时走发布页回退拿到 v2.7.56 → 伪 `TiaMcpServer.exe` 在跑时拒绝（exit 1，文件未动）。

## `CheckForUpdate`（引擎侧，只读）

`[L0][Diagnostics][SESSION]`。比较引擎版本（程序集版本前三段）与最新 Release：`Meta.currentVersion` / `latestVersion` / `latestTag` / `updateAvailable` / `zip {name,url,size,digest}` / `sha256 {name,url}` / `installRoot`（向上找 `manifest/delivery.json`）/ `updaterScript` / `howToUpdate`（四步）。API 限流或解析失败时自动改读发布页（`Meta.source = releasePage`，`apiProblem` 保留原因）；机器没有外网时 `success=false` 并给出离线步骤。参数 `repository`（只接受 `owner/name`）、`timeoutSeconds`。

## `PreflightToolCall(name, argumentsJson)`：先预检、再调用

`[L0][Meta][SESSION]`，**不执行任何东西**：

| 报告项 | 内容 |
|---|---|
| 工具名 | 不分大小写解析；不存在时给候选（包含 / 前缀）并要求换名重跑 |
| 参数 | `MISSING`（必填缺失，含给了 `null` 的）、`UNKNOWN`（并给最接近的参数名）、`TYPE`（布尔 / 整数 / 数值不对）、`Case`（`SoftwarePath -> softwarePath`）、`Coercion`（`CallTool` 会做的转换：字符串数字 / 布尔、`*Json` 参数给了对象、`""` 表示默认值、备选值只差大小写）、`Warning`（值不在文档备选值里；`dryRun=false` 却没设 `confirm*`） |
| 类别 | `[L?][域][操作]`（未标注时按名推断并注明）与每类操作的注意事项（WRITE 不自动保存 / 编译 / 下载；ONLINE-WRITE 只对 PLCSIM Advanced…） |
| dryRun | 是否支持、给了什么、**实际是预览还是执行**、有哪些 `confirm*` 标志、设了哪些 |
| 前提 | 该操作是否需要已绑工程；当前是否已连接、绑的是哪个工程（离线套件里为未知） |
| 示例 | 该工具的 `Example`（如有）与完整描述 |

`Meta.ok` = 参数能绑定；`Meta.success` = 还满足会话前提；`Message` 给结论（`NOT READY: fix N problem(s)` / `Arguments fit; the session prerequisite is not met` / `READY … it EXECUTES` 或 `it is a preview`）。备选值解析（`PreflightLogic.Alternatives`）识别 `a | b | c`（任意位置）、冒号后的 `a/b/c`、括号里的 `(a, b, c)`，排除 `e.g.` 列表、引号例子、带连字符的散文（真机描述 "(substring, case-insensitive)" 曾误判）。

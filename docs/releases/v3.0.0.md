# v3.0.0 — Official Openness workflow fixes and ecosystem tools

Released: 2026-09-29. Complete V20/V21 delivery: `TIA_MCP_Delivery_v3.0.0_20260929.zip` plus its SHA-256 sidecar.

This release adds 11 tools (464 total; lite remains 59), incorporates the pinned Siemens `tia-portal-ai-extensions` guidance, and fixes connection selection, ownership, late attachment cleanup, DLL identity checks, transaction outcomes and nested exclusive access.

## Upgrade changes

- `RunToolsInTransaction` now accepts only eight reviewed synchronous editing tools: `CreatePlcTypeGroup`, `DeleteEmptyPlcBlockGroup`, `ManagePlcUserGroup`, `ManageDeviceUserGroup`, `ManageUnifiedHmiGroup`, `DeleteEmptyUnifiedHmiScreenGroup`, `UpdateUnifiedObjectProperties`, and `UpdateUnifiedMultilingualProperty`. Unsupported calls fail preflight before starting a transaction; use their standalone tools where appropriate. Existing broader transaction clients need updating. This contract restriction is why the version advances to 3.0.0.
- Native PLC `GetCrossReferences` and deletion cross-reference queries are disabled by default following reported TIA crashes. `TIA_MCP_ENABLE_NATIVE_PLC_CROSS_REFERENCES=1` is an explicit diagnostic opt-in and still requires readable, consistent compilation state. Compilation success does not establish that the native query is safe.
- All MCP transports share a process-local execution gate. Diagnostics record BEFORE/RETURNED/THREW without argument contents. Separate engine processes still have separate session state.

## Added capabilities

`ReadOpennessGuidance`, `RenderPlcVisualDiff`, `RunPlcCompanionTool`, `ReadToolBatch`, `PreviewToolBatch`, `ApplyToolBatch`, `ManagePlcGitRepository`, `GenerateOpcUaModelledInterface`, `AuditEngineeringExports`, `InstantiatePlcXmlTemplates`, and `ComposePlcAliasAlarmLad`.

The [usage guide](../reference/ecosystem-tools.md) documents previews, bounded inputs, installation and output formats. Batch apply is not an atomic transaction. OPC UA output generation does not import or compile a PLC. PLC Tools runs in a separate Python environment; install it with `scripts/ecosystem/Install-PlcTools.ps1`. The Python environment, Siemens PublicAPI assemblies and user projects are excluded from the distribution.

The 32 official Siemens guidance topics and nine fixes are documented in the [official workflow audit](../development/official-openness-audit-20260929.md). `GetAuthoringGuide("openness-workflow")` links the workflow in the engine. Symbol quoting and array readback corrections from upstream preserve this project's existing LAD render features. Vendored MIT sources retain attribution in [third-party notices](../licenses/THIRD-PARTY-NOTICES.md); GPL implementations were not copied.

## Validation and limits

V20 and V21 builds, 2,551 offline assertions, API shape checks (V20: 2,805; V21: 3,097), 31 ecosystem checks per runtime and transport tests run locally. The pinned Python offline suite previously passed 2,091 tests with eight documented skips. The complete release build also runs resource discovery, remoting and configurator regression checks; exact results and input hashes are recorded in `manifest/release-build.json` and `manifest/configurator-build.json`.

No VM deployment or live TIA writes were performed for these new features. Native transaction/close behavior still needs acceptance testing. Pure Openness creation of a Unified faceplate type from scratch, editing its internal controls and type-local scripts remains unverified; library and instance operations do not establish those capabilities. See the audit for the remaining coverage gaps.

Upstream version-branch integration is intentionally deferred until after this release is published.

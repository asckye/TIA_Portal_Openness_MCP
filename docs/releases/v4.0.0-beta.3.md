# v4.0.0-beta.3: third 4.0 pre-release

This is the third 4.0 pre-release of Automation Engineering Workbench (formerly TIA Portal Openness MCP). It is published on
GitHub as a **pre-release**: it is never marked as the latest release, and the 3.3 updater and the Workbench update check of a
3.3 installation do not offer it. Download it by hand from the [releases page](https://github.com/asckye/TIA_Portal_Openness_MCP/releases) to test it.

The last real-TIA test round used V21 on a virtual machine. This release fixes some of its findings; other findings remain
open as listed under Known limitations. These fixes and the new features have not been retested on a real TIA Portal yet.

## Behavior changes you must know

- **File-write restrictions (SEC-1).** Tools cannot write the approval settings or `.git` metadata. WritePlcSclSourceFile
  writes `.scl` files only; directory and extensionless inputs resolve to an `.scl` filename. It rejects alternate data streams
  and trailing dots or spaces. Git calls ignore repository hooks, fsmonitor and signing, so commits made through
  ManagePlcGitRepository do not run repository hooks.
- **Device whitelist removed.** CreateHardwareDevice, CreateDevice and CreateHardwareCatalogDevice create any exact row of the same
  catalog read instead of only two example CPUs of the S7-1200/S7-1500 families, and the exact OrderNumber, version, duplicate-name
  check, preview hash, confirmation, project file identity and read-back after creation still apply.
- **`expectedProject` is the project name.** It is `Project.Name`, not a file path: a value that looks like a path is refused with
  INVALID_ARGUMENT before any TIA call, and tools that check the project file keep `expectedProjectFile` (an absolute path).
- **ListPlcBlocks pages by default.** It returns 4 items per page (`limit` 1 to 100); pass the returned `meta.paging.nextCursor` as
  `cursor` until `complete` is true, and start again with an empty cursor when a changed block inventory refuses the old one.
- **FindTools matches more strictly.** A query of several words returns only tools that match every capability word with a minimum
  relevance, ranked by relevance with exact tool names first, while a one-word query still matches descriptions, so a broad
  query can return fewer tools than in beta.2.
- **Software-unit parameters only where the API has them.** `unitName` and `includeUnits` appear only in the tool definitions of
  V16 to V21, `swImportOptions` from V15.1 on block and type imports (never on tag-table imports), and the culture
  `importOptions` only on V19 to V21.
- **New Workbench palette.** The Workbench has new colors, system fonts, high-contrast outlines and a keyboard focus ring, while its
  layout, navigation and approval drawer are unchanged in beta.3.
- **Host stop and restart ask first.** The Workbench asks for confirmation before it stops or restarts an MCP host, first asks the
  host to exit on its own (up to 20 seconds), and ends it by force only after a second confirmation that warns TIA Portal may
  need a restart.
- **Old HMI write tools preview by default.** The `EnsureUnifiedHmi*`, `ApplyUnifiedHmi*` and `BindUnifiedHmi*` tools default to
  `dryRun=true` and return a plan; pass `dryRun=false` to write, with approval as before.

## What is new compared with beta.2

### What testers will notice

- **New public name.** The product is now called Automation Engineering Workbench (自动化工程工作台). Executables, the plugin ID,
  the MCP server name `tia-portal`, the delivery package name and the repository address are unchanged. The Siemens trademark
  notice and the project origin are stated in the README and NOTICE files.
- **For testers.** A 3.3 to 4.0 [migration guide](../guides/migrate-3.3-to-4.0.md), a per-release
  [real-machine checklist](../guides/beta-tester-checklist.md) and new issue forms for bugs, real-machine results and feature
  requests.
- **MCP hosts are visible.** The MCP page of the Workbench lists every host of its data folder: PID, version, start time,
  transport and HTTP endpoint. Hosts from an older or unknown version are flagged. After a human confirms, the Workbench can stop a
  host or restart the HTTP host with the saved settings. A stdio host is restarted by its MCP client. AI tools cannot stop or
  restart hosts.
- **DecodePlcSimaticMl works on a clean installation.** The package includes an isolated CPython 3.12.10 standard-library runtime,
  pinned by hash, with its original licence. No user Python, pip download or ecosystem environment is needed. A missing runtime
  prerequisite is reported without installation paths.

### Fixes for the beta.2 VM findings

- **Worker timeouts.** A read that times out now reports `requiresSessionReset=true` with the recovery steps, instead of "no reset
  needed". The time budgets are unchanged. A worker that still responds detaches from TIA on its own thread; a busy or lost worker
  is still ended, and TIA Portal may still need a restart.
- **Failed reads.** Failed reads (DCC/Startdrive, library and project compare, SiVArc, Safety and others) report the same reset
  requirement as the session state. The next call no longer gets an unexpected SESSION_RESET_REQUIRED.
- **Old L2 PLC tools.** CreatePlcBlockGroup, MovePlcBlockToGroup, RepairAndReimportPlcBlock, ImportPlcTagTablesFromDirectory and
  related tools no longer fail on a valid reply or a dry-run argument. CreateDevice and CreateHardwareCatalogDevice use the same
  exact hardware creation path as CreateHardwareDevice, including devices that TIA files in the ungrouped system group.
- **Native messages.** A native failure keeps the redacted exception type and message in the result, not only in the server log.
- **One session state.** Host tools, generation planning and the Workbench read one session state. PlanProjectGeneration no longer
  says "No TIA Portal is connected" for an attached project. `GetWorkbenchState.data.session` describes the calling MCP session;
  `selectedSession` is the Workbench's current selection.
- **EnsureUnifiedHmiTag.** An unsupported binding is refused before the tag is created. If the tag was created and the binding then
  fails, the result reports a partial write and the reset requirement, not an unknown outcome.
- **Library type instances.** Overwriting a library type instance by XML import can break its type link. The preview and the
  execution now warn about it. The preview reports `recoveryStatus=not-attempted-preview`; the execution reports the real backup
  result.
- **V20/V21 examples.** V20 and V21 serve the maintained call examples instead of frozen engine values. Unified paths start at
  `ScreenGroups`/`Screens`, screen and tag-table paths are absolute, and the `softwarePath`/`blockPath` hints show grouped stations
  and group-qualified block paths.
- **Large results.** A large direct or `CallTool` result includes a ready-to-run GetExportContent call to read the rest. Completed
  export content survives cache eviction, block pages keep their cursor through `CallTool`, and malformed worker pages are refused.
- **Extension-family replies (VMFIX-2).** Alarm, OPC UA, SiVArc, Startdrive/DCC and Safety tools validate each worker reply against its
  own contract. A normal refusal or failure is a typed tool error with the native cause and no longer locks the session.
- **Unified reads and HMI probes (VMFIX-2).** Paged Unified reads no longer fail with "Structured input was not decoded by the host".
  GetUnifiedObjectEvents returns the script code. The HMI connection probes find devices inside device groups by name or
  project-tree path and name the target when nothing is found. SetUnifiedHmiRuntimeState reports the native failure cause.

### New tools and parameters

- Registered tools per release: see the [tool matrix](../reference/tool-matrix.md); runtime `tools/list` is authoritative.
- **AnalyzePlcCrossReferences** (new READ tool, all eight releases) exports the relevant PLC blocks once and analyses callers,
  callees and reference sites offline, without the native cross-reference service. "Not queried" is never reported as zero
  references.
- **Native cross references.** GetPlcCrossReferences, GetUnifiedCrossReferences and the delete-time reference checks run by
  default on V14 SP1 to V20. V21 stays opt-in: a human-only Workbench switch for the current session (the environment variable
  still works) enables it with a risk notice. GetSessionState reports where the setting comes from and the read-only approval
  state.
- **HMI.** Faceplate interface items can be addressed by `PropertyName`; their values are converted to the current value's type and
  read back. Faceplate instance tracing no longer asks the caller to guess the type path and version.
- **Software units (V16 to V21).** PLC XML import, export and directory import take an exact `unitName`; without it the PLC root is
  used as before. New explicit `swImportOptions` (V15.1 to V21) and culture `importOptions` (V19 to V21) are off by default and
  shown in the preview. The software tree shows units, tag and constant reads take `unitName` or `includeUnits`, and
  AnalyzePlcCrossReferences can select a unit. Unit objects are published with the existing SetPlcUnitObjectAccess tool (preview,
  approval, read-back).
- **ListPlcBlocks** takes `limit` and `cursor`, pages in a stable group-qualified path order and reads full attributes only for the
  current page. Every item has the exact path that GetPlcBlockInfo and ExportPlcBlock accept.

### Safety and approval

- The old HMI write tools refuse renames and same-name items of another type, and keep per-item write results and read-back. HMI
  arguments and paths are validated before any TIA call; group and plant paths are absolute `/Group/Sub/Name`.
- Device creation keeps every real guard after the whitelist removal; a Unified panel version must match the Portal major version.
- Only a human in the Workbench can stop or restart a host, and a forced end needs a second confirmation after the graceful stop
  times out.

### Workbench look

The Workbench theme follows the shared EplanMcp design system (ADR 0028). The layout redesign and the Approvals page follow in a
later pre-release.

- Accent color #0071E3, the system fonts Segoe UI Variable, Segoe UI and Microsoft YaHei UI, new type sizes, control sizes and
  corner radii. High contrast draws an outline on every control, the keyboard focus ring is 2 px, and every text and background
  pair in use has a contrast of at least 4.5:1. The bundled Maple Mono CN font is removed.

### Removed code and package contents

The retired engine code, its host cross-check clients and its dedicated fixtures have been removed. The unshipped SafeV4
candidates were archived and removed too. These removals do not change the tools available to testers or their MCP contracts;
all eight releases continue to use PLC workers.

The package is smaller after removing development files. It omits five files: `.editorconfig`, `Directory.Build.props`, and
`src/Shared/CodeAnalysis.props`, `src/Shared/DependencyVersions.props`, `src/Shared/ReproducibleBuild.props`. Siemens DLLs are
not included. Third-party shipped sources, licences and provenance records remain; unused upstream tests and reference archives
have been removed from the repository.

After an update from an earlier beta, the old `schemas/` folder can be deleted. The beta.1/beta.2 inventories can leave it and
`runtime/README.md` behind harmlessly. Updates remove the five development files when the installed inventory owns them and
restore them on rollback; beta.1/beta.2 runtime-only inventories can leave them behind. The root `hooks/` folder remains in use.

### Documentation

Development documentation is now grouped into standards, the plan and progress pages, manuals and archives. The release and
validation manuals describe the replacement release tooling; the project plan records the remaining beta.4 work.

### Build and release (internal)

Build and release tooling has been replaced: `merge-check` checks affected work, `prepare` builds and packages the release,
runs the full checks and uploads a private draft, and `publish-prepared` verifies and publishes that prepared draft within
300 seconds. The old scheduler, cache, evidence chain and nightly dependency are removed. Tool-definition contract checks and
functional coverage remain; approved duplicate tests and all eight releases' per-tool response captures were removed.

## Known limitations

- **Real-TIA coverage is limited.** Only V21 was tested on a real TIA Portal in the last round, without a PLC or PLCSIM.
  Online, download and monitor tools have not run against a real target. V14 SP1 through V20 were not tested in that round.
  Compilation was exercised only on a small PLC program; this does not establish behavior on large projects.
- **The eight releases are not yet fully unified.** V20 and V21 default to the short tool list (lite); V14 SP1 through V19 list
  every tool, producing a long `tools/list` response. Unifying this is planned for the next beta.
- **Some VM findings remain open.** VMFIX-3 covers incorrect outcome reporting on some writes, including a known result being
  reported as unknown. VMFIX-4 covers session rebinding, recovery and read-timeout handling. VMFIX-5 covers remaining result
  mapping, redaction and diagnostics defects, plus V21 PLC services, technology objects and Unified HMI behavior. Whole-program
  reads can still time out on large projects. There are also 31 open lower-severity defects from the VM findings.
- **File writes are not yet confined to an output folder.** SaveExportContent can still write any file type outside an output
  folder, subject to the protected-target restrictions above. Wider approval for file writes is planned for the next beta.
- **Trust and transport.** The executable is not signed. The updater checks a hash but no signature, and HTTP transport is plain
  text. Use it on a trusted network only.
- A read that hangs in TIA can still end its worker. TIA Portal may need a restart before you connect again.
- Overwriting a library type instance by XML import still breaks its type link. The preview warns; restore the link in TIA Portal.
- Tools that need an option package (SiVArc, DCC, Startdrive and similar) fail when the package is missing.

## Install it next to 3.3

1. Open the [releases page](https://github.com/asckye/TIA_Portal_Openness_MCP/releases), select `v4.0.0-beta.3`, and download
   `TIA_MCP_Delivery_v4.0.0-beta.3_<date>.zip` and its `.sha256` sidecar. Do not use `/releases/latest`: pre-releases are never
   latest. In PowerShell, run `Get-FileHash -Algorithm SHA256 -LiteralPath '.\<downloaded-package>.zip'` with the actual filename,
   then open the matching `.sha256` file and compare its 64-character hash with the command's `Hash` value (case does not matter).
   Extract only if they match; otherwise download both files again. This verifies the hash, not a publisher signature.
2. Unpack it into a new folder, for example `C:\TIA_MCP_4.0.0-beta.3`. Do not unpack it over the 3.3 installation and do not run the
   3.3 updater on it. Each installation keeps its own data and logs when its folder is writable.
3. Start `TiaOpenness.exe` from the new folder and use the environment check. Point a separate MCP client entry at the new folder;
   keep the 3.3 entry for your normal work. See [configuration](../getting-started/configuration.md).
4. Use copies of your TIA projects. Do not connect the 3.3 and the 4.0 hosts to the same TIA Portal process at the same time.
5. To remove the pre-release, close its processes and delete its folder; the 3.3 installation is not changed.

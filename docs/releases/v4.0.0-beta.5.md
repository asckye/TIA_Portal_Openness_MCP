# v4.0.0-beta.5 — fifth 4.0 pre-release

This is the fifth 4.0 pre-release of Automation Engineering Workbench (formerly TIA Portal Openness MCP).
It is a **pre-release** on GitHub: it is never marked as the latest release, and is not offered by the
3.3 updater or the Workbench update check of a 3.3 installation. Download it by hand from the
[releases page](https://github.com/asckye/TIA_Portal_Openness_MCP/releases) to test it.

Unless a release is named below, the changes apply to all eight supported TIA Portal releases, V14 SP1, V15.1 and V16–V21.
The beta.5 changes have not run on a real TIA Portal. A separate real-machine regression session follows publication.

## Behavior changes you must know

- **Unknown writes no longer lock the session.** An unknown result belongs to its call. Later independent requests can run,
  subject to their normal project, preview and approval checks. `GetSessionState` keeps unconfirmed request IDs in
  `data.sessionState.unsettled`, and the Workbench shows their count. `SaveProject` and `SaveProjectCopy` warn with
  `UNSETTLED_CALLS` in preview and apply. Inspect the actual target before deciding on another write; **never replay an
  unknown write automatically**. Recovery does not replay it either.
- **A wait budget is not an operation deadline.** A native call that outlasts the client's wait returns `in-progress` with
  `OPERATION_IN_PROGRESS`, while the worker continues. Read the final result with `GetCallResult(requestId)`, available
  in lite and while busy. Other native calls return a temporary busy refusal until it finishes; disconnect and worker restart refuse
  while it is running. Identical writes remain guarded until their result is read. Results live in the current session's
  memory, with at most 16 completed full results plus running calls; retained summaries identify guarded unread writes
  whose full result has been evicted. Reading a result does not prove an unknown write safe to repeat.
- **TIA dialogs are visible with running calls.** Running-call replies, busy state and the Workbench include reported
  dialogs. Unanswered confirmations promptly return `in-progress`; notifications and confirmations with only Ok are
  acknowledged after recording. Read-only window observations can identify an unhandled modal window. Compile, transfer,
  import/export, archive and library-update wait budgets are 300 seconds; the native operation can continue beyond them.
- **Abandoned attachments can give way.** Within one host, `ConnectPortal(processId, takeOver=false)` can take an eligible
  idle attachment after ten minutes without requests. `takeOver=true` permits a more recently active idle holder. Running
  calls, approval waits, Workbench participation, operator ownership and worker-started TIA instances keep their guards. Handover is audited,
  carries unsettled IDs and leaves the previous session able to reconnect. Cross-host lease refusals identify the holder's
  host PID and release. An unclean previous owner produces `PREVIOUS_OWNER_UNCLEAN` on a new explicit connection.
- **Lost workers recover on the next native call.** Recovery rebinds the recorded TIA process and exact project, reports
  `WORKER_RESTARTED` and retains export handles and unsettled calls. A new TIA PID is selected only when exactly one matching
  project is open without attached Openness clients. Running calls and live workers that started their own TIA retain their
  stop guards. Recovery changes the binding generation: make a fresh preview if the old plan is stale. Disconnect allows a
  new connection in the same MCP session and reports `disconnected`; the old TIA-restart fields are removed.
- **Reset fields and the reset error are removed.** This is a hard cut under ADR 0001, with `schemaVersion` still 4.
  `meta.requiresSessionReset` and `SESSION_RESET_REQUIRED` are gone. Read `meta.outcome` for the call and
  `GetSessionState.data.sessionState.unsettled` for unconfirmed writes. Typed results rename `data.requiresSessionReset` to
  `data.outcomeUnknown` for device add, document import/export, batch export, batch document import/export, external-source
  tools and special export, keeping the values unchanged. Batch import keeps only `data.nativeOutcomeUnknown`.
- **Some unknown writes can be settled by evidence.** Eligible calls use definite read-back on the existing worker lane or
  after rebind. The original result remains `OUTCOME_UNKNOWN`; `data.settlement` and `sessionState.settled` record the
  evidence. Settled calls stop save warnings, and `not-applied` releases the identical-write guard. Ambiguous reads, compile
  and overwrite imports remain unsettled. Optional settlement reads use a separate request identity and a five-second
  budget; each rebind attempts one eligible entry, rotating the rest on later rebinds. These checks never replay writes.
- **Errors point to declared fields.** DES-4R2 uses RFC 6901 JSON pointers and `details.expected`, including batch row prefixes
  and allowed values where applicable. Undeclared caller keys stay private. Missing targets identify known declared
  parameters; otherwise their target remains null. `ALREADY_EXISTS.details.target` is now a declared JSON pointer, or null
  when no catalog can verify the parameter. Known unchanged refusals use
  typed errors such as `NOT_FOUND`, `INVALID_ARGUMENT`, `ALREADY_EXISTS` and `UNSUPPORTED_CAPABILITY`; writes whose effects
  cannot be established remain `OUTCOME_UNKNOWN`.
- **Native reasons remain useful after redaction.** DES-4R3 keeps the redacted first-line native reason and `error.innererror`
  with the worker's short exception type, numeric HResult and request correlation ID. `GetNativeInvocationLog` accepts
  `diagnosticId` and bounded offset paging, excludes its own rows and returns empty pages after journal rotation. Redaction
  covers URL userinfo, private keys, structured credential echoes and scoped one-character secrets as whole tokens,
  including JSON-escaped and URL-encoded forms. Runtime-channel and per-item failures retain the safe reason.
- **Compile and import defaults are safer.** `CompileDevice` now previews by default; execution needs `dryRun:false`, its
  preview's `expectedPlanHash` and the exact bound `expectedProjectFile`. `ImportTechnologyObjectsFromDirectory` defaults
  to `overwrite:false` on V16–V21. Replacing existing technology objects requires explicit `overwrite:true`.
- **Previews disclose what they checked.** Generic write previews say `targetVerified:false` for the cached target and expose
  `data.targetBound`; an unbound apply refuses with `PROJECT_NOT_BOUND`. `PreviewToolCall` reports effective dry-run state
  and `data.changesState`, validates prefill fields as the real tool does, and names its tool's prerequisites. Generic reads
  report `readOnlyInvocation:true`. Web-variable and operating-mode previews retain their login/current-value reads and
  disclose `contactedDevice:true`. S7 Web API safety flags reflect the current HTTPS exchange; certificate validation is
  claimed only after a response with checks enabled and is null when disconnected. Executed results no longer carry
  `targetVerified` or preview scope text; scope returned by native execution is preserved.
- **Small response-shape changes matter to clients.** `PreviewToolBatch.data.previewToken` aliases `data.token`, which remains
  until 5.0. On V19–V21, Unified HMI replies omit null DTO members while preserving false, zero and empty strings.
  On V19–V21, `GetUnifiedGraphicSelection` puts `records` and `nextCursor` under `data.page` and uses its public tool name in page scopes;
  `CompareUnifiedGraphicSelections` accepts both old and new labels. Migration pages and failure paths also name their
  public tools. HMI, hardware, library and optional-package scalar dates use ISO 8601 round-trip strings, preserving
  fractional seconds and timezone information.
- **Symbolic HMI types follow TIA.** On V19–V21, `EnsureUnifiedHmiTag.hmiDataType` and
  `BindUnifiedHmiTagDynamization.dataType` default to empty. Symbolic tags use TIA's type; absolute tags still default to Bool.
  Dynamization type, PLC tag and address are optional expectations compared after binding, because those properties are
  read-only. Colour conversion and verification accept `0xAARRGGBB` as well as the existing forms on V19–V21.

## What is new compared with beta.4

- **More accurate write outcomes.** A failed block move restored and verified in its original group reports `failed` unless
  target groups were created. Technology-object creation refused without changes reports `failed`. Verified imports retain
  a negative verdict, failed undo on an object subsequently deleted by rollback does not alone force `unknown`, and applied
  batch document imports report `succeeded`. Uncertain native document imports remain `unknown`.
- **Stable PLC import verification.** Read-back and preview tokens ignore TIA-computed dates and memory sizes, so an unchanged
  block can keep its reviewed token after compilation. A completed mismatch reports `failed` and keeps backup and cleanup
  evidence. `PatchPlcBlockDocument` adds `setMemberComment` for DB, FB/FC interface and UDT members across all eight releases.
  UDT member comments are imported without verification.
- **PLC and offline refusals explain the next step.** Failed live S7 watch connections keep the connection reason. Offline
  comparisons identify `plc-online` and suggest `ConnectOnlinePlc`; alarm export identifies missing PLC text lists. Real
  tag-table, block and type deletion needs `dryRun=false`, `confirm=true` and the exact bound `expectedProjectFile`.
  Offline library/template analyses distinguish completed findings from missing folders, and release validation identifies
  caller-supplied fixtures absent from the repository and package. ASCII source guidance explains re-saving without a BOM.
  Source replies expose `encoding` and `importableByTool`; other text keeps its UTF-8 BOM and manual import instructions.
  Online monitoring/data-provider planning reports invalid fields as `INVALID_ARGUMENT` instead of `plc-operation`
  preconditions, accepts ordinary and quoted PLC member names and filters provider options by intent.
- **Hardware paths and reads are clearer.** Printed device paths and arrays containing `/` in names resolve on the seven
  string device entries. Ambiguous paths report `TARGET_AMBIGUOUS` with candidates; missing arrays report `NOT_FOUND` with
  a pointer and bounded candidates. Network-info reads disclose their attribute-name heuristic and partial reads. Hardware
  features use `present:null` for unprobed features and compute completeness from probes and page coverage. Subnet validation
  and hardware utilities refuse invalid inputs before a write, with declared fields and useful reasons.
- **Unified and Classic HMI fixes.** Unified items apply on V19–V21. Symbolic tag rollback restores bindings and types in the right order. Event scripts keep
  safe native reasons, and empty event deletion accepts a comment-only definition area with empty ScriptCode. Exact unbound
  Tag snapshots can be previewed and deleted when their Address, DataType and PlcTag getters fail. Optional faceplate `typePath` can be omitted.
  Unified template layout resolves dimensions from declarations, names and caller fallbacks; PLC sync explains missing
  bindings and blockers. Classic HMI and SiVArc accept absolute `/Group/Sub` folders. V21 optional assemblies load by exact
  SDK identity, distinguishing absent components from load failures.
- **Discovery and status are more precise.** Capped lists report counts and truncation; `FindTools` reports matching counts
  and page ranges and restores no-match recovery guidance. Tool descriptions use one usage hint and maintained examples.
  Passive self-tests use cached state unless `connectIfNeeded=true` authorizes project validation and tree reads. Detached
  calls report Busy with the running request, and compile counts exclude declared summary nodes.
- **Client and installation fixes.** STDIO emits each JSON-RPC message and newline as one serialized frame. Rate-limited
  pre-release update checks report the latest version as unknown, unknown ZIP sizes omit the MB figure, and new installations
  start with approval enabled instead of inheriting a disabled old-profile switch.

## Known limitations

- **MTA-1 is not in this release.** V14 SP1–V19 workers still use STA; V20/V21 use MTA. The MTA migration is implemented on
  its own unmerged branch and awaits eight-release VM smoke tests. The maintainer moved it to beta.6 on 2026-11-16.
- **VMFIX-10D is deferred to beta.6.** S7DCL admission and PLC document diff defects M11 and M13 are not fixed in beta.5.
- **No beta.5 changes have been re-verified on real TIA since beta.4.** Offline tests, generated contracts and corrected
  examples do not prove the fixes on a real project. The generated checklist below remains unverified.
- **Externally reported V21 risks remain unreproduced.** These include Unified alarm-indicator and transactional screen
  crashes, widget binding loss, silent S7DCL import changes, repeated textual-interface export/import crashes, Classic HMI
  graphic-list export crashes, incomplete cross-reference placeholders and unreadable technology-object instance DBs.
  The [real-machine testing manual](https://github.com/asckye/TIA_Portal_Openness_MCP/blob/master/docs/manuals/real-machine-testing.md#v21-外部报告的风险复现)
  lists the reproduction cases.
- **Late results are not durable across host restarts.** `GetCallResult` retains results in session memory; callers must keep
  their own evidence and inspect project state after a host restart. Some unknown writes cannot be settled automatically.
- **Update signing is not done.** The maintainer accepted this risk on 2026-11-04. The updater checks a hash from the same
  GitHub release as the ZIP. Someone controlling the GitHub account could publish a malicious update.
- **LAN transport is plain HTTP.** The maintainer accepted this risk on 2026-11-04. Anyone on the same network can read the
  access key and PLC passwords. Use it only on a trusted network.
- **UNC access can precede approval.** Tool input and preview checks can contact a UNC server before an approval card and
  expose Windows credentials. S8, planned before 4.0, will refuse network paths from AI calls, including loopback network paths.
- **Eight-release behavior unification and new capabilities remain unfinished.** UNIFY-1 is still a 4.0 condition. The ten
  new-feature tasks moved to beta.6 remain outside this release. Capabilities depend on each release's actual official API;
  the existing V21 technology-object type/version crash guard remains in place pending real-machine evidence.

- **Some single-object exports are refused on some releases.** `semantics-unverified` previews refuse apply for a
  technology-object export on V14 SP1, V15.1 and V21, and for a watch-table export on V14 SP1. The official API has the
  export on all eight releases, so UNIFY-1 opens these.
- **Some PLC group names are refused.** In tag, technology, watch-table and external-source trees, a group literally named
  `Program blocks` or `程序块` is refused with `INVALID_ARGUMENT`.
- **Directory previews are broader than the import.** The hash includes all nested files. An unrelated changed file makes the
  plan stale, and an unreadable file can refuse preview. A locked apply input may report a validation refusal instead of
  `PLAN_STALE`. Some host preflight checks omit `sourceDirectory` readability.
- **Some output hints need correction.** `ExportPlcBlockDocuments` chooses an existing default directory although its
  description requires a new one. Optional outputs such as `PatchPlcBlockDocument` may advertise an omitted-target default
  they do not provide. Supply an explicit suitable target.
- **Some validation and recovery messages remain imprecise.** HMI connection guidance can name a tool that cannot create the
  connection. A lost TIA process before a network write starts can be reported as an exclusive-access refusal.
- **A refused scaffold step can still report an unknown result.** A refused `BuildProjectScaffold` step can still report the
  whole write as unknown; read the step report before any further write.
- **UDT member comments are imported without verification.** This applies to the new `PatchPlcBlockDocument.setMemberComment`
  workflow; the edited UDT's native import remains unverified.

## Install it next to 3.3

1. Select `v4.0.0-beta.5` on the releases page and download
   `TIA_MCP_Delivery_v4.0.0-beta.5_<date>.zip` and its `.sha256` file. Run
   `Get-FileHash -Algorithm SHA256 -LiteralPath '.\<downloaded-package>.zip'` and compare its hash with the sidecar.
   Extract only when they match. This checks the downloaded bytes. The accepted signing risk is described above.
2. Extract into a separate folder, such as `C:\TIA_MCP_4.0.0-beta.5`, keeping the 3.3 installation separate.
3. Start `TiaOpenness.exe`, run the environment check and create a separate MCP client entry for this folder.
   Follow the [configuration guide](../getting-started/configuration.md).
4. Use project copies, and connect only one host to a given TIA Portal process at a time.
5. To remove the pre-release, close the processes belonging to that installation and remove its folder.

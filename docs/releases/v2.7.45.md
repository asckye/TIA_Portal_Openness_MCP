# v2.7.45

引擎 **2.7.45.0**（V20/V21 均重建）。工具 447 不变，默认 lite 清单 56 项不变。维护者建了一个空工程 `项目1` 让引擎自建设备做测试——临时 S120（V5.2）+ 电机模块 + 电机 + 编码器上**首次真机跑通 DCC 全族**，同时暴露了一处危险的会话重绑和几处小缺陷。

## 修复

| 项 | 内容 | 真机依据 |
|---|---|---|
| 会话绑定 | `GetState` 重绑（"取 `_portal` 的第一个可访问会话 / 工程"）只接受与 `_expectedProjectName` 同名的工程；不同名一律跳过，`_project` 保持不变 | 维护者在第二个 TIA 实例里重新打开 `AutomaticDipCoatingMachine` 后，引擎在几次 `GetState` 之后从显式绑定的 `项目1` 切到了它，`AddHardwareCatalogDeviceWithProbe` 把 `MCP_TP700` 建进了维护者的工程（已立即删除，未保存） |
| `PlugDeviceItem` / `GetDevicePlugLocations` | 新参数 `plugOnDevice`：以 Device（站）本身为 `HardwareObject` 宿主；`ReadFreeSlots` / `ReadOccupiedSlots` / `ResolveNewItemName` 改收 `HardwareObject`；槽位 65535 插入后按新对象名读回并回报真实位置 | 官方 "Creating a drive component" 用 `Device.PlugNew`；真机 `Device.CanPlugNew("OrderNumber:6SLxx2x-1xxxx-xxxx", name, 65535)` = true，CU 设备项 / 机架项上全部 false；插入后位置是 200（电机模块）/ 1000（电机），按 65535 读回失败 |
| `ManageDccPin update` | `Value` 按当前值的 CLR 类型转换（`TypedValueChanges`） | ADD 块输入 X1 是 `System.Single`：2.5 → "The type of the argument 'Value' (System.Double) is invalid"，2 → "System.Int32 … not accepted in place of System.Single" |
| `ManageDccChart` / `ManageDccBlock` | 只带 `sequenceIndex` 的 update 合法（`DccLogic.ValidateChartRequest / ValidateBlockRequest` 收 `sequenceIndex`） | 真机被引擎拒 "update needs at least one property" |
| `AddDevice` | 失败时列出每个 TypeIdentifier 变体（× 项名）的尝试与短原因（最多 24 行），并提示用目录原样标识（以 `OrderNumber:` 开头的 `orderNumber` 原样使用） | TP700 Comfort：`AddDevice {orderNumber:"6AV2124-0GC01-0AX0", version:"14.0.1.0"}` 失败时只报最后一个变体 `.../V14.0.1.0.0.0`，而目录原样的 `OrderNumber:6AV2 124-0GC01-0AX0/14.0.1.0`（`AddHardwareCatalogDeviceWithProbe` 用它插成功）在变体列表里也试过、为何被拒看不到 |
| `ExportAlarmInstanceTexts` | 描述改指 `ImportPlcAlarmInstanceTexts` | 此前写着 "ImportInstanceTexts (not yet exposed)"，`Check-DeadToolReferences.py` 的对应例外一并删除 |

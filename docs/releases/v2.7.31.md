# v2.7.31

引擎 **2.7.31.0**（V20/V21 均重建）。工具 380 → **386**，默认 lite 清单 56 项不变。本版做两件事：修 2.7.30 真机暴露的三处问题，以及"官方 Openness API 全量对齐"计划 [路线图 §2.0](../development/roadmap.md#20-官方-api-全量对齐计划) **阶段 3 子批次 ③-②：库深层**——`ILibrary` 的更新检查 / 同步 / 协调 / 清理、类型与版本的深层字段、详细比较、全局库信息与归档，逐页对照官方 "Functions on libraries" 章节与 `Siemens.Engineering.Base.xml`。

## 2.7.30 真机问题的修复

| 问题 | 修法 |
|---|---|
| 变更前取到的 HW 组合代理陈旧：`MrpDomainComposition.Create` 后在旧代理上按名查不到（工具误报失败）；`Delete` 后枚举旧代理抛 `EngineeringObjectDisposedException` | `ManageNetworkDomain` / `ManageTransferArea` / `ManageDeviceUsers` 的核对一律**从 owner 重新导航**取新组合（`FindOnFresh` / `CountOnFresh`）；`Create` 以返回的代理为准读 `Name`（`createdName`，TIA 可能规范化）并附 `foundByNameAfterCreate`；`Delete` 后若新组合枚举仍撞已释放代理，记为 `absenceEvidence` 而不是失败 |
| 该异常误触发连接失败保护，阻断所有步骤工具直到 `AttachToOpenProject` | 保护本身**保留**（HMI 快照那条策略是 2.7.26 因 TIA 进程崩溃学到的，既有测试钉住）；改为在预期出现已释放代理的地方就地捕获（`HmiReadSafety.DisposedObjectOnly`：链上只有 `EngineeringObjectDisposedException`、没有 remoting/COM 形状的失败），不再让它逃到 `RunHmiStepTool` |
| `ReadDeviceItemChannels` 的 `attributeNames` 缺访问模式，写前只能猜只读 | `attributeNames` 改为 `[{name, accessMode}]`（`GetAttributeInfos().AccessMode`）；`UpdateDeviceItemChannel` 写前按它拒绝 `Read` / `None` 属性（`readOnlyAttributes`），未列出的属性照原样尝试并在 `unlistedAttributes` 标明 |

## 新增工具（域 `Library`）

| 工具 | 动作 | 官方入口 |
|---|---|---|
| `ReadLibraryOverview` | 工程库或已打开的全局库：`GlobalLibrary` 头（Author / Comment 按语言 / Copyright / Family / Version / Path / CreationTime / LastModified(By) / IsModified / IsWriteProtected / Size、`HistoryEntries`、`UsedProducts`）、`TypeFolder` 树（文件夹 `Status`，每个类型的 Guid / Namespace / DoNotUse / SetForUpdate / MinimumTargetDeviceVersion / Status / 版本摘要）、`MasterCopyFolder` 树（Author / CreationDate / `ContentDescriptions`）；`maxDepth` / `maxItems` 有界 | `GlobalLibrary.*`、`LibraryTypeFolder`、`MasterCopy.ContentDescriptions` |
| `ReadLibraryType` | 按 `typePath` 或 `guid`（`FindType` → `FindVersion`）定位类型：类型标量 + `GetSupportedExportFormats` + 每个版本的 State / IsDefault / OriginalLibrary / `Dependencies` / `Dependents` / `MasterCopiesContainingInstances`（逐字段捕获失败，InWork 版本官方注明可能抛） | `ILibrary.FindType/FindVersion`、`LibraryTypeVersion.*` |
| `ManageLibraryType` | `update`（Name / DoNotUse / SetForUpdate）、`delete`、`updateLibrary`（`LibraryType.UpdateLibrary` 四参重载，目标按 GUID 读回）、`updateProject`（`LibraryType.UpdateProject` 逐范围） | `LibraryType.UpdateLibrary/UpdateProject/Delete` |
| `CheckLibraryUpdates` | `ILibrary.UpdateCheck(project, mode)` 的消息树（Description / MessageParts / 嵌套 Messages）扁平化 | `UpdateCheckResult` |
| `SynchronizeLibrary` | 选择集（`[{"type":…},{"folder":…}]`，`{"folder":""}` = 整个 Types 文件夹）上的 `updateLibrary`（五参重载）、`updateProject`（工程库三参 / 全局库五参重载）、`harmonizeProject`（`HarmonizeNames` / `HarmonizePaths`）、`cleanUp`（工程库带 `CleanUpMode`，用户全局库无模式）；实做需 `confirmChange` | `ILibrary.*`、`ProjectLibrary.CleanUpLibrary`、`UserGlobalLibrary.CleanUpLibrary` |
| `CompareLibraryObjects` | 同类两对象的详细比较（`LibraryType` / `LibraryTypeVersion` / `MasterCopy` 的 `CompareTo`）：`DetailedCompareResult.Properties` 行（Description / DetailCompareStatus / LeftValue / RightValue）+ 状态汇总 | `Compare.DetailedCompareResult*` |

扩展：`ManageGlobalLibrary` 新增 `infos`（`GetGlobalLibraryInfos`：本 Portal 认识的全部库，含未打开的）、`openInfo`（`Open(GlobalLibraryInfo)`）、`archive`（`UserGlobalLibrary.Archive`，四种 `LibraryArchivationMode`，未保存的库按官方约束拒绝）；`ImportLibraryTypeDocuments` 改为强类型读回 `TypeCreateTransferResults`（`CreatedType`、`Messages`、`TransferResultState`），新增 `typePath` + `createOptions` 走 `LibraryTypeVersionComposition.CreateFromDocuments`（"Updating type from document"），STEP 7 文档可给 `targetSoftwarePath` + `targetGroupKind` + `targetGroupPath` 作目标环境。

未暴露：`LibraryTypeVersion` 上的 `IUpdateProjectScope` 只接受 `PlcSoftware` / `HmiTarget` / Unified `HmiSoftware`（V20 上 Unified 不实现）；`ProjectLibrary.ImportDcbLibrary` 为 V20 独有，留给 DCC 选件包阶段。`LibraryCompareResult*` 仍由 `CompareLibraries` 的反射遍历到达，登记为动态覆盖。

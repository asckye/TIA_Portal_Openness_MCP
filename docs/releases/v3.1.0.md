# v3.1.0 — Openness diagnostics, PLC editing and V21 ecosystem tools

Released 2026-10-01. Complete V20/V21 delivery, with engine and configurator file version **3.1.0.0**. The full inventory contains **486 tools**, including **22 additions** since v3.0.0; the default lite profile exposes **62**, with the others accessible through `FindTools` and `CallTool`.

## Changes

- Optional `--isolate-openness` keeps MCP host diagnostics available after a worker failure. The supervisor uses bounded queues/deadlines, explicit recovery and no automatic write replay. It remains disabled by default. Exact project binding and cross-process TIA ownership checks reduce accidental session switching. See [isolation and recovery](../guides/openness-worker-isolation.md).
- The generated tool matrix is now replaced atomically, so an open memory-mapped viewer does not make publication fail while truncating the existing document. First creation and replacement with an active mapped view were checked locally.
- Fine-grained diagnostics cover supported engine-owned Openness call boundaries. The build checks instrumentation coverage and wrapper compatibility; stage records distinguish attempted, returned and thrown calls. They do not instrument Siemens internals or prove crash safety.
- PLC cross-reference protections also cover reflection routes. Native queries remain disabled by default because they have caused TIA exits. Download readiness uses actual consistency evidence, and document import checks use exact returned objects rather than ambiguous name matching.
- PLC document workflows add offline call/symbol reference analysis, capability inspection, bounded XML text/start-value edits, and guarded overwrite import with retained export and readback comparison. Native import/compilation acceptance remains pending. See [editing workflow and limits](../reference/ecosystem-tools.md#plc-editing-and-offline-references-local-310-candidate).
- V21 ecosystem additions provide a dated official/third-party catalog, local Siemens XSD fragment validation, analysis-only SimaticML decoding and custom web control packaging. The catalog has 86 entries with explicit compatibility, licensing and integration status; it is not a list of 86 fully integrated products. See [ecosystem adapters](../reference/ecosystem-tools.md#v21-ecosystem-survey-and-adapters-2026-10-01).
- Precise HMI tag deletion, software-unit document operations, V20 option wrappers and compatibility diagnostics extend existing native tools. Siemens AI guidance is pinned to the latest reviewed source; all 32 guide bodies remain unchanged.

## Validation

The release build records both Windows/net48 engines, **2,703 offline checks**, **75 ecosystem protocol checks per version**, and **17,936 local tool calls** across direct/isolated hosts, STDIO/HTTP and full/lite profiles. API shape checks cover 2,840 cases for V20 and 3,126 for V21; the configurator has 111 checks. HTTP, resource discovery, process leases, fault injection, native journal readers and diagnostic wrapper checks are also in the [build record](../../manifest/release-build.json).

The pinned decoder separately passed 107 selected upstream tests; two symbolic-link tests were skipped because the local Windows account could not create symlinks. Older extended stress and probe records are historical evidence for their recorded binaries, not additional tests of this release.

These checks do not attach to TIA, compile a user project or download to a PLC. This publication does not include new native acceptance or deployment to the user's virtual machine. The standalone native lifecycle/MCP/probe harnesses remain explicit opt-in tools.

## Known limitations and upgrade

- The V21 Unified script-library type `Name` crash remains unresolved. The known write route is guarded; this is not a usable rename fix. Standalone diagnostic preparation and evidence are included without claiming successful native rename tests.
- Native PLC cross-reference crash safety, faceplate type creation and editing of type-internal controls/scripts are not certified by this release. Offline reference analysis cannot prove that an object is unreferenced or safe to delete.
- Worker isolation protects availability of the MCP host; it cannot guarantee that TIA survives a failing API call. Writes interrupted by failures can have unknown outcomes and must not be replayed automatically.
- SimaticML decoding is for reading only: its output is not recompilable/reimportable. XSD validation covers recognized fragments, not the whole export or instruction semantics. CWC packaging checks basic file/manifest conventions, not JavaScript behavior, the complete manifest schema or runtime compatibility; CWC is distinct from a faceplate/library type.
- Official MAC, Project Check, external IDEs and remaining catalog candidates are not all embedded. Do not treat upstream claims or a V21 version selector as local acceptance.

Download the complete **TIA_MCP_Delivery_v3.1.0_20261001.zip** and its `.sha256`, rather than GitHub's source-only ZIP. Stop the MCP service before updating; the configurator's update workflow verifies and backs up the existing installation. Reconnect clients after restarting the engine. This publication does not automatically update a running service.

The archive contains V20/V21 runtimes and the WPF configurator, source, tests, documentation, templates and licenses. Siemens PublicAPI assemblies, private TIA projects, credentials and build logs are excluded. Python companion tools need their documented environment setup; isolation remains opt-in. V17–V21 upstream branches are retained independently and are not additional certified runtimes in this package.

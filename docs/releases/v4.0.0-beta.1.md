# v4.0.0-beta.1: Draft

This is an unpublished draft of the first 4.0 pre-release. It is published on GitHub as a **pre-release**: it is never marked as the
latest release, and the 3.3 updater and the Workbench update check of a 3.3 installation do not offer it. Download it by hand from the
release page to test it. Its CHANGELOG entry (`## [4.0.0-beta.1] - <date>`) is added right before the release command, because the
delivery check compares the newest CHANGELOG entry with the packaged version.

This pre-release was not tested on a real TIA Portal. Builds, the offline suites, the V4 contract and response snapshots and GitHub CI
passed; the items that only a real TIA Portal can confirm are listed at the end. Please test with copies of your projects only.

## What is new compared with 3.3.0

The complete list is in the [4.0.0 release draft](v4.0.0.md); the main points:

- **Breaking MCP changes.** Tool names are normalized by operation and domain, inputs use typed V4 schemas, and every result uses one
  schema-version-4 envelope. There are no 3.x tool aliases; the [tool migration tables](v4.0.0-tool-migration.md) list every old name
  with its destination. Update prompts, scripts and client rules that call 3.x tool names.
- **One host for all eight releases.** V14 SP1 to V21 start `TiaMcp.FoundationHost.exe --release-key <key>` from their own runtime
  folder, and the host starts a per-session Openness worker. Tools common to all eight releases share one implementation.
- **Sessions and safety.** Every MCP session has its own worker and leases the selected TIA process; an unknown write outcome locks
  the session until it is inspected and disconnected. Writes are previewed before approval, and refusals are typed.
- **More tools on V14 SP1 to V19**, ported from V20/V21 where the release's API allows them, plus the Workbench control, standard
  package and staging tools on every release.
- **Workbench.** Write approvals, a hash-chained audit log, a live call panel, an environment check, ladder rendering and the
  program book.
- **Updater.** The C# updater (`runtime/tools/TiaMcp.Updater.exe`) replaces the PowerShell script. A pre-release installation is
  offered newer pre-releases and the final release; a plain installation is only offered plain releases.

## Install it next to 3.3

1. Download `TIA_MCP_Delivery_v4.0.0-beta.1_<date>.zip` and its `.sha256` from the GitHub pre-release and check the SHA-256.
2. Unpack it into a new folder, for example `C:\TIA_MCP_4.0.0-beta.1`. Do not unpack it over the 3.3 installation and do not run the
   3.3 updater on it. Each installation keeps its own data and logs when its folder is writable.
3. Start `TiaOpenness.exe` from the new folder and use the environment check. Point a separate MCP client entry at the new folder;
   keep the 3.3 entry for your normal work. See [configuration](../getting-started/configuration.md).
4. Use copies of your TIA projects. Do not connect the 3.3 and the 4.0 hosts to the same TIA Portal process at the same time.
5. To remove the pre-release, close its processes and delete its folder; the 3.3 installation is not changed.

## 修复：按 `SW.PlcBlocks.Access_v5.xsd` 重写 SCL 的 Access / Symbol 渲染

对照本机 PublicAPI 的 XSD 确认了两处根因并一并覆盖 Access 的全部分支：

- **`Symbol` / `Instance` 是有序 Token 序列**：SCL 导出把 `.`、`%X15`、`[`、`]` 都作为 `<Token>` 放在 Symbol / Component 内部，原实现只拼接 `<Component Name>`，标点和切片随之丢失。现按子节点顺序渲染；FlgNet 导出没有 Token 时才合成 `.`、`[…]` 与 `SliceAccessModifier`，`#` / `"…"` 前缀始终由作用域决定。
- **`ENO` 是 `<PredefinedVariable Name="ENO"/>`**（仅 SCL），新增渲染。
- 同时补齐 `Label`、`Statusword`、`DataType`、`Expression`、`Reference` 分支；`IntegerAttribute` / `StringAttribute` / `BooleanAttribute` / `DateAttribute` / `TemplateValue` 这类信息性元数据不再泄漏进正文，`Parameter` 的命名参数判断也跳过它们。

## 修复：离线文档工具同一族的漏渲染

`RenderPlcBlockDocument`、`ComparePlcBlockDocuments`、`GeneratePlcDocumentation` 走的是另一套 `OfflineAnalysisLogic` 渲染，在同一个块上暴露了同类问题：`LocalConstant` / `GlobalConstant` 命名常量输出为空（`#statStatus := ;`）、`REGION` 名丢失（`<Text>` 节点未处理）、`ENO` 丢失。三者已修，信息性 `*Attribute` 元素同样跳过。

# v2.7.26

引擎 **2.7.26.0**（V20/V21 均重建）。工具 362 → **364**，默认 lite 清单 56 项不变。"官方 Openness API 全量对齐"计划（[路线图 §2.0](../development/roadmap.md#20-官方-api-全量对齐计划)）第二阶段 WinCC Unified 的第一个子批次：**画面对象族**——`Siemens.Engineering.HmiUnified.UI.Shapes` / `Widgets` / `Controls` / `Screens.HmiScreenWindow` 的全部 43 个具体画面对象类型（V20 37 个）及其 `UI.Base` 基类和 13 个 `UI.Features` 特性接口。

## 为什么先做画面对象

此前创建画面对象只有 Button / Rectangle / Text / IOField 四个别名（其余要给完整 CLR 名且没有属性表），改属性要靠通用路径工具且不支持颜色；而画面对象是 Unified 未封装类型里最大的一块（69 个类型），也是 AI 生成画面最常碰的。

## 新增

| 工具 | 内容 | 官方入口 |
|---|---|---|
| `DescribeUnifiedScreenItemType`（新，不需要工程） | 空 `itemType` 返回目录：加载的官方 API 里每一个具体画面对象类型（分组 Shapes / Widgets / Controls / Screens）及其实现的 `IHmi*Feature` 接口；给名字（`HmiCircle`、`Circle`、`Widgets.HmiSlider` 或完整 CLR 名）返回属性 schema——每个属性分类为 scalar / color / multilingual / part / collection / reference，附 CLR 类型、枚举值、可写性，部件（`Font`、`Padding`、`Corners`…）按 depth 展开子属性，另给事件类型枚举与 `Delete` 可用性 | 反射自 `Siemens.Engineering.WinCCUnified.dll`（V20 为合并的 `Siemens.Engineering.dll`） |
| `ManageUnifiedScreenItem`（新） | 单张画面（`screenPath` = 唯一画面名或 `/组/画面`）上任意类型的画面对象：`list`（名称/类型/几何，分页）、`read`（标量与 `#AARRGGBB` 颜色、部件与集合按 depth 展开、每种语言的 `MultilingualText`、特性接口、事件/动态化计数）、`create`（`itemType` 经原生 `Create<T>(name)`，容器类可给 `containedType` 走 `Create<T>(name, containedType)`，可带初始 `propertiesJson`）、`update`、`delete`（`confirmDelete`）。`propertiesJson` 里部件写成嵌套对象（`{"Font":{"Size":14},"BackColor":"#FF0000FF"}`），多语言文本按 culture（`{"Text":{"en-US":"Start"}}`，给纯字符串会被拒绝以免只写一种语言）；每个叶子都读回核对 | `HmiScreenItemBaseComposition.Create<T>`、`HmiScreenItemBase.Delete`、各类型公开属性 |

顺带修复：`HmiSlider` / `HmiToggleSwitch` / `HmiCircleSegment` / `HmiEllipseSegment` 用更窄的组合类型隐藏了基类的 `EventHandlers`，`Type.GetProperty("EventHandlers")` 对它们抛 `AmbiguousMatchException`——`ReadUnifiedObjectEvents` / `ManageUnifiedObjectParts` / `ManageUnifiedDynamization` 的嵌套读写此前在这四种对象上会失败。现统一改为取最派生的声明（`UnifiedUiModelLogic.FindProperty`），离线测试用同形态的假类型复现并锁定。

## 覆盖口径的变化：动态覆盖登记表

这一族的类型名从不出现在源码里（`Create<T>` 的 T 是运行时解析的），词法审计看不见。2.7.26 起引入 [scripts/diagnostics/openness-dynamic-coverage.json](../../scripts/diagnostics/openness-dynamic-coverage.json)：每条登记模式、工具、机制与证据，`Audit-OpennessCoverage.ps1` 匹配后记为 DYNAMIC 并在统计表单列"动态覆盖"栏。没有形状检查或真机证据的类型不登记。本版登记了画面对象族以及 2.7.18 就已存在但一直被算作"未触及"的 `UI.Events`（96）/ `UI.Parts`（85）/ `UI.Dynamization` 适配器。结果：完全未触及 885 → **626**，动态覆盖 262；WinCC Unified 未封装功能类型 113 / 685 → **41 / 219**（剩余为运行时设置、报警、记录、审计、列表、阈值、Cpm，多数已可经通用属性路径到达，按子批次真机验证后登记）。

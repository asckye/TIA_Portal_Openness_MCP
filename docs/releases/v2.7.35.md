# v2.7.35

引擎 **2.7.35.0**（V20/V21 均重建）。工具 402 → **408**，默认 lite 清单 56 项不变。本版做两件事：修 2.7.34 真机暴露的单元关系回读缺陷，以及"官方 Openness API 全量对齐"计划 [路线图 §2.0](../development/roadmap.md) 阶段 4 子批次 ④-②：Step7 收尾——外部源文件、系统组、变量表常量、报警文本列表 XLSX、监控 / 强制表条目、ProDiag 导出，加上十处类型化改造（监控 / 强制表访问规则、OPC UA 通信组与命名空间限制、报警类 / 监控设置结果消息、STEP 7 库类型子类、五种用户组）。阶段 4 只剩 ④-③ 工艺对象映射（5 类型 / 42 成员）。

## 2.7.34 真机问题的修复

| 问题 | 修法 |
|---|---|
| `ManagePlcSoftwareUnit createRelation / deleteRelation`：`PlcUnitRelationComposition.Create` 后同一组合代理上 `Find` 回 null，`PlcUnitRelation.Delete` 后旧代理抛 `EngineeringObjectDisposedException`（引擎按"会话受阻"归类，要重绑） | 回读改为从 `PlcUnitProvider.UnitGroup` 重新导航到单元、枚举 `Relations` 比对 `RelatedObject`（`RelationExists`），不再用旧组合的 `Find` |

## 新增工具（域 PLC-Software / PLC-Alarms）

| 工具 | 动作 | 官方入口 |
|---|---|---|
| `ManagePlcExternalSources` | PLC 或单元的外部源文件（根系统组或 `groupPath` 用户组）：`list`（`PlcExternalSourceGroup` Name / ExternalSources / Groups）、`read`、`createFromFile`（`PlcExternalSourceComposition.CreateFromFile(name, filePath)`，TIA 机器上已存在的 .scl / .awl / .stl / .db / .udt）、`createFromMasterCopy`（`copyMode`）、`delete`、`generateBlocks`（`PlcExternalSource.GenerateBlocksFromSource`，`generateOption` None / KeepOnError，可指定块或类型用户组作目标，回报生成对象名单；原生覆盖同名对象）、`createGroup` / `renameGroup` / `deleteGroup`（`PlcExternalSourceUserGroup`，只删空组） | "Generating blocks from source" / "Generating block/UDT from external source file in specific user group" / "Adding external sources in units" |
| `ReadPlcSystemGroups` | `PlcBlockSystemGroup.SystemBlockGroups` 的 `PlcSystemBlockGroup` 树（Name、块的编号 / 类 / 语言、递归到 `maxDepth`）与 `PlcTypeSystemGroup.SystemTypeGroups`（`PlcSystemTypeGroup` Name / Types）；可指向单元 | "Querying the system group for system blocks" / "Enumerating system subgroups" |
| `ReadPlcTagTableConstants` | 一张变量表的 `UserConstants` + `SystemConstants` 作类型化 `PlcConstant` 行（Name / DataTypeName / Value / kind），分页 | "Tag table" |
| `ExchangePlcAlarmTextListsXlsx` | `PlcAlarmTextListProvider`（PLC 或单元的服务）：`export` 到新建 .xlsx（全部用户文本列表 + 全部工程语言，或 `textListNamesJson` + `culturesJson` 过滤重载，语言经 `LanguageSettings.Languages.Find(CultureInfo)`）→ `TextListXlsxResult` State / LogFilePath + 文件哈希；`import`（`ImportOptions` None / Override）需 `confirmImport` | "Export/Import of Plc Alarm TextLists" |
| `ManagePlcTableEntries` | 监控 / 强制表条目按原生顺序的类型化行：`PlcWatchTableEntry`（Name / Address / DisplayFormat / MonitorTrigger / ModifyTrigger / ModifyValue / ModifyIntention）、`PlcForceTableEntry`（… / ForceValue / ForceIntention）、注释行（`PlcTableCommentEntry`）；监控表支持 `createComment`（`PlcTableCommentEntryComposition.Create`）与 `deleteEntry`（0 基索引 + `confirmDelete`），强制表刻意只读 | 监控 / 强制表章节 |
| `ExportPlcProDiagInfo` | `CodeBlock.ExportProDIAGInfo(directory)`：ProDiag FB 的报警消息导出为 CSV，调用前门控语言 = ProDiag 且一致，新文件哈希 | "Exporting ProDiag alarm message" |

类型化改造（不改工具签名）：`ManageWatchForceTableWebAccess` 改走 `WatchTableAccessRuleComposition` / `ForceTableAccessRuleComposition` 的 `Create` / `Find` 与 `WatchTableAccessRule` / `ForceTableAccessRule` 的 `Access` / `Delete`（行里带 `WatchTable` / `ForceTable` 名）；`GetOpcUaServerInterfaceGroup` 经 `OpcUaProvider.CommunicationGroup`（`OpcUaCommunicationGroup.ServerInterfaceGroup`）；`ReadOpcUaAccessControl` / `ManageOpcUaAccessControl` 的限制行是类型化 `NamespaceAccessRestriction`（V21）；`ExportAlarmClasses` / `ImportAlarmClasses` 回报 `AlarmClassExportImportResult` 的 ErrorCount / WarningCount 与每条 `AlarmClassExportImportResultMessage` 的 Message / State，PLC 上没有提供者时回退到工程（官方说它在 `ProjectBase` 上）；`ManagePlcSupervision exportSettings / importSettings` 回报 `SupervisionSettingsExportImportResultMessage`；`ReadLibraryType` 行新增 `typeKind`（`CodeBlockLibraryType` / `PlcTypeLibraryType` / `PlcDocumentLibraryType`）；`ManagePlcUserGroup` 新增 `watchTables` / `externalSources` 两族并把结果组读回为类型化行（`PlcTypeUserGroup` / `PlcTagTableUserGroup` / `PlcWatchAndForceTableUserGroup` / `PlcExternalSourceUserGroup`）。

只在 PublicAPI 上核实的事实：`WatchTableAccessRule` / `ForceTableAccessRule` 的命名空间是 `Siemens.Engineering.HW`，但 V21 把它们放在 `Siemens.Engineering.Step7.dll` 里；`PlcExternalSourceUserGroup.Name` 在 V20 只读（V21 可写）；`NamespaceAccessRestriction` 仅 V21；`PlcWatchTable.Entries` 是 `PlcTableCommentEntryComposition`（`Create()` 只建注释行，监控 / 强制条目是其子类）；`PlcAlarmTextListProvider` 是 PLC 与单元共有的服务。

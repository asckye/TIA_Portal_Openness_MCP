# v2.7.32

引擎 **2.7.32.0**（V20/V21 均重建）。工具 386 → **389**，默认 lite 清单 56 项不变。本版做两件事：修 2.7.31 真机暴露的四处库工具缺陷，以及"官方 Openness API 全量对齐"计划 [路线图 §2.0](../development/roadmap.md#20-官方-api-全量对齐计划) **阶段 3 子批次 ③-③：用户管理与安全**——工程级 syslog 服务器与 CPU 的 syslog 配置、三套密码策略、UMC（中央）用户 / 用户组 / 服务器、证书模板与主题备用名，逐页对照官方 "Functions for UMAC Global Users and UMC Server"、"Setting password policies for UMAC / for PLC"、"Managing certificate"、"Managing Syslog configuration"、"Accessing Anonymous user" 章节与 `Siemens.Engineering.Base.xml`。

## 2.7.31 真机缺陷的修复

| 问题 | 修法 |
|---|---|
| `ProjectLibrary` 没有 `Name` 属性（PublicAPI 只有 `MasterCopyFolder` / `Parent` / `TypeFolder`），工程库上的 `ReadLibraryOverview` / `CheckLibraryUpdates` / `SynchronizeLibrary` 与原有的 `CompareLibraries` 全部在读头时抛 "ProjectLibrary.Name is unavailable" | 库标签统一走 `LibraryRef`：`GlobalLibrary.Name`，工程库固定为 `ProjectLibrary` 并附所属工程名（`project`）；六处读名全部改用它 |
| `SystemGlobalLibrary.TypeFolder` 为 null（系统库只有母版），`ReadLibraryOverview includeTypes=true` 抛 `NullReferenceException`，选择集解析报泛泛的 "unavailable" | `typeFolder` / `masterCopyFolder` 为 null 时输出 null + `typeFolderNote`；`EngineeringLibraryFolder` 对 null 根给出明确的 `NotFound`（"has no TypeFolder … master copies only"） |
| 对 `SystemGlobalLibrary` 调 `UpdateCheck` 被 TIA 以 `NonRecoverableException` 拒绝，并被连接失败保护当作断连（后续工具阻断，需重新附加） | `CheckLibraryUpdates` 在调用 TIA 前拒绝没有 `TypeFolder` 的库（`ArgumentException`，"Nothing was called on TIA"），并要求已绑定工程 |
| `Close` / `Save` / `SaveAs` / `Archive` 只在 `UserGlobalLibrary` 上，`openInfo` 打开的系统库无法经 API 关闭，`close` 却报 "not found" | `ManageGlobalLibrary` 对找到但不是用户库的目标报 "action=close exists only on UserGlobalLibrary in the Openness API"；`openInfo` 返回 `closableThroughApi` / `hasTypeFolder`，系统库的文案直接说明它会一直打开到 TIA 关闭 |

## 新增工具（域 `Security`）

| 工具 | 动作 | 官方入口 |
|---|---|---|
| `ManageSyslogServers` | `scope=project`：`read` / `create` / `update`（Name / Address / Port / Tls / Comment）/ `delete` / `assignModule` / `unassignModule`（`AssignedModules` 关联的 `Add` / `Remove`，按 `Contains` 核对）；`scope=plc`：`read`（EnableSystemLogging / TransportProtocol / 服务器行 / 三个官方动态属性）/ `update`（属性 + `attributesJson`）/ `createServer`（地址 + 端口）/ `deleteServer` | `Security.SyslogServerProvider.Servers` → `SyslogServerComposition.Create`、`SyslogServer.*`；`HW.Features.SysLogConfigurationManager`、`SysLogServerConfigurationComposition.Create/Find`、`SysLogTransportProtocolType` |
| `ManagePasswordPolicy` | `read`（三套策略与可用性）、`update`（`target=umac|plc|legacyPlc` + `propertiesJson`，逐项读回；legacy 的官方范围 5..8 / 0..8 / 0..8 在调用前核；需 `confirmChange`） | `Umac.PasswordPolicyConfigurator`（8 项）、`Security.PlcPasswordPolicyService.PasswordPolicyEnabled`、`Security.LegacyPlcPasswordPolicyService`（5 项）、`PasswordPolicySettingsException` |
| `ManageUmcUsers` | `kind=user|group`：`read`（Name / IsActive / DomainId / Description / 角色）、`createOffline`（`CreateOfflineUmcUser(name)` / `CreateOfflineUmcUserGroup()` + `SetName`）、`importFromServer`（`GetUserByName` / `GetUserGroupByName` → `Create(info)`，凭据经 `Authentication` 事件写入 `UmcCredentials`，SecureString 不回显）、`rename` / `activate` / `deactivate` / `delete`（刷新组合核对）、`assignRole` / `unassignRole`（系统或自定义角色）；`kind=server`：`read`、`checkConsistency`、`synchronize` | `UmacConfigurator.UmcUsers / UmcUserGroups`、`UmcUser.*`、`UmcUserGroup.*`、`UmcUserInfo` / `UmcUserGroupInfo`、`UmcServerConfigurator.UmcServer / CheckConsistency / Synchronize`、`UmcServer.Authentication` + `UmcCredentials.Name / SetPassword` |

扩展：`ManagePlcCertificate` 新增 `template`（`GetCertificateTemplate(usage)` 的默认值：Signature / SubjectCommonName / Usage / ValidFrom / ValidUntil / `SubjectAlternativeNames`，附三个枚举目录）、`create` 改为类型化模板字段校验（`Sha1RSA` / `Sha256RSA`、五种用途、ISO 日期、`ValidUntil` 晚于 `ValidFrom`）+ `subjectAlternativeNamesJson`（`SubjectAlternativeNameComposition.Create(type, value)`，Dns / Email / IP / Uri）并核对新证书在本地存储里、`import` 支持 `password`（`Import(file, SecureString)`）并回报 `HasPrivateKey`、`list` 附 `LocalCertificateManager.EnableGlobalCertificatesStore`；`ManageProjectUserManagement` 新增 `activateAnonymousUser` / `deactivateAnonymousUser`（无名参数，`UmacConfigurator.ActivateAnonymousUser / DeactivateAnonymousUser`，读回 `AnonymousUser` 状态），`ReadProjectUserManagement` 的设备功能权行带 `identifier` / `group` / `comment`（`SystemDeviceFunctionRight` / `CustomDeviceFunctionRight`），工程用户管理里的组合与关联改为类型化访问（`ProjectUserComposition` / `CustomRoleComposition` / `RoleAssociation` / `EngineeringFunctionRightAssociation`，`Remove` 返回 false 时如实报错）。

未暴露：`UserManagementDownload`（`UserManagementPreDownloadSelection`）属于下载配置回调，归 ③-④ 的下载/上载配置类；`CertificateManagementConfiguration`（动态证书管理、`CertificateSupportedService`）留 ③-④ 硬件收尾；`ProtectProject` / `Protect` / `Unprotect` 仍刻意不暴露。V20 与 V21 在 `Security` / `Umac` 命名空间的功能成员完全一致（只差 `.Any()`），两版共用一份实现。

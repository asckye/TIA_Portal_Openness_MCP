# v2.7.32

引擎 **2.7.32.0**（V20/V21 均重建）。工具 386 → **389**，默认 lite 清单 56 项不变。本版做两件事：修 2.7.31 真机暴露的四处库工具缺陷，以及"官方 Openness API 全量对齐"计划 [路线图 §2.0](../development/roadmap.md#20-官方-api-全量对齐计划) **阶段 3 子批次 ③-③：用户管理与安全**——工程级 syslog 服务器与 CPU 的 syslog 配置、三套密码策略、UMC（中央）用户 / 用户组 / 服务器、证书模板与主题备用名，逐页对照官方 "Functions for UMAC Global Users and UMC Server"、"Setting password policies for UMAC / for PLC"、"Managing certificate"、"Managing Syslog configuration"、"Accessing Anonymous user" 章节与 `Siemens.Engineering.Base.xml`。

## 2.7.31 真机缺陷的修复

| 问题 | 修法 |
|---|---|
| `ProjectLibrary` 没有 `Name` 属性（PublicAPI 只有 `MasterCopyFolder` / `Parent` / `TypeFolder`），工程库上的 `ReadLibraryOverview` / `CheckLibraryUpdates` / `SynchronizeLibrary` 与原有的 `CompareLibraries` 全部在读头时抛 "ProjectLibrary.Name is unavailable" | 库标签统一走 `LibraryRef`：`GlobalLibrary.Name`，工程库固定为 `ProjectLibrary` 并附所属工程名（`project`）；六处读名全部改用它 |
| `SystemGlobalLibrary.TypeFolder` 为 null（系统库只有母版），`ReadLibraryOverview includeTypes=true` 抛 `NullReferenceException`，选择集解析报泛泛的 "unavailable" | `typeFolder` / `masterCopyFolder` 为 null 时输出 null + `typeFolderNote`；`EngineeringLibraryFolder` 对 null 根给出明确的 `NotFound`（"has no TypeFolder … master copies only"） |
| 对 `SystemGlobalLibrary` 调 `UpdateCheck` 被 TIA 以 `NonRecoverableException` 拒绝，并被连接失败保护当作断连（后续工具阻断，需重新附加） | `CheckLibraryUpdates` 在调用 TIA 前拒绝没有 `TypeFolder` 的库（`ArgumentException`，"Nothing was called on TIA"），并要求已绑定工程 |
| `Close` / `Save` / `SaveAs` / `Archive` 只在 `UserGlobalLibrary` 上，`openInfo` 打开的系统库无法经 API 关闭，`close` 却报 "not found" | `ManageGlobalLibrary` 对找到但不是用户库的目标报 "action=close exists only on UserGlobalLibrary in the Openness API"；`openInfo` 返回 `closableThroughApi` / `hasTypeFolder`，系统库的文案直接说明它会一直打开到 TIA 关闭 |

**真机暴露的问题（2.7.33 处理）**：

1. 工程级 `SyslogServerComposition.Create` 让 TIA Portal V21 崩溃（两次复现，无错误对话框、进程直接退出）。`ManageSyslogServers scope=project create` 要在描述里标明，并默认拒绝实做（只留预览），除非未来找到前置条件。
2. `ManagePlcCertificate template` 误要求 `certificateId`——把 `template` 加进免查证书的动作列表。
3. `RequireUmacDevice` 的报错文案应指向 Device 或拥有 UMAC 配置的 DeviceItem。
4. `CheckLibraryUpdates` 的 `messageParts` 是 `KeyValuePair<string,string>`，经 `EngineeringScalarProperties.Read` 渲染后体积膨胀约 60 倍（1539 条 = 2.2 MB）——改为 `{Key: Value}`。
5. 两个 TIA 进程同时打开时（第二个是 `TESL_DU1_30000_SICAR4.0_CH_V17_V21`），引擎在两次调用之间自动改绑到了另一个工程（`IsProjectNull()` 自愈走 `ConnectPortal()` 重挑进程）；显式 `AttachToOpenProject` 后稳定。写工具应核对绑定工程名未变（现有 `expectedProject` 模式）。

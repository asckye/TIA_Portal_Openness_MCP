# v2.7.33

引擎 **2.7.33.0**（V20/V21 均重建）。工具 389 → **396**，默认 lite 清单 56 项不变。本版做两件事：修 2.7.32 真机暴露的五处问题，以及"官方 Openness API 全量对齐"计划 [路线图 §2.0](../development/roadmap.md#20-官方-api-全量对齐计划) **阶段 3 子批次 ③-④：Base 收尾**——`Siemens.Engineering.Base.dll` 里最后 52 个未封装功能类型（门户 / 会话诊断、事务、对象标识、受保护工程与 UMAC 在线凭据、传输路由与 R/H 冗余系统、硬件工具、Web 应用 / 遥控数据点 / 动态证书管理、类型化的传输提示 / 结果 / 交叉引用 / 比较 / 目录 / 多用户 / 版本控制 / 设置行）。**Base 的功能类型缺口归零，阶段 3 收口。**

## 2.7.32 真机问题的修复

| 问题 | 修法 |
|---|---|
| 工程级 `SyslogServerComposition.Create(name)` 让 TIA Portal V21 崩溃（两次复现） | `ManageSyslogServers scope=project create` 只留预览：`dryRun=false` 在调用前被 `NotSupportedException` 拒绝，文案说明原因与替代路径（TIA 界面里建，本工具 `read` / `update` / `assignModule` / `delete`）；描述里标 PREVIEW ONLY |
| `ManagePlcCertificate template` 误走"按 `certificateId` 查证书"的门 | `template` 加进免查证书的动作列表 |
| `RequireUmacDevice` 报错指向 CPU 项，而 `UmacDevice` 在设备上 | 文案改为 "on the reference project it lives on the Device (devicePathJson only, itemPathJson=[])" |
| `CheckLibraryUpdates` 的 `messageParts` 经标量读渲染，1539 条 = 2.2 MB | `KeyValuePair<string,string>` 直接渲染为 `parts {Key: Value}`（DeviceName / LibraryTypeName / LibraryVersionNumber / UpToDate / PathToInstance / InstanceName / CurrentVersionNumber），非键值部件才进 `messageParts` |
| 两个 TIA 进程同开时，`IsProjectNull()` 自愈经 `ConnectPortal()` 重挑进程，引擎在两次调用之间改绑到了另一个工程 | 记住显式绑定的工程名（`AttachToOpenProject` / `OpenProject` / `CreateProject` 设，`Connect` / `Disconnect` / `CloseProject` 清）：自愈只回绑该名字（3 s 内找不到就报 "Project is null: the explicitly bound project 'X' is not open…"，绝不改绑别的工程）；每次写操作（`AcquireHmiEditAccess`）与事务开始前核对 `_project.Name` 未变，变了就拒绝并要求重新附加；`GetState` 发现不一致时记警告 |

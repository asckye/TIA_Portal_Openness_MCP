配置器 **2.7.61**（引擎同版本重建，工具 453、lite 59 不变）。维护者的要求（附了千问工作助理那边的记录）：配置文件的写入要能给不同的电脑用，要能检测 AI 客户端安装的位置再写入——其他客户端也一样。

## 本机客户端检测（全部 12 张卡片）

`ClientProfiles.Detect`：每张卡片按顺序找证据，找到即记下（都是只读检查，不需要客户端在运行）：

1. 它要写的配置文件是否存在，否则其目录是否存在（`~/.claude.json`、`~/.codex/`、`~/.gemini/`、`~/.qwen/`、`~/.kimi-code/`、`~/.codebuddy/`、`~/.config/opencode/`、`~/.qwen-agent/`、`~/.cursor/`、`%APPDATA%\Code\User`）；
2. 可执行文件是否在 PATH 上（`claude` / `codex` / `gemini` / `qwen` / `kimi` / `codebuddy` / `opencode` / `cursor` / `code` / `code-insiders`，扩展名 `.exe` / `.cmd` / `.bat` / `.com`——npm 装的 CLI 是 `.cmd`）；
3. 已知安装目录（`%LOCALAPPDATA%\Programs\claude` / `AnthropicClaude`、`Programs\cursor`、`Programs\Microsoft VS Code` 与 `Program Files\Microsoft VS Code`、`Programs\qwen-agent`、`Programs\Codex`）；
4. 控制面板卸载项 `DisplayName`（HKCU / HKLM / WOW6432Node，关键字 Claude / Cursor / Visual Studio Code / 千问工作助理 / Qwen Agent / Codex）。

界面：卡片副标题 `CLI · 已检测` / `IDE · 未检测到`，悬停显示"已检测到：配置文件 C:\Users\<你>\.claude.json"之类的证据和将写入的文件；启动日志列出 12 张的结果（✓ / –）；默认选中第一张检测到的卡片。未检测到的卡片仍可写入。

## 写入位置按当前用户解析

`%USERPROFILE%` / `%APPDATA%`、`CODEX_HOME` / `KIMI_CODE_HOME`；VS Code 本机只有 Insiders 时写 `Code - Insiders\User\mcp.json`。同一个 `TiaMcpConfigurator.exe` 拷到任何电脑，写的都是那台电脑当前用户的文件。

## 新卡片：千问工作助理

| 项 | 值 |
|---|---|
| 写入 | `%USERPROFILE%\.qwen-agent\mcp.json`（全局）；只对一个项目生效时自己把同名文件放到 `<项目>\.qwen-agent\mcp.json` |
| 远程条目 | `mcpServers.tia-portal-vm = { url: "http://<虚拟机>:8765/mcp", headers: { Authorization: "Bearer <密钥>" } }`——静态令牌直接写进 headers，不走 OAuth，无 `type` |
| 本机条目 | `mcpServers.tia-portal = { command, args }` |
| 提示 | 必须完全退出千问工作助理进程（不是关窗口）再打开才会重新读取；它在内存里留着的 OAuth 同名条目会让重载时报“已注册，跳过” |

密钥以明文落在该文件里（与其它客户端的配置文件一样）；只在本机单用户、服务只监听内网时这样用。

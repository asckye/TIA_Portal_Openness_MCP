## 配置器：菜单栏里的更新

维护者：“Update-Engine.ps1 不能做成 UI 吗？”“更新做成到菜单栏里。”窗口顶部新增菜单栏，页面本身不变：

- **更新**：第一行“引擎 2.8.0（包名）”（读旁边的 `manifest\delivery.json`），第二行检查结果；“检查更新”“更新引擎…”“打开 GitHub Releases”。启动时在后台联网比对一次（GitHub API，限流时读发布页的跳转 tag），有新版本时菜单标题变成“更新 · 有新版本 X”并启用“更新引擎…”。
- **更新引擎…** 的顺序：本窗口启动的 MCP 还在跑 → 提示先“停止”；机器上有 `TiaMcpServer.exe` → 列出 pid 并拒绝（绝不代杀，可能是某个 AI 客户端启动的）；找不到更新器或目录里有 `.git`（源码仓库）→ 拒绝；确认后关闭本程序，在新的 PowerShell 窗口（`-NoExit`，日志留在窗口里）运行 `scripts\operations\Update-Engine.ps1 -InstallRoot <目录> -WaitForPid <本程序 pid> -RelaunchConfigurator`，完成、无事可做或失败后都重新打开配置器。
- **帮助**：所选客户端的使用说明（原来点 B 栏右上角文字也能看）、打开项目主页、关于（配置器版本、引擎版本、目录）。

实现：`tools/mcp-configurator/UpdateCheck.cs`（`Compare` / `Parse` / `TagFromLocation` / `ParseRelease` / `Latest` / `RunningEngines` / `LaunchArguments`，纯逻辑可离线测）；`Configurator.cs` 的 `ShowInstalledVersion` / `CheckUpdate` / `RunUpdate`；`MainWindow.xaml` 的 `Menu`。配置器测试 111 项（新增 13 项：版本比较、发布页 tag、release JSON、安装版本读取、`.git` 判定、启动参数、菜单项与布局）。

## 更新器：robocopy 与长路径

在宿主机上用交付包副本真跑“更新引擎”时发现：Windows PowerShell 的 `Expand-Archive` 在 `<安装目录>\.update\extract\<包名>\tools\...\ClassicHmiTemporaryImportPreflightSuite.cs`（269 字符）上失败，修掉解压后 `Copy-Item` 又在备份 `.previous\<包名>\...`（263 字符）上失败。交付包最深文件在包根下 109 字符；虚拟机现在的安装目录（嵌套的 `TIA_MCP_Delivery_v2.7.62_20260921\TIA_MCP_Delivery_v2.7.62_20260921`）加备份前缀正好 250，离失败只差几个字符。

- 解压到 `%TEMP%\tia-mcp-update-<pid>`（短），只对这一步检查长度（> 250 就明确失败并提示把 TEMP 指到短目录）；安装目录很深时只提示。
- 备份、丢弃旧备份、替换 `runtime\` / `manifest\`、覆盖其余文件、回滚、清理全部走 robocopy（`CopyTree` / `RemoveTree`，退出码 ≥ 8 才算失败），不受 260 字符限制。
- 新参数 `-WaitForPid`（等发起更新的配置器退出，最多 30 s）、`-RelaunchConfigurator`（结束时重开 `TiaMcpConfigurator.exe`）；脚本级 `trap`：任何意外错误也打印 `FAIL:` 并重开配置器。
- 宿主机验证：交付包副本（安装目录 108 字符）从 2.7.61 → 2.7.62 更新成功（备份里 267 字符的文件用 `\\?\` 确认存在）、`-Rollback` 回到 2.7.61、临时目录清理干净。

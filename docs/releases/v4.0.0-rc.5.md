# v4.0.0-rc.5 — fifth 4.0 release candidate

## 中文

这是自动化工程工作台（适用于 TIA Portal）4.0 的第五个发布候选，发布日期 2026-11-25。它在 GitHub 上标为预发布，不是最新版。GitHub 的最新版仍是 3.3，3.3 的更新器不会提示这一版，请手动下载。rc.1 到 rc.4 安装中的更新器能识别本版。
[GitHub 发布页](https://github.com/asckye/automation-engineering-workbench/releases)

本版修复 rc.4 真机复验发现的问题，并更正部分失败结果的判定：有证据的报确定结果，没有证据的报结果未知。**本版的代码改动尚未在任何真实 TIA Portal 上运行。** 除非写明版本，下列变化适用于全部八个支持的 TIA Portal 版本：V14 SP1、V15.1 和 V16–V21。工作台界面与 rc.4 相同。

各版本的工具数与 rc.4 相同：V14 SP1 287、V15.1 328、V16 354、V17 377、V18 402、V19 478、V20 499、V21 518。工具名称、参数名和参数类型没有变化。

### 必须了解的变化

- **有些以前报确定失败的调用现在报结果未知。** 写入已发给 TIA、但没有证据说明它的效果时，结果是 `OUTCOME_UNKNOWN`。重试前请先检查工程和 `GetSessionState` 的 `unsettled`。
- **有些以前报结果未知的调用现在报确定失败。** 重新读取证明目标没有变化时，TIA 的拒绝报为失败，并附上西门子的原因。
- **验证导入的判定改了。** `ImportPlcBlockVerified` 的完整读回不一致时，会再按普通导出方式导出一次，与你传入的文档比较，然后才报不一致。
- **`ManageMultiuserSession` 的 `port` 说明改了（V17–V21）。** 使用 `connectServer` 时要给出服务器配置的 TCP 端口。说明不再写 0 是默认值，校验本来就拒绝 0。

### 自 rc.4 以来的变化

#### 验证导入与离线文档工具

- 以导出文件原样导入时，普通导出与完整读回的写法差异不再造成误报，包括带有实例起始值的 UDT 成员和 SCL 块。导入恢复的设置和文档中写明的成员属性仍与完整读回核对，时间戳和内存大小允许变化。
- TIA 重新导出时添加的空标题和空注释不再算作差异。有内容的文字和接口变化仍算不一致。
- 离线文档工具（例如 `PatchPlcBlockDocument`、`ComparePlcBlockDocuments`）在写文件之前发现参数或文件错误时报确定拒绝，不再报结果未知。文件可能已经写出时，结果指出要检查的文件。
- `PatchPlcBlockDocument` 接受嵌套 UDT 成员的完整路径，拒绝两种写法指向不同成员的路径。`GetPlcBlockEditCapabilities` 标明哪些成员的起始值可以修改。
- `GetPlcBlockEditCapabilities` 等工具对不存在或不可读的输入文件报输入错误，不再报原生失败。
- 整数超出范围的错误写出字段名和允许范围，例如 `ListPlcBlocks` 的 1..100。

#### 编译与安全程序

- V17–V21：安全程序离线登录失败，且 TIA 确认会话已注销时，`CompilePlcSoftware` 和 `CompilePlcDiagnostics` 报访问被拒绝，不再报结果未知。登录失败后不编译。登录后的检查拒绝而注销又失败时，结果未知。
- 读不到单条诊断时，软件和单元的编译结果保留 TIA 的状态和计数，并说明诊断不完整。块和组范围的编译在这种情况下仍报结果未知。

#### 有证据的拒绝改报失败

- `CreatePlcTag`、`CreatePlcUserConstant`、`CreatePlcTagTable`、单个变量表导入和 `CreatePlcInstanceDb`：TIA 拒绝，且重新读取证明没有创建时，报失败并附上 TIA 的原因。
- `CreateHardwareDevice`、`CreateDevice`、`SetDeviceItemAttribute`、`SetCpuCommonSettings`、`SetDeviceItemIoAddress` 和 `CreateVersionControlWorkspace`：重新读取证明目标没有变化时，报失败。用户中止和连接丢失仍报结果未知。
- `DownloadPlc` 区分三种情况：传输没有发出、此前已改过路由、传输已发出。
- 批处理中第一个源文件已过期时，报告没有开始执行。
- `ExportDeviceAml`：CAx 返回 `false` 时报 `NATIVE_OPERATION_FAILED`，不再留下未决调用。结果指出 TIA 的日志和可能残留的部分文件。
- `ConnectProjectToWorkspace`（V16–V21）：重新查找没有映射，且工作区文件没有变化时，被拒绝的导出报确定失败。部分成功时给出已映射和失败的数量，以及每个失败对象的原因。
- `ImportAlarmClasses`、`ImportAlarmTextLists` 和 `ImportOpcUaInterface`：许可证、产品、安全和多用户方面的 TIA 拒绝仍报确定失败。

#### 没有证据的失败改报结果未知

- 批处理在已派发的子调用之后失败（例如完成审批时出错）时报结果未知，并保留已完成的项目。
- `ImportAlarmClasses`、`ImportAlarmTextLists` 和 `ImportOpcUaInterface` 发出导入后遇到未能识别的异常（例如文件格式错误）时报结果未知。新建的 OPC UA 接口能确认已删除时仍报确定失败。
- `GenerateBlocksFromExternalSource` 的生成调用被中止或连接丢失时报结果未知。
- `DeletePlcTagTable` 删除后读不到原来的组或表时报结果未知。
- `SeedProjectFromReference` 只把 TIA 返回的对象名算作已导入，遇到未确认的文件即停止后续导入。
- `ManagePlcSafety`、`ManagePlcSoftwareUnit`、`ManageDeviceUserGroup`、`ManageTransferArea`、`ManageUnifiedDynamization`、`ManageSyslogServers` 和 `SetDeviceAddress`：其他写入没有证明已恢复时，不再因为部分值恢复就报没有变化。
- `SetPlcCpuSettings` 不把读回值与请求值不同的属性算作已应用，结果给出请求值和实际值。
- `ImportDeviceAml`：TIA 没有给出传输状态时，报结果未知。

#### 工具示例

- 示例覆盖所有注册工具的参数，给出各版本的 CPU 和面板目录值，并写明文件、已有连接和工作区目录等前置条件。

- V16 的 `CreateDevice` 示例改为 `6ES7 513-1AL02-0AB0` V2.8。原来的 `6ES7 515-2AM02-0AB0` V2.9 被 TIA 拒绝。
- `ManagePlcExternalSources` 的参数说明删去 `list` 调用不接受的 `name` 和 `filePath` 示例。

完整变化见[更新日志](../../CHANGELOG.md)。

### 已知限制

- **本版的改动尚未在真机上运行。** 结果判定的改动来自读代码和离线测试，其中多数情况没有在真机上出现过。
- **结果判定尚未统一。** 各工具共用的宿主默认判定规则没有改，对应的改动已撤回，留待 4.0 之前。普通情况仍可能报结果未知，也可能在没有证据时报确定失败。
- **`ConnectOnlinePlc` 和 `DisconnectOnlinePlc` 的结果判定与 rc.4 相同。**
- **没有连接过真实 PLC。** 在线、下载、强制和仿真执行都未经真机验证。
- **一些失败的写入仍报结果未知。** 包括删除块、类型和变量表，从源生成块（TIA 明确说明的生成失败除外），以及 `ManagePlcGitRepository` 的暂存和提交。名称或版本没有变化，不足以证明没有副作用。
- **导入遇到未能识别的异常时报结果未知。** 例如报警类、报警文本列表和 OPC UA 接口的文件格式错误。
- **验证导入可能误判为一致。** 没有展开的 UDT 成员，如果其中嵌套的 UDT 在读回中保留旧的非默认值，可能被判为一致。rc.4 也有此问题。
- **验证导入和符号清单有未覆盖的情况。** UDT 展开内部的成员属性和注释不参与比较，新文档省略的块属性和成员设置从原块恢复。UDT 数组的展开不做归一化，未展开 UDT 实例的标志没有恢复。符号清单尚未覆盖包含 `IEC_TIMER` 等系统类型的 UDT。
- **同一 DB 有两个相同 UDT 的实例时，`ComparePlcBlockDocuments` 会拒绝比较。** 在 V18–V21 上比较导入前后的文档时出现。
- **工作区导出的判定有限制。** 快照遇到重解析点、超过 10,000 项或无法读取时报结果未知，快照之后的延迟写入和时间戳精度内的等长改写可能看不到。旧的 XML 导出路径同样适用这些规则。全部导出被拒绝、但已有映射存在时，结果的详细计数仍是 0/0。
- **VCI 原生导出和状态仍有问题。** V16、V17 的原生导出可能失败并报“file is deleted”。V19 的 `GetVersionControlStatus` 把对象全部报为未知，`changedOnly=false` 的同步对相同对象会失败。
- **`CreateDevice` 拒绝创建 TP700 面板且不说明原因（V18–V20）。** 在 V18 和 V19 上，`CreateHardwareCatalogDevice` 的关键字方式可用。
- **`ExportDeviceAml` 不能导出部分 HMI 设备。** V19–V21 上 TIA 报 TypeIdentifier 错误并留下部分文件，V16 和 V18 上 TIA 的导出返回失败。V17 导入 HMI AML 报“wrong type”，原因尚未查明。
- **V17、V19、V20 上固件 V2.9 CPU 的证书模板不可用。** 这是 TIA 的已知限制。
- **OPC UA 的 ReferenceNamespace 不能新建。** `ImportOpcUaInterface` 选择 `ReferenceNamespace` 新建时总是被拒绝，因为 SDK 的创建方法与本工具的调用方式不同。
- **多数示例没有在真机上运行过。** rc.4 复验的 104 处真机标记只涉及 V18–V21。
- **按最终设计改版的工作台尚未在真机上逐页手动检查。** 它只经过自动化界面测试和离线截图检查。
- **窄窗口中的调用详情仍是抽屉。** 窗口较窄时，调用详情以 520 像素宽的模态抽屉打开；设计稿中是页面内的面板。
- **仍未解决的 LOW 问题。** `GetHardwareFeatures` 把一些功能列为提供，读取时却报不存在；`ProbeHardwareHmiConnectionWhitelistedServices` 报接口候选不可用；`GetSoftwareTree` 把 PID 的系统 UDT 列在用户类型下；`GenerateBlocksFromExternalSource` 的 `generatedObjects` 可能为空（V14 SP1）；`FindTools` 首页很大时分页完整性自相矛盾（V15.1）。
- **V14 SP1、V15.1 和 V16 不能带安全程序密码编译。** 这三个版本的 Openness 没有对应接口，带密码的编译在审批前返回 `UNSUPPORTED_CAPABILITY`；请在 TIA 中编译安全程序。
- **局域网 HTTP 不认证且是明文。** MCP 连接不使用密码或访问密钥，能访问 HTTP 端点的设备都能调用工具。HTTP 默认关闭；只在可信局域网或虚拟机的仅主机网络中启用。
- **作为工具参数传入的密码会离开本机。** 密码由 AI 客户端组成，会到达模型服务商并留在客户端的对话记录中。本产品只在自己的审批卡、日志和审计中脱敏。不要在 AI 对话中输入重要密码，或在使用后更换。
- **更新包没有签名。** 更新器用同一发布中的 SHA-256 核对 ZIP，不能防御 GitHub 账户被控制。
- **更新不是整目录切换。** 更新器核对更新包后逐个替换文件；更新中断时，安装可能只替换了一部分。遇到这种情况，请从发布页下载完整包，解压到新文件夹。
- **关闭审批后，删除也不再确认。** 关闭普通写入审批后，只有向真实设备的在线写入和放弃更改的 `CloseProject` 仍须由人确认。
- **名称像凭据的值在审批卡上被遮蔽。** 审批卡按参数名脱敏，名称像凭据的用户数据（例如变量 `Door_Key`、`TokenCount`）的写入值也显示为圆点。
- **批处理、文档、交叉引用和目录工具不接受短 PLC 名。** 请传入完整的软件路径。
- **只读监视计划不接受变量表中的全局变量。** `PlanOnlineReadOnlyMonitoring` 拒绝这类变量并说明原因。
- **大的用法条目只有一个拆页。** `GetToolUsage` 只把 `BuildAndImportPlcArtifact` 的完整输入定义移到后续页面，其他大条目尚未按同样规则拆分。
- **工作台配置页的检测可能让界面短暂停顿。** 检测 AI 客户端和 TIA 安装仍在界面线程上进行。
- **V21 OPC UA 报警类型更新可能让 TIA 退出。** 在带界面的 TIA V21 上用 `ManageUnifiedOpcUaAlarmType` 修改 nodeId 时，TIA 进程退出，结果为 `OUTCOME_UNKNOWN`。原因尚未查明；请先保存工程，或在 TIA 中手动修改。
- **V21 交叉引用只在无界面 TIA 上验证过。** 带界面实例待复验。
- **V19–V21 仍拒绝新建 Unified 脚本模块。** 请在 TIA 中创建，再预览并执行 `SetUnifiedGlobalScript` 的 `action=update`。
- **V21 LAD 生成有限制。** 以触点开头的扇出分支被拒绝；梯级中的上升沿、下降沿触点返回 `edge-contact-unverified`。
- **V14 SP1–V19 的 worker 仍用 STA。** V20/V21 使用 MTA。

## English

This is the fifth release candidate of Automation Engineering Workbench for TIA Portal 4.0, released on 2026-11-25. It is marked
as a pre-release on GitHub, not as the latest release. The latest GitHub release is still 3.3, and the 3.3 updater does not
offer this version, so download it manually. The updater in an rc.1 through rc.4 installation recognizes this release.
[GitHub releases](https://github.com/asckye/automation-engineering-workbench/releases)

This candidate fixes problems found in the real-machine retest of rc.4 and corrects how some failed calls are reported: definite
when there is evidence, unknown when there is none. **The code changes in this candidate haven't run on any real TIA Portal.**
Unless a release is named, the changes below apply to all eight supported TIA Portal releases: V14 SP1, V15.1 and V16–V21. The
Workbench UI is the same as in rc.4.

Tool counts are the same as in rc.4: V14 SP1 287, V15.1 328, V16 354, V17 377, V18 402, V19 478, V20 499, V21 518. No tool name,
parameter name or parameter type changed.

### Changes you must know

- **Some calls that used to report a definite failure now report an unknown outcome.** When a write was sent to TIA and nothing
  proves its effect, the result is `OUTCOME_UNKNOWN`. Before you retry, check the project and `unsettled` in `GetSessionState`.
- **Some calls that used to report an unknown outcome now report a definite failure.** When a fresh read proves that the target is
  unchanged, a refusal from TIA is reported as failed, with the Siemens reason.
- **Verified import decides differently.** When the full readback of `ImportPlcBlockVerified` differs, the tool exports the block
  once more in the ordinary style and compares it with the document you passed before it reports a mismatch.
- **The `port` description of `ManageMultiuserSession` changed (V17–V21).** With `connectServer`, supply the TCP port configured
  for the server. The description no longer says that 0 is the default; validation already refused 0.

### Changes since rc.4

#### Verified import and offline document tools

- Importing an exported file unchanged no longer gives a mismatch because ordinary exports and the full readback are written
  differently. This includes UDT members with instance start values and SCL blocks. Settings restored by the import and member
  attributes stated in the document are still checked against the full readback. Timestamps and memory lengths may change.

### Known limitations

- **The changes in this candidate haven't run on a real machine.** The outcome changes come from reading the code and from offline
  tests. Most of these cases haven't been seen on a machine.
- **Outcome rules aren't uniform yet.** The default rules that the host shares across tools are unchanged; a change was withdrawn and
  is planned before 4.0. Ordinary cases may still be reported as unknown, or as definite without proof.
- **The outcomes of `ConnectOnlinePlc` and `DisconnectOnlinePlc` are the same as in rc.4.**
- **No real PLC has been connected.** Online, download, force and simulation runs are unverified on real hardware.
- **Some failed writes still report an unknown outcome.** These are deletions of blocks, types and tag tables, block generation from a
  source (except generation failures that TIA documents), and staging and committing with `ManagePlcGitRepository`. An unchanged name
  or revision doesn't prove that there were no side effects.
- **Imports report an unknown outcome for an unrecognized exception.** An example is a malformed file for alarm classes, alarm text
  lists or OPC UA interfaces.
- **Verified import can report a false match.** A UDT member that isn't expanded can verify as a match when a nested UDT keeps old
  non-default values in the readback. rc.4 has this problem too.
- **Verified import and the symbol manifest don't cover every case.** Member attributes and comments inside an expanded UDT aren't
  compared. Block attributes and member settings that the new document leaves out are restored from the existing block. The expansion
  of an array of UDTs isn't normalized, and flags on UDT instances that aren't expanded aren't restored. The symbol manifest doesn't
  yet cover UDTs that contain system types such as `IEC_TIMER`.
- **`ComparePlcBlockDocuments` refuses a DB with two instances of the same UDT.** This happened on V18–V21 when comparing the documents
  from before and after an import.
- **The workspace export check has limits.** The outcome is unknown when the snapshot meets a reparse point, exceeds 10,000 entries or
  can't be read. A write after the snapshot, or a same-length rewrite within the timestamp resolution, can go unseen. The older XML
  export path follows the same rules. When every export is refused but a mapping exists, the detail counts are still 0/0.
- **Native VCI export and status still have problems.** The native export on V16 and V17 can fail with "file is deleted". On V19,
  `GetVersionControlStatus` reports every object as unknown, and a synchronization with `changedOnly=false` fails for equal objects.
- **`CreateDevice` refuses a TP700 panel without a reason (V18–V20).** On V18 and V19, the keyword form of `CreateHardwareCatalogDevice` worked.
- **`ExportDeviceAml` can't export some HMI devices.** On V19–V21 TIA reports a TypeIdentifier error and leaves a partial file. On V16
  and V18 the TIA export returns a failure. On V17, importing HMI AML reports "wrong type"; the cause is open.
- **Certificate templates of a CPU with firmware V2.9 are unavailable on V17, V19 and V20.** This is a known TIA limit.
- **An OPC UA ReferenceNamespace can't be created.** Creating one with `ImportOpcUaInterface` is always refused, because the SDK create
  method differs from the call this tool makes.
- **Most examples haven't run on a machine.** The 104 marks from the rc.4 retest cover only V18–V21.
- **The final-design Workbench hasn't been walked through by hand on a real machine.** It is covered only by automated UI tests
  and offline screenshot checks.
- **Call details in a narrow window are still a drawer.** In a narrow window, call details open in a 520 px modal drawer; the
  design shows a panel inside the page.
- **Open LOW findings.** `GetHardwareFeatures` advertises some features that read back as not present;
  `ProbeHardwareHmiConnectionWhitelistedServices` reports its interface candidate as unavailable; `GetSoftwareTree` lists PID system
  UDTs under user types; `generatedObjects` of `GenerateBlocksFromExternalSource` can be empty (V14 SP1); the paging completeness of
  a large first `FindTools` page contradicts itself (V15.1).
- **V14 SP1, V15.1 and V16 can't compile with a safety program password.** Openness on these releases has no API for it, so a
  compile with a password returns `UNSUPPORTED_CAPABILITY` before approval. Compile the safety program in TIA.
- **LAN HTTP has no authentication and is plain text.** MCP connections don't use a password or an access key, so any device that
  reaches the HTTP endpoint can call tools. HTTP is off by default. Enable it only on a trusted LAN or a VM host-only network.
- **Passwords passed as tool arguments leave this computer.** The AI client composes them, so they reach the model provider and
  stay in the client's transcript. This product redacts them only in its own approval cards, logs and audit. Don't type important
  passwords into an AI conversation, or change them afterward.
- **Updates aren't signed.** The updater checks the ZIP against the SHA-256 from the same release, which doesn't protect against
  a compromised GitHub account.
- **Updates don't switch the whole folder.** After verifying the package, the updater replaces files one by one, so an interrupted
  update can leave the installation partly replaced. If that happens, download the full package and extract it to a new folder.
- **With approval off, deletions aren't confirmed either.** When you turn ordinary write approval off, only online writes to a real
  device and `CloseProject` with `discardChanges=true` still need a person.
- **Values with credential-like names are masked on approval cards.** Cards redact by parameter name, so the written value of user
  data with a credential-like name, such as a tag named `Door_Key` or `TokenCount`, also shows as dots.
- **Batch, document, cross-reference and directory tools don't accept a short PLC name.** Pass the full software path.
- **Read-only monitoring plans don't accept global tags from a tag table.** `PlanOnlineReadOnlyMonitoring` refuses them and explains why.
- **Only one large usage entry is split.** `GetToolUsage` moves the full input contract to later pages only for
  `BuildAndImportPlcArtifact`; other large entries aren't split the same way yet.
- **Detection on the Workbench configuration page can pause the window briefly.** AI client and TIA installation detection still
  run on the UI thread.
- **A V21 OPC UA alarm type update can end TIA.** Changing a nodeId with `ManageUnifiedOpcUaAlarmType` in a V21 TIA instance with

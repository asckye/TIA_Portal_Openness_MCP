# v2.7.41

引擎 **2.7.41.0**（V20/V21 均重建）。工具 **437** 不变，默认 lite 56 项不变。2.7.40 真机重跑（见 [v2.7.40](v2.7.40.md#验证)）发现：TIA Portal V21 在 G120C 上退出后，**MCP 引擎进程自己也跟着崩溃**（退出码 -532462766 / 0xE0434352，控制台只剩 "由于 Exception.ToString() 失败，因此无法打印异常字符串"），虚拟机上的服务虽把它拉起来，但连接、绑定与临时对象状态全部丢失。本版让引擎在 TIA 退出后活下来，并再挡一处 Startdrive 崩溃触发点。

## 变更

| 项 | 内容 |
|---|---|
| `App.config`（新） | `<legacyUnhandledExceptionPolicy enabled="1"/>`：Openness 在 TIA 退出后于后台线程抛出的异常（其 `ToString()` 自身会失败）不再终止 .NET Framework 进程；SDK 生成的程序集绑定重定向照常合并进同一个 `<runtime>`，`runtime/v20`、`runtime/v21` 的 `TiaMcpServer.exe.config` 随之带上这一行 |
| `Program.cs` | `AppDomain.UnhandledException` / `TaskScheduler.UnobservedTaskException` 记进诊断日志（`DescribeSafely`：先记类型名，`Message` 取不到就写 "Message unavailable"，绝不因为记录本身再抛） |
| `GetState` | 绑定的 TIA 进程不在时直接回 `isConnected=false`，`meta.hmiReadHealth.portalProcess.processAlive=false` 说明原因，不再抛 "disposed" |
| `ManageDriveTelegrams` | 驱动对象没有任何报文（未连到 IO 系统）时 check / insert / erase 一律以 InvalidState 拒绝：新建 G120C 上 `CanInsertAdditionalTelegram(2, 4)` 抛 "Invalid operation"，接着的 `CanInsertTelegram(700, SupplementaryTelegram)` 让 TIA 退出 |
| PLCSIM Advanced 桥（`PlcSimAdvancedChannel`） | 维护者报告 2.7.38 在 PLCSIM 连续读写 15–30 次后引擎崩溃 5 次（与并发无关）。此前每次调用都 `CreateInterface` → `UpdateTagList` → 读写 → `Dispose`；现在每个实例名只保留一个 `IInstance` 接口（`Acquire`，探测失效才重建）、变量表只装载一次（`EnsureTagList`；列表时与报 "not found" 时刷新，`ReadWithRefresh` / `WriteWithRefresh` 重试一次）、所有 API 调用在同一把锁上串行；`unregister` / `powerOff` / `memoryReset` 与任何异常后 `Forget` 释放接口；结果里 `interface` 字段回 `cachedInterface` / `openedAt` / `uses` / `tagListLoaded`。本机无 PLCSIM Advanced，未做真实验证 |

已知的 TIA Portal V21（G120C）退出触发点至此五处：读 `r2139` 的值；已有主报文时 `CanInsertMainTelegram`；新建驱动上读未接线 `p840[0]` 的值；未联网驱动上 `CanInsertTelegram`；（`CanInsertAdditionalTelegram` 只抛异常不退出）。交接页 §5 有完整清单。

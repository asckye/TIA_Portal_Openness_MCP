# v3.2.0 — Eight TIA releases, direct Openness Studio and unified tool examples

Released 2026-10-03. The complete delivery includes MCP runtimes for **V14 SP1, V15.1 and V16–V21**, the WPF configurator, and **TIA Openness Studio with eight native adapters**. Application release version: **3.2.0**. Original V14/V15 are not supported.

## Changes

- The configurator selects the exact installed release. Shared version identities, environment discovery and independent algorithms reduce duplication; typed adapters preserve real SDK differences. Original version branches were archived before deletion; `master` is the maintained branch.
- TIA Openness Studio is included as a direct Openness desktop client. Its English/Chinese Glass Layers views preserve the application commands and use a native bridge without an MCP dependency. VCI uses legacy APIs on V16–V19 and modern APIs on V20/V21; V14 SP1/V15.1 have no VCI implementation.
- Every registered tool has a parameterized call example through `GetToolUsage`, together with input origins, result interpretation and official references. The unified library includes 25 programming examples and 14 call sequences, 89 pinned official documents and 381 indexed code blocks/methods. The 1,322 release/tool combinations and 1,038 operation examples are checked against actual MCP schemas. Official API patterns and project-authored wrapper examples are identified separately.
- Foundation external-source workflows now import an ASCII SCL/AWL/DB/UDT file, generate PLC blocks/types, compile and read back results. V14 SP1 exposes inventory observations because its generation method returns void; V15.1+ maps native generated objects to their actual paths. Ordinary native generation errors retain diagnostics and a usable session so corrected source can be tried again.
- Foundation compilation no longer rejects every execution. It checks the selected PLC and observable project online states, and returns typed native counts and nested diagnostics. Devices without an exposed state provider are listed rather than asserted offline; Siemens' all-devices-offline prerequisite still applies.
- Flat UDT and global DB XML builders accept `outputReleaseKey` for all eight releases, selecting Interface v2/v3/v4/v5 and version-dependent object attributes. The shared dependency planner reuses the integrated MIT Eido implementation.
- All 30 MCP prompts register independently of optional unavailable assemblies. HMI screen import no longer automatically replays a failed write; directory batches retain the first failure. Startdrive parameter reads avoid the previous detailed parameter/bit traversal; the reported BICO crash remains unverified.
- The formal release pipeline now rebuilds and packages all eight MCP runtimes and Studio, verifies their source/runtime hashes, and independently checks the downloaded release asset. Embedded JSON examples are part of the validated source inventory.

## Validation and remaining work

The release process runs both full-engine test identities, eight typed worker/adapter builds, Studio client/WPF tests, foundation functional tests with the supplied eight SDKs, STDIO/HTTP checks, full/lite checks, diagnostics and local stability tests. It executes 74 in-memory call examples and validates 16 UDT/global DB interface fragments against their corresponding official XSDs. Final evidence is in [the full-engine build record](../../manifest/release-build.json), [multi-version build record](../../manifest/multi-version-build.json) and [example coverage](https://github.com/asckye/TIA_Portal_Openness_MCP/blob/master/manifest/tool-usage-coverage.json).

**New native TIA/project acceptance remains NOT RUN.** These checks do not establish successful import or compilation in a real project, or crash safety. This release does not deploy to a virtual machine or download to a PLC.

- Foundation catalogs remain smaller than the full engines. The [functional matrix](../reference/openness-coverage.md) tracks 29 reviewed families across eight releases; watch-table/technology-object imports, broader VCI exposure and additional families remain to be completed.
- Foundation source import currently accepts ASCII. Chinese/non-ASCII source encoding requires version-specific native validation.
- The other six shared PLC XML builders still emit V21 candidate XML. Interface-fragment XSD validation does not certify a complete document or CPU/type semantics.
- Native PLC cross-reference and Unified script-library `Name` crash issues remain subject to their documented limits. The reported p2051[0] BICO read crash has no confirmed native regression pass. Worker isolation cannot guarantee TIA survives a native API failure.

## Download and upgrade

New users can follow the [beginner guide (Chinese)](../getting-started/beginners.zh-CN.md), covering installation, local/VM connections, version selection, Studio, and the bundled SCL import/compile exercise. It includes copyable AI prompts and explains how to inspect actual results.

Download **TIA_MCP_Delivery_v3.2.0_20261003.zip** and its `.sha256` asset. GitHub's automatically generated source archives do not include the runtime binaries. Stop the MCP/Studio processes before replacing an installation, preserve your configuration and secret, and restart clients after updating. No running service is updated automatically.

Select `runtime/v<release-key>/TiaMcpServer.exe` or use `TiaMcpConfigurator.exe`; Studio is `runtime/studio/TiaOpenness.exe`. Install matching Siemens TIA Portal, Openness, licenses and .NET runtimes separately: full engines require .NET Framework 4.8, foundation hosts also require .NET 8/ASP.NET Core 8, and Studio requires .NET 10 Desktop Runtime. Python companion tools retain their separate setup.

The archive contains the reviewed source, tests, documentation, templates, licenses and manifest-verified application files. Siemens PublicAPI assemblies, private engineering projects, user design handoffs, credentials and build logs are excluded.

# v2.7.34

引擎 **2.7.34.0**（V20/V21 均重建）。工具 396 → **402**，默认 lite 清单 56 项不变。本版做两件事：修 2.7.33 真机暴露的事务缺陷，以及"官方 Openness API 全量对齐"计划 [路线图 §2.0](../development/roadmap.md) 阶段 4 子批次 ④-①：Step7 软件单元与 `PlcSoftware` 小服务（`SW.Units`、`PlcDocument*`、`PlcChecksumProvider`、`FingerprintProvider`、`PlcBlockWriteProtectionProvider`、`PlcSimulationSettingsProvider` / `VirtualPlcSettingsProvider`、`PlcTagProvider`、`ProcessImageProvider`、类型化的文档导入导出结果）。

## 2.7.33 真机问题的修复

| 问题 | 修法 |
|---|---|
| `RunToolsInTransaction` 内层调用不带 `dryRun` 时按内层工具默认 `dryRun=true` 跑成预览，事务却回报 `committed=true` | `BaseLeftoversLogic.ForceRealExecution` 无论键是否存在都写入 `dryRun=false`（大小写不敏感命中已有键）；离线测试改为断言 `{}` → `{"dryRun":false}` |

扩展：`ManagePlcSoftwareUnit` 新增 `unitKind=safety`（系统生成的 `PlcSafetyUnit`：只允许 read / update / 关系，create / delete 在参数门就拒绝）、`createFromMasterCopy`（`PlcUnitComposition.CreateFrom(MasterCopy[, MasterCopyMode])`）、`commentsJson`（按工程语言写 `Comment.Items[i].Text`）；`SetPlcUnitObjectAccess` 也能对安全单元里的块发布；`ReadDeviceItemChannels` 新增 `includeLinkedTags`（V21 `Channel.GetService<PlcTagProvider>().GetLinkedTags()` → 变量名 / 数据类型 / 逻辑地址 / 变量表；V20 回 null 并说明）；`UpdateDeviceAddress` 的 `processImageObName` 在 V21 改走 `Address.GetService<ProcessImageProvider>().AssignProcessImageToOrganizationBlock(OB)`（V20 仍是 `Address.AssignProcessImageToOrganizationBlock`），不再对 V21 报 NotSupported；`ImportFromDocuments` / `ImportBlocksFromDocuments` 的结果改为类型化 `DocumentImportResultForBlocks`，失败时把 `DocumentResultMessage.Message` 附进错误文案，`ImportedPlcBlocks` 名单记到 `LastImportedDocumentBlocks`。

只在 PublicAPI 上学到的事实：V21 的 `Project` 没有 `IsSimulationDuringBlockCompilationEnabled` / `IsVirtualPlcDuringBlockCompilationEnabled`（官方页面仍按 V20 写法举例），只剩两个服务提供者；`Channel` / `Address` 在 V20 不是 `IEngineeringServiceProvider`；`PlcUnitSystemGroup.Name` 与 `PlcDocumentComposition.CreateFrom` 仅 V21；`PlcDocument` 在 PublicAPI 里只有 `Name`（内容要导出后看）。

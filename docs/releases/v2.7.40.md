# v2.7.40

引擎 **2.7.40.0**（V20/V21 均重建）。工具 **437** 不变，默认 lite 56 项不变。本版是 2.7.39 真机重跑的收尾：Startdrive 在 G120C 上有三处调用会让 **TIA Portal V21 整个进程退出**，引擎加守卫、加"进程是否还在"的诊断，并修正两处 SiVArc 文案 / 回退。真机结果本身记在 [v2.7.39](v2.7.39.md#验证)。

## 2.7.39 真机暴露的问题与本版处理

| 真机现象（G120C，TIA V21，2026-09-20） | 2.7.40 处理 |
|---|---|
| 已有主报文时 `TelegramComposition.CanInsertTelegram(1, MainTelegram)` 回 false，紧接着 `CanInsertMainTelegram(1)` 抛 "Unexpected exception"，TIA Portal 退出 | `ManageDriveTelegrams` 在 `Find(MainTelegram) != null` 时不调用 `CanInsertMainTelegram` / `InsertMainTelegram`：`check` 回 `checks.mainTelegramPresent=true` + 说明，`insert` 以 InvalidState 拒绝（改用 `changeNumber` / `changeSize`；主报文只在 G220 上可增删） |
| 读 `r2139`（现有驱动）与新建驱动上未接线 BICO 汇点 `p840[0]` 的 `Value` 时 TIA Portal 退出（同一 `p840[0]` 在已接线的现有驱动上可读） | `ReadDriveParameters` / `ReadOnlineDriveParameters` 新增 `includeValue`（默认 true），行里 `Value` 最后读；`includeValue=false` 先拿元数据（号 / 索引 / 上下限 / 单位 / 文本 / 枚举 / 位），描述里点名这两个触发点 |
| `Find("r722.0")` 回 null：位参数只在父参数的 `Bits` 里（成员 `Name` 带点名） | `ReadDriveParameters` / `ReadOnlineDriveParameters` / `ManageStartdriveParameter`（含 BICO 源）对带点的名字走 `Find(base)` + `Bits` |
| TIA 退出后每个工具只看到 `EngineeringObjectDisposedException`（"TIA Portal has either been disposed or stopped running"），`AttachToOpenProject` 失败，无法区分"句柄陈旧"和"进程没了"；未保存工程里的临时设备随进程消失 | 引擎在每个绑定点记住 TIA 进程 id（`RememberBoundProcess`）；`Portal.GetPortalProcessHealth()` 用 `Process.GetProcessById` 判断进程是否还在：`GetState` 的 `hmiReadHealth.portalProcess`、连接失败保护记录的 `portalProcess` / `recovery` 与 `GetState` 失败文案都直接说"TIA Portal 进程 N 已不在：重启、重开工程、AttachToOpenProject" |
| `GenerateSiVArc` 传 `PlcSoftware.Name` 与所属设备名都报 "PLC device '…' not found"（HMI 没有到该 PLC 的连接；官方页要求 PLC 已连接到 HMI 设备） | 先按软件名、再按设备名调 `Sivarc.Generate`，`meta.attempts` 记两次结果；两次都 "not found" 时以 InvalidState 说明要检查 HMI 连接（`GetHmiConnections` / `EnsureUnifiedHmiConnection`） |
| `ScreenRule.ProgramBlock = null` 被 TIA 拒绝 "The argument 'ProgramBlock' may not be null" | `ManageSivarcTableRule` 描述改正（null 透传但 TIA 拒绝，改挂别的块） |

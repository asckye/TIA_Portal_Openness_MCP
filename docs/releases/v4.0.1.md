# v4.0.1 — Automation Engineering Workbench 4.0.1

## 中文

这是自动化工程工作台（适用于 TIA Portal）4.0 的第一个修复版，发布日期 2026-11-27，在 GitHub 上设为最新版（Latest）。本版适用于全部八个 TIA Portal 版本：V14 SP1、V15.1 和 V16–V21。工具名称、参数和结果格式与 4.0.0 相同，只有下列消息和建议的文字改变。

已安装 4.0.0 的用户可以在工作台中检查更新，也可以从 [GitHub 发布页](https://github.com/asckye/automation-engineering-workbench/releases)手动下载。3.3 的自动更新器仍不提供 4.x，从 3.3 升级见 [4.0.0 发布说明](v4.0.0.md#从-33-升级)。

### 修复

- **同步后的建议按比较结果给出（V16–V19）。** 只有带默认值和不带默认值的两次导出都完成、且都与工作区文件不同时，才建议备份并删除过期的工作区文件。导出被中断时报告中断它的错误；比较没有完成时建议重试比较，不再建议重新编译。同步后的最终比较中，如果两次导出都因普通拒绝或本地释放的导出代理而失败，观察到不一致的块仍建议重新编译。这是 4.0.0 已知限制中计划在 4.0.1 修复的第一项。
- **工作区路径无效时，`GetVersionControlStatus` 不再整体失败（V16–V21）。** 工作区根路径含 Windows 不允许的字符时，状态照常列出映射行和合计，汇总说明无法检查工作区中的 XML 文件，`unmappedFiles` 为 `null`。V20 和 V21 现在对无效的映射文件路径也这样处理，V16–V19 原来就是如此。这是 4.0.0 已知限制中计划在 4.0.1 修复的第二项。
- **验证导入的证据路径过长时提前拒绝（全部八个版本）。** 当某个证据文件的路径会达到 260 个字符时，`ImportPlcBlockVerified` 在导出和导入之前返回 `INVALID_ARGUMENT`，点名 `evidenceDirectory` 及其最大长度。以前导入会照常执行，随后报告一个误导的读回不一致。

### 验证

本版的修复经过离线测试和本机完整门禁（`merge-check -All`），GitHub CI 的离线检查也已通过。修复没有在虚拟机上重跑，也没有连接过真实 PLC。

### 已知限制

[4.0.0 的已知限制](v4.0.0.md#已知限制)仍然适用，上面修复的两项除外。另外，在高度不到 812 像素的屏幕上，工作台首次打开的窗口可能比可用区域高，可以手动调整窗口大小。

### 报告问题

请在 [GitHub Issues](https://github.com/asckye/automation-engineering-workbench/issues) 报告，写明 TIA Portal 版本、工具名称、请求编号和返回的错误码。

## English

This is the first patch release of Automation Engineering Workbench for TIA Portal 4.0, published on 2026-11-27 and marked Latest on GitHub. It applies to all eight supported TIA Portal releases: V14 SP1, V15.1 and V16–V21. Tool names, parameters and result shapes are the same as in 4.0.0; only the messages and advice listed below change.

If you have 4.0.0 installed, check for updates in the Workbench, or download the release manually from the [GitHub releases page](https://github.com/asckye/automation-engineering-workbench/releases). The 3.3 updater still does not offer 4.x; to upgrade from 3.3, see the [4.0.0 release notes](v4.0.0.md#upgrade-from-3x).

### Fixes

- **Advice after synchronization follows the comparison result (V16–V19).** Synchronization advises backing up and removing a stale workspace file only when the exports with and without defaults both complete and both differ from that file. An interrupted export reports the error that interrupted it, and an incomplete comparison advises retrying the comparison instead of recompiling. In the final comparison after synchronization, if both exports fail because of an ordinary refusal or a locally disposed export proxy, a block observed to be inconsistent still gets recompile advice. This is the first of the two 4.0.0 known limitations planned for 4.0.1.
- **`GetVersionControlStatus` no longer fails as a whole when a workspace path is invalid (V16–V21).** When the workspace root path contains a character that Windows does not allow, the status still lists the mapping rows and totals, the summary says the workspace XML files could not be checked, and `unmappedFiles` is `null`. V20 and V21 now handle an invalid mapping file path the same way, as V16–V19 already did. This is the second of the two 4.0.0 known limitations planned for 4.0.1.
- **Verified import refuses an evidence path that is too long before it starts (all eight releases).** When an evidence file path would reach 260 characters, `ImportPlcBlockVerified` returns `INVALID_ARGUMENT` before any export or import, naming `evidenceDirectory` and its maximum length. Before, the import ran and then reported a misleading readback mismatch.

### Verification

The fixes in this release are covered by offline tests and the full host gate (`merge-check -All`); the GitHub CI offline checks also pass. They were not rerun on the virtual machines, and no real PLC was connected.

### Known limitations

The [4.0.0 known limitations](v4.0.0.md#known-limitations) still apply, except the two fixed above. In addition, on a screen less than 812 pixels high, the Workbench window may open taller than the work area on first start; resize it by hand.

### Report problems

Report problems in [GitHub Issues](https://github.com/asckye/automation-engineering-workbench/issues) with the TIA Portal release, the tool name, the request ID and the returned error code.

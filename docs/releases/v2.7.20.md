# v2.7.20

引擎 **2.7.20.0**。工具数量与默认 lite 清单不变（359 / 56）。本版两件事：修 `DescribeBlockLogic` 的文本渲染器——它在真实工程导出上会**悄悄丢内容**，工具照样报 `success`，读到的却是残缺逻辑（缺陷由真实工程 V21 `AutomaticDipCoatingMachine` 连机测试发现）；配置器的 AI 客户端卡片重排，加入国产模型与 Grok。

## 配置器：客户端卡片重排，加入通义千问 / Kimi / 腾讯元宝 / DeepSeek / 智谱清言 / Grok

`TiaMcpConfigurator.exe` 的 AI 客户端页现按 **CLI 在前、Claude Code 与 Codex 居首、IDE 在后** 排列，共 11 张卡片；去掉 Windsurf、Cline 和 Claude Desktop · Chat（后者的 `mcp-remote` 桥接与 `tia-portal-vm-chat` 服务器名一并移除）。国产模型和 Grok 的聊天 App / 网页不支持 MCP，卡片按模型命名，实际写入各家官方 CLI 或 OpenCode（卡片小字标出），远程 HTTP 与本机 stdio 都支持：

| 卡片 | 实际写入 | 配置位置 | 远程条目 |
|---|---|---|---|
| 通义千问 | 阿里 Qwen Code | `%USERPROFILE%\.qwen\settings.json` | `httpUrl` + `headers`（同 Gemini CLI） |
| Kimi | 月之暗面 Kimi Code CLI | `%KIMI_CODE_HOME%\mcp.json`，默认 `%USERPROFILE%\.kimi-code\mcp.json` | `url` + `headers` |
| 腾讯元宝 | 腾讯 CodeBuddy Code CLI | `%USERPROFILE%\.codebuddy\.mcp.json` | `type: http` + `url` + `headers` |
| DeepSeek / 智谱清言 / Grok | OpenCode（provider 分别选 DeepSeek / 智谱 GLM / xAI） | `%USERPROFILE%\.config\opencode\opencode.json` 的 `mcp` 节 | `type: remote` + `url` + `headers` |

三张 OpenCode 卡片写同一个文件，多选时只写一次；OpenCode 本机模式写 `type: local` 且 `command` 为含可执行文件的单个数组，与其它客户端的 `command` + `args` 不同。豆包没有卡片：其 IDE（Trae）全局 MCP 文件位置未公开、远程只支持 SSE，本引擎只提供 Streamable HTTP。配置器隔离测试 58 → 80。**新客户端均未在真实客户端上联调**，路径与字段以其官方文档为准。

## 修复：`DescribeBlockLogic` 渲染丢失

| 场景 | 2.7.19 输出 | 2.7.20 输出 |
|---|---|---|
| SCL 无参系统调用 `#tick := TIME_TCK();` | `#tick := ;` | `#tick := TIME_TCK();` |
| SCL 位置参数表达式 `TIME_TO_DINT(#tick - #prev)` | `#tick.prev` | `TIME_TO_DINT(#tick - #prev)` |
| SCL 命名参数 + 命名常量 `LIMIT(MN := 0, MX := #MAX_MS)` | `LIMIT(MN := 0, MX := )` | `LIMIT(MN := 0, MX := #MAX_MS)` |
| SCL 多重实例调用 | `#statTimer(IN := "DB".run, …)` 无 FB 类型 | `#statTimer⟨TON⟩(IN := "DB".run, PT := T#1S)` |
| SCL 数组下标 / 绝对地址 | `#arr := ` | `#arr[#i] := %I1.3` |
| LAD 网络含 FB/FC 调用框 | 退化成孤立触点清单，看不到调用、参数与 EN 条件 | `当 [NOT("Start")] 时: CALL "FB_Motor"["FB_Motor_DB"](start=⟨"Auto"⟩, sp=#setpoint, done="Q1")` |
| LAD 块 Bool 输出驱动线圈 | 线圈上游 `?` | `"BusyLamp" ( ) ⇐ NOT("Start") · CALL "FB_Motor"["FB_Motor_DB"].busy` |
| LAD MOVE/定时器框的 EN 触点链 | 丢失（只查 `in` 引脚） | 按 `in → IN → en` 回溯 |

根因：

- `RenderStructuredText` 只遍历 `<StructuredText>` 的一层子节点；`<Access>` 分支把所有后代 `<Component>` 用 `.` 拼接、只认 `<ConstantValue>`。`Scope="Call"` 的 `<CallInfo>`/`<Parameter>` 子树、`LocalConstant`/`GlobalConstant` 的 `<Constant Name>`、`<Address>` 全部落空。现改为递归渲染，未知包装节点一律下钻。
- FlgNet 里块调用是 `<Call UId><CallInfo Name BlockType><Instance/><Parameter Name Section/>`，不是 `<Part>`；原实现只收集 `<Part>`。现将 `<Call>` 收集为调用框，按 `Parameter Section` 判断引脚方向（用户命名的 Bool 输入引脚也能回溯触点链），并新增 `Not` 元件。

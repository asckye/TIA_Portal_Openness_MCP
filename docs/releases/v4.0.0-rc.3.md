# v4.0.0-rc.3 — third 4.0 release candidate

## 中文

这是自动化工程工作台（适用于 TIA Portal）4.0 的第三个发布候选，发布日期 2026-11-23。它在 GitHub 上标为预发布，不是最新版。GitHub 的最新版仍是 3.3，3.3 的更新器不会提示这一版，请手动下载。rc.1 和 rc.2 安装中的更新器能识别本版。
[GitHub 发布页](https://github.com/asckye/automation-engineering-workbench/releases)

除非写明版本，下列变化适用于全部八个支持的 TIA Portal 版本：V14 SP1、V15.1 和 V16–V21。2026-11-23 在 V14 SP1 和 V15.1 真机上复验 rc.2 时发现两个 HIGH 缺陷：带 UDT 成员的 DB 经验证导入并编译成功后仍报读回不一致；在 V14 SP1、V15.1 和 V16 上携带密码的编译什么都没执行，却报 `OUTCOME_UNKNOWN`。本版修复了这两个缺陷，并包含复验中发现的较小问题的修复和工作台界面修复。本版的修复尚未在真机上复验。

各版本的工具数与 rc.2 相同：V14 SP1 287、V15.1 328、V16 354、V17 377、V18 402、V19 478、V20 499、V21 518。

### 必须了解的变化

- **删除工艺对象须确认并指明工程。** 预览后执行 `ManageTechnologyObject` 的删除时，须传入 `action="delete"`、`dryRun=false`、`confirm=true`，并在 `expectedProjectFile` 中给出已绑定工程的确切文件。rc.2 只要 `dryRun=false` 就会删除。其他动作不变。
- **V14 SP1、V15.1 和 V16 上带密码的编译在审批前拒绝。** 这三个版本的 Openness 没有带安全程序密码编译的接口。`CompilePlcSoftware` 和 `CompilePlcDiagnostics` 携带密码时，预览和执行都在审批和派发给 worker 之前返回 `UNSUPPORTED_CAPABILITY`，不出现审批卡，请求也不留在未确认清单中。V17–V21 不变：开启写入审批时，带密码的编译须审批。

### 更正 rc.2 发布说明

rc.2 的说明写的是导出到输出根目录之外会被拒绝，这是错的。实际规则是：输出父目录不存在时，在派发前拒绝；目标在输出根目录之外时，开启写入审批需要先批准，关闭写入审批则直接执行。`CHANGELOG.md` 和 rc.2 说明中的这段文字已更正，代码没有改变。

### 自 rc.2 以来的修复

#### 写入结果

- **带 UDT 成员的 DB 的验证导入。** `ImportPlcBlockVerified` 把编译后展开的 UDT 成员按成员名、数据类型、顺序和起始值与 UDT 声明逐项比较，不再因导出带出的属性差异而把未改动的 DB 报成读回不一致。Struct 内的 UDT 成员同样处理。名称、类型、顺序、数量或起始值不同仍报不一致。
- **读回不一致的原因。** 读回仍不一致时，结果证据中的 `readbackDifference` 写明成员路径和不同的方面，例如 `Static/Motor/Speed: type`，不包含 XML 内容。
- **符号清单。** 离线符号清单接受编译后导出中展开的 UDT 成员，并保留对 UDT 的引用，不再报 `unsupported-nested-member-shape`。
- **带密码的编译结果确定。** 见上文。以前在这三个版本上会报 `OUTCOME_UNKNOWN`，并把请求留在未确认清单中，实际并没有开始编译。

#### 工具说明与错误消息

- **工具说明只提到本版注册的工具。** 工具和参数说明不再点名所选版本没有注册的工具，例如低版本上的 `BuildProjectScaffold` 不再指向 `SearchHardwareCatalog`，在没有 `ConnectOnlinePlc` 的版本上，在线和仿真工具的说明不再指向它。
- **缺少目录时写明参数。** 目录输入的工具在目录不存在时指出对应参数并说明目录不存在，不再报“输入文件读不到”。
- **超出范围的参数写明名称和允许范围。** 例如 `ComparePlcBlockDocuments` 的 `contextLines` 或 `limit` 越界时，错误写明参数名和允许范围。未知参数排在一个无效的已声明参数之前时，错误指出那个已声明参数。
- **未知参数的提示列出可用的参数名。** 错误中列出本工具声明的参数名，便于改正调用；不回显调用方传入的未知键名。
- 完整变化见[更新日志](../../CHANGELOG.md)。

#### 工作台

- **阅读区居中。** 各页面的内容栏在任何窗口宽度下都居中显示，导航栏、侧栏和滚动条改变宽度时也一样。调用、审计和日志等数据表仍占满宽度。
- **环境检查页与设计一致。** 通过的行只显示“通过”标签，不再带按钮；失败的行写明具体原因，只在确实能执行修复时显示按钮。八个版本的 worker 文件合为一行，全部通过才显示通过，失败时写明哪个版本的哪个文件有问题。首次连接帮助仍在本页，但不再计入需要处理的数量。导出诊断包移到日志页，诊断包中仍保留首次连接和逐版本的检查结果。
- **只有一个环境检查。** 高级连接选项中的“环境检查”打开环境检查页并在那里运行同样的检查，不再另行运行、只写日志。
- **窗口最大化。** 最大化的窗口不再超出屏幕边缘，标题栏按钮和状态栏保持可见；最大化时该按钮显示为“还原”。
- **状态栏。** 没有参与者文字时，不再显示孤立的分隔点。
- **不再显示占位和内部文字。** 版本控制页说明本会话中能读取什么、支持哪些版本，以及更改须通过 MCP 版本控制工具进行，不再显示内部任务编号。审计页在首次核验审计链之前说明如何核验，不再显示“尚未接入”。项目菜单中原名“审查”的项按实际作用改名，它打开的是规则。
- **访问键在每页唯一。** 日志页的复制、清空和导出诊断包使用不同的访问键；每页上可见控件的访问键不重复，无障碍名称与可见文字一致。
- **保存空的在线目标列表前确认。** 删除最后一个在线目标并保存时，设置页先说明空列表的含义，并提供两个选择：保留空列表，拒绝全部在线目标；或移除列表，恢复为未配置，不再限制目标地址。

### rc.2 真机复验结果

2026-11-23，rc.2（`bb154034d`）在 V14 SP1 和 V15.1 上做了定向复验，各一批。计数按调用。

| 版本 | 调用 | 通过 | 只有按设计拒绝 | HIGH | MEDIUM | LOW | 未运行 |
|---|---:|---:|---:|---:|---:|---:|---:|
| V14 SP1 | 143 | 90 | 40 | 3 | 0 | 10 | 0 |
| V15.1 | 150 | 96 | 38 | 2 | 0 | 12 | 2 |

- 两个版本都只剩同样的两个 HIGH 缺陷（V14 SP1 的 3 次 HIGH 调用对应 2 个缺陷），本版已修复：带 UDT 成员的 DB 的验证导入报读回不一致（不带 UDT 成员的 DB 通过），带密码的编译报 `OUTCOME_UNKNOWN`。
- rc.1 的其他 HIGH 缺陷确认已修好：`ExportDeviceAml` 给出确定结果；V15.1 上 `ManageHardwareUtilities` 的 `exportOpcUa` 和 `ImportHmiScreensFromDirectory` 给出确定结果。rc.1 的 LOW 问题修好 30 项以上。
- rc.2 的行为检查通过：UNC 和设备路径输入被拒绝，覆盖导入先备份，目录导入给出批次汇总，`ManageCfcChartProtection` 未注册，绑定工程前的调用被拒绝。
- 两个版本的测试中 TIA 重启和会话中断都是 0 次。V14 SP1 上编译用时 7.5–9.0 秒。在线、下载和仿真没有运行，因为 VM 中没有 PLC。
- 复验中发现的较小问题大部分已在本版修复；仍未解决的见下文。

### 已知限制

- **本版的两个 HIGH 修复尚未在真机上运行。** 带 UDT 成员的验证导入修复，是用按真机证据的语义比较重建的测试数据验证的，原始导出文件未能从 VM 上取回。
- **验证导入和符号清单有未覆盖的情况。** UDT 数组成员的展开不在读回比较范围内，因为没有能确定其布局的编译后导出样本；符号清单尚未覆盖包含 `IEC_TIMER` 等系统类型的 UDT。
- **V16–V21 没有复验 rc.1、rc.2 或本版。** V16、V18、V19、V20 最近一次复验在 2026-11-19 至 11-20 的 RC 候选上；V17 和 V21 最近一次复验分别在 RC2 候选（`9a4274f2`）和 RC3 候选（`aa9c749b`）上。
- **没有连接过真实 PLC。** 在线、下载、强制和仿真执行都未经真机验证。
- **工作台尚未在真机上逐页手动检查。** 本版的界面修复只经过自动化界面测试。
- **仍未解决的 LOW 问题。** `GetHardwareFeatures` 把一些功能列为提供，读取时却报不存在；`ProbeHardwareHmiConnectionWhitelistedServices` 报接口候选不可用；`GetSoftwareTree` 把 PID 的系统 UDT 列在用户类型下。
- **V14 SP1、V15.1 和 V16 不能带安全程序密码编译。** 见上文；请在 TIA 中编译安全程序。
- **局域网 HTTP 不认证且是明文。** MCP 连接不使用密码或访问密钥，能访问 HTTP 端点的设备都能调用工具。HTTP 默认关闭；只在可信局域网或虚拟机的仅主机网络中启用。
- **作为工具参数传入的密码会离开本机。** 密码由 AI 客户端组成，会到达模型服务商并留在客户端的对话记录中。本产品只在自己的审批卡、日志和审计中脱敏。不要在 AI 对话中输入重要密码，或在使用后更换。
- **更新包没有签名。** 更新器用同一发布中的 SHA-256 核对 ZIP，不能防御 GitHub 账户被控制。
- **更新不是整目录切换。** 更新器核对更新包后逐个替换文件；更新中断时，安装可能只替换了一部分。遇到这种情况，请从发布页下载完整包，解压到新文件夹。
- **关闭审批后，删除也不再确认。** 关闭普通写入审批后，只有向真实设备的在线写入和放弃更改的 `CloseProject` 仍须由人确认。
- **名称像凭据的值在审批卡上被遮蔽。** 审批卡按参数名脱敏，名称像凭据的用户数据（例如变量 `Door_Key`、`TokenCount`）的写入值也显示为圆点。
- **批处理、文档、交叉引用和目录工具不接受短 PLC 名。** 请传入完整的软件路径。
- **只读监视计划不接受变量表中的全局变量。** `PlanOnlineReadOnlyMonitoring` 拒绝这类变量并说明原因。
- **大的用法条目只有一个拆页。** `GetToolUsage` 只把 `BuildAndImportPlcArtifact` 的完整输入定义移到后续页面，其他大条目尚未按同样规则拆分。
- **工作台配置页的检测可能让界面短暂停顿。** 检测 AI 客户端和 TIA 安装仍在界面线程上进行。
- **V21 OPC UA 报警类型更新可能让 TIA 退出。** 在带界面的 TIA V21 上用 `ManageUnifiedOpcUaAlarmType` 修改 nodeId 时，TIA 进程退出，结果为 `OUTCOME_UNKNOWN`。原因尚未查明；请先保存工程，或在 TIA 中手动修改。
- **V21 交叉引用只在无界面 TIA 上验证过。** 带界面实例待复验。
- **V19–V21 仍拒绝新建 Unified 脚本模块。** 请在 TIA 中创建，再预览并执行 `SetUnifiedGlobalScript` 的 `action=update`。
- **V21 LAD 生成有限制。** 以触点开头的扇出分支被拒绝；梯级中的上升沿、下降沿触点返回 `edge-contact-unverified`。
- **V14 SP1–V19 的 worker 仍用 STA。** V20/V21 使用 MTA。

## English

This is the third release candidate of Automation Engineering Workbench for TIA Portal 4.0, released on 2026-11-23. It is marked
as a pre-release on GitHub, not as the latest release. The latest GitHub release is still 3.3, and the 3.3 updater does not
offer this version, so download it manually. The updater in an rc.1 or rc.2 installation recognizes this release.
[GitHub releases](https://github.com/asckye/automation-engineering-workbench/releases)

Unless a release is named, the changes below apply to all eight supported TIA Portal releases: V14 SP1, V15.1 and V16–V21.
The rc.2 retest on real V14 SP1 and V15.1 machines on 2026-11-23 found two HIGH defects. Verified import of a DB with a UDT member
reported a readback mismatch after a successful import and compile. A compile that carried a password on V14 SP1, V15.1 or V16
reported `OUTCOME_UNKNOWN` although nothing ran. This candidate fixes both, together with smaller problems found in the retest and
Workbench fixes. The fixes in this candidate haven't been retested on a real machine.

Tool counts are the same as in rc.2: V14 SP1 287, V15.1 328, V16 354, V17 377, V18 402, V19 478, V20 499, V21 518.

### Changes you must know

- **Deleting a technology object needs confirmation and the project file.** To apply a `ManageTechnologyObject` deletion after
  preview, pass `action="delete"`, `dryRun=false`, `confirm=true` and the exact bound project file in `expectedProjectFile`.
  In rc.2, `dryRun=false` alone deleted the object. Other actions are unchanged.
- **On V14 SP1, V15.1 and V16, a compile with a password is refused before approval.** Openness on these releases has no API to
  compile with a safety program password. When `CompilePlcSoftware` or `CompilePlcDiagnostics` carries a password, preview and
  apply both return `UNSUPPORTED_CAPABILITY` before approval and before the worker is called. No approval card appears, and the
  request isn't left unsettled. V17–V21 are unchanged: with write approval on, a compile with a password needs approval.

### Correction to the rc.2 notes

The rc.2 notes said that an export target outside the output root is refused. That was wrong. The actual rule: a missing output
parent folder is refused before dispatch; a target outside the output root needs approval when write approval is on, and runs
when it is off. The text in `CHANGELOG.md` and the rc.2 notes has been corrected; the code is unchanged.

### Fixes since rc.2

#### Write outcomes

- **Verified import of a DB with a UDT member.** `ImportPlcBlockVerified` compares the compiled expansion of a UDT member with the
  UDT declaration by member name, data type, order and start value, so attribute differences added by the export no longer make an
  unchanged DB report a readback mismatch. UDT members inside a Struct are handled the same way. A different name, type, order,
  member count or start value is still a mismatch.
- **Why a readback differs.** When the readback still differs, `readbackDifference` in the result evidence names the member path
  and the aspect that differs, for example `Static/Motor/Speed: type`, without XML content.
- **Symbol manifest.** The offline symbol manifest accepts the expanded UDT members of a compiled export and keeps the UDT
  reference, instead of reporting `unsupported-nested-member-shape`.
- **A definite result for a compile with a password.** See above. On these three releases it used to report `OUTCOME_UNKNOWN` and
  leave the request unsettled, although no compile had started.

#### Tool descriptions and error messages

- **Tool descriptions name only tools registered on the release.** Tool and parameter descriptions no longer name tools the
  selected release doesn't register. For example, `BuildProjectScaffold` on older releases no longer points to
  `SearchHardwareCatalog`, and on releases without `ConnectOnlinePlc` the online and simulation tool descriptions no longer point to it.
- **A missing directory names its parameter.** Tools that take a directory name the parameter and say that the directory doesn't
  exist, instead of reporting that the input file can't be read.
- **An out-of-range argument names the parameter and its range.** For example, `ComparePlcBlockDocuments` names `contextLines` or
  `limit` and the allowed range. When an unknown key comes before an invalid declared parameter, the error names that parameter.

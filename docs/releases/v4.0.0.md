# v4.0.0 草稿 / Draft

## 中文

4.0 将更改 MCP 工具名、输入 schema、结果信封和安装布局。客户端需要更新到 V4，3.x 的别名和输入转换层已撤下。本说明仍是草稿；交付检查会比较 CHANGELOG 最新版本与包版本，版本条目随发布提交加入。

### 主要变化

- 八版按已安装版本的 API 能力检查工具和动作，再检查 TIA 就绪状态。未知动作在派发前拒绝。没有安装 TIA 时，`GetSessionState` 返回 `PRECONDITION_FAILED` 并保持冷 worker 停止；V14 SP1–V19 显式读取状态但找不到安装中的 Openness 文件时也如此。`--public-api` 选择 worker 程序集，doctor 在八版单独检查安装证据。
- 八版 `GetToolUsage` 的索引与示例库使用 V4 字段。V20/V21 的具名完整引擎示例也用 `summary` 表示消息，保留调用方参数名。块文档渲染及比较接受原生块路径。Safety 编译密码需要 V17+。V20 库文档导入接受 `SkipInactiveCultures` 和 `ActivateInactiveCultures`，仍检查项目库和文件名；真机验收待执行。
- 八版均支持可选的 `ConnectPortal.takeOver`，在 schema 版本 4 中默认为 `false`。宿主内符合条件的空闲附着连续十分钟未收到请求，或新连接显式传入 `takeOver=true`，即可移交。运行中调用、审批等待、工作台参与者及 worker 启动的 TIA 受保护。故障持有者满足移交条件时，宿主先确认停止其 worker。移交写入审计并传递未确认编号；旧会话的原生调用返回 `taken-over`，显式 ConnectPortal 可重新连接，DisconnectPortal 在本地结清并返回接管警告。跨宿主拒绝给出持有者宿主 PID 和发布键。
- 根变量表、变量和常量创建，外部源删除和禁止覆盖的导入，以及单文件导出，可通过确定性读回结算。原信封保持 `OUTCOME_UNKNOWN`，`data.settlement` 和 `sessionState.settled` 记录 `applied` 或 `not-applied`。已结算项不再触发保存警告；未执行时解除相同写入保护，已执行时保留保护直至读取 GetCallResult。编译、覆盖导入及无法确定的读回仍待核对。每次重绑轮流选一项，用独立请求号在五秒内读回。外部源导入只以所请求文件名已存在为证；工程文本导出只以目标不存在为证，其未知结果会记录写入摘要，保存时给出 `UNSETTLED_CALLS`。
- 超过客户端等待时间时返回 `in-progress` 和 `OPERATION_IN_PROGRESS`。八版 lite 档均可用 `GetCallResult(requestId)` 读取原最终信封。`running`、`lateResults` 和 Busy 显示工作状态。相同写入在原结果读取前返回 `same-call-unsettled`；断开、重置及结束会话均保留运行中的原生调用。契约保持 `schemaVersion=4`。
- 产品由 TIA Portal Openness MCP 更名为 **Automation Engineering Workbench**，工作台标题同步更新。可执行文件（`TiaOpenness.exe`、`TiaMcp.*`）、Claude Code 插件 ID `tia-portal-openness-mcp`、MCP 服务名 `tia-portal` 和仓库地址沿用原值；单因更名无需修改客户端配置。
- 工具按操作与领域统一命名，指南和配方查询合入 GetToolUsage。[逐版迁移表](../releases/v4.0.0-tool-migration.md)列出八版 3.x 到 V4 的保留、合并、撤下、新增及参数类型变化。客户端按 schema 传入对象或数组。`current` 策略下不公布仅供安全 V4 候选使用的参数。
- 直接调用、CallTool 和批次共用 V4 信封。structuredContent 与文本表示相同，CallTool 成功时直接返回目标结果。详见[响应与错误规则](https://github.com/asckye/TIA_Portal_Openness_MCP/blob/master/docs/standards/design.md)。
- 八版从各自运行目录启动 `TiaMcp.FoundationHost.exe --release-key <key>`，再按 MCP 会话启动 `runtime/v<key>/worker/TiaMcp.PlcWorker.<key>.exe`。共有工具共享实现、输入和用法。先 ConnectPortal，再 AttachOpenProject；V20/V21 专有工具保留 V4 名称及输入 schema，与共用工具在同一 TIA 连接和 MTA 所属线程运行，V14 SP1–V19 使用 STA。
- V20/V21 的旧 `TiaMcp.Engine.V20.exe`、`TiaMcp.Engine.V21.exe`、worker 文件及 `tool-catalog.json` 已撤下。无 TIA 的打包宿主与原引擎应答一致。`--engine-worker`、`--engine-catalog` 等 `--engine-*` 旧选项以 64 退出。随包构建记录改为 `manifest/multi-version-build.json`，旧 `manifest/release-build.json` 已退役。八版命令行保留 doctor、audit verify、schema、version、config、install-plc-tools 和 help；gen、patch、describe、compile、export、import、prewarm 的工作改由 MCP 工具或项目生成框架承担。
- stdio 每会话一个 worker，HTTP 每个活会话一个；并发容量取决于 worker 内存和 TIA 实例数。其他会话断开、故障或重启时，受保护会话保有自己的 worker、暂存和导出句柄；可让出的持有者遵循上面的移交规则。会话结束等运行中调用完成再释放。宿主用 Windows 作业对象约束 worker，宿主终止会结束 worker，由 worker 启动的 TIA 继续运行。停止期间自行退出的 worker 视为已停止，断开和结束会话时不再误报 “Unable to verify or stop the owned worker”。HTTP 提供与 MCP 相同 Bearer 认证的 `/mcp/ready`，`/mcp/health` 包含 fileVersion。
- 各版同一 TIA 进程同时只租给一个 MCP 所有者。受保护的活持有者拒绝竞争连接并给出身份及释放方法。句柄释放后，新会话取得租约和前所有者未决请求。BUSY、UNCERTAIN 或旧 ACTIVE 添加 PREVIOUS_OWNER_UNCLEAN。尚未连接时，需要 TIA 的工具返回 PRECONDITION_FAILED 并提示 ConnectPortal；会话可继续使用。
- 未知写入只影响该次调用。后续独立读写照常校验身份并审批。`GetSessionState.data.sessionState.unsettled` 给出编号、工具及 UTC 时间；SaveProject 和 SaveProjectCopy 在预览和执行时提示 UNSETTLED_CALLS，工作台显示数量。先核对目标，禁止自动重放。
- 通道默认 120 秒，每代 worker 的首次附加、编译、下载/上传、导入/导出、归档及库更新为 300 秒。可用 `--worker-timeout-config`、`TIA_MCP_WORKER_TIMEOUTS` 或默认值选项 `--worker-timeout-seconds` 配置。读取和预览用默认预算，断开有独立期限。派发前取消返回 CANCELLED，派发后等待真实结果。超过 1 MiB 的请求在派发前拒绝，过大回复存为导出句柄，进度送回调用方令牌。worker 退出、挂起、帧损坏或 TIA 丢失会使本代 worker 故障且结果未知，可断开或显式 RestartOpennessWorker 再绑定。重启前先分离空闲 worker。断开和重启结果移除 requiresTiaRestart、recoveryMessage，分别移除 priorUnknownRequestId 和 requiresExplicitRebind；断开返回 `sessionState=disconnected`，同会话可重新连接并绑定。
- V20/V21 默认 lite，通过 `--profile full` 或 `TIA_MCP_PROFILE=full` 公布全目录；lite 可用 FindTools 和 CallTool 访问。V20/V21 撤下重复的 ConnectProject（3.x ConnectToProject），改用 ConnectPortal 后接 AttachOpenProject。ConnectIsolatedPortal、SaveProjectCopy、RetrieveProjectArchive、ManageMultiuserSession、BuildProjectScaffold 均将 portal、项目及租约纳入唯一会话绑定。八版共有工具包括 ConnectPortal、AttachOpenProject、OpenProject、CreateProject、SaveProject、CloseProject、DisconnectPortal、GetSessionState、ListPortalProcessProjects 和 GetPortalConnectionReadiness。
- 开启审批时，用原参数预览写入，预览拒绝或无效果则直接返回；决定后执行前再次检查。审批计时从预览完成后开始。`dryRun: true` 或 `mode: preview` 直接执行预览。操作前的参数与前提拒绝分别给出 INVALID_ARGUMENT、PRECONDITION_FAILED 和参数名，会话可继续使用。各版透传本项目的前提消息。调用方文件缺失返回 INVALID_ARGUMENT，不可读的输入文件在执行前拒绝。项目路径只检查存在性，TIA 持有文件不会导致误报未知结果。INVALID_ARGUMENT、PRECONDITION_FAILED 和 CONFIRMATION_REQUIRED 附 RECOVERY_GUIDANCE，给出本版用法及匹配的示例参数。
- 路径统一为绝对路径，接受两种分隔符。XML 导入在 `overwrite: false` 时先检查对象，各表中重复的 PLC 变量或常量按表名拒绝。V20/V21 导入导出先检查格式、父目录及新目标。导出抛出异常且没有写入时，返回带原生消息的 NATIVE_OPERATION_FAILED。纯文件工具明确返回原生错误或失败状态时也使用该错误码，会话可继续使用，包括报警文本、CAx、文档、单元导出和文件夹下载；可能已改工程的导入、上传、下载保持未知结果。两类结果均携带原生状态、日志、消息及目标文件大小与存在性。
- V20/V21 的 SaveProjectCopy 执行 TIA 另存为，打开的工程及绑定转到新位置，未保存更改写入副本，原文件保持上次保存状态。工具分类为 SESSION，返回 previousProjectFile 和 newProjectFile。
- V20 VM 发现的两处崩溃已有前置保护：SiVArc 仅接受 FB/FC；V20/V21 没有安全 CFC 清单接口，在原生调用前拒绝图表保护和导出，保留导入。原生调用开始前刷盘记录，GetNativeInvocationLog 按时间读取所有会话日志，崩溃后可从新会话查最后一次调用。ManagePlcGitRepository 对缺失路径返回类型化错误。
- 编译返回错误时报告 COMPILE_ERRORS 已完成失败，详情含错误与警告数、至多十条带对象路径的叶错误，完整诊断保留在 data。
- StageImportFiles、ListStagedImportFiles、CleanupStagedImportFiles 可远程传送 SCL、SimaticML、变量表及 UDT 文本。位置为 `<bundle-root>/staging/<session>/<batch>/`，每个文件 4 MiB、每会话累计最多 128 个文件、32 MiB。审批展示位置、名称、种类、大小和 SHA-256。每批记录所属 MCP 会话，所有者会话或宿主结束后其他会话可清理。列表返回最近 200 批，超出时附 INCOMPLETE_DATA。
- `ImportPlcBlocksFromDirectory` 和 `ImportPlcProgramFromDirectory` 接受 `overwrite: true`。预览计划哈希记录新建和替换，在首次导入前导出所有替换对象。失败时停止并按依赖顺序恢复已知替换。单 XML 导入尽力备份，备份失败提示 BACKUP_SKIPPED。
- 硬件目录在写入前拒绝未绑定会话与不存在的目录条目。CreateHardwareDevice 校验名称和审阅过的计划哈希，防止重复创建。创建严格使用所请求的 TypeIdentifier、版本和名称；不尝试相邻固件版本、替代 CPU 或改名重试；没有精确匹配时在创建前拒绝，支持硬件目录的版本列出候选。CreateGsdDevice 仅 V18–V21，多播传送区修改需 V19+。写属性先查访问模式并读回，建子网前按名称查询，拒绝重复 IO 系统名。设备遍历包含未分组设备；VCI 使用固定 UngroupedDevices 目录并拒绝同名根组。tia schema 列出必填 plcMlfb 及 plcVersion、hmiMlfb、hmiVersion。
- TIA 下载按显式许可回答 F 程序、硬件差异、取消活动测试、扩展下载与标识数据对话框，对应参数为 allowSafetyProgramDownload、allowHardwareDifferences、allowActiveTestCancel、allowExpandedDownload、allowIdentificationDataLoad。审批列出拟答复，拒绝时停止下载并在 meta.promptsRefused 指明参数。DownloadPlc 前先 DisconnectOnlinePlc；仅 stopBeforeDownload=true（默认）才为 DB 重初始化停机。`downloadScope: softwareOnlyChanges` 需要 V17+。
- 在线、下载和上传的 `trustDeviceCertificate` 默认为 `false`；V21 在 meta.tlsVerification.certificates 列出证书。非安全通信需显式设置 `allowNonTlsLogin: true` 才发送密码。UploadStationFromPlc 和 UploadDeviceParameters 的扫描、创建地址和应用路线均在批准后执行。
- V15.1–V21 的 OpenProject、RetrieveProjectArchive 接受 UMAC 凭据 umacUserName、umacPassword、umacUserType。口令不进入日志、审计、审批或结果。受保护工程缺少凭据时返回 PRECONDITION_FAILED 并列出缺失参数。无权访问、产品或许可缺失、多用户拒绝均返回 PRECONDITION_FAILED 和 `details.condition`，会话可继续使用；多用户提交失败仍为未知。已有主工程或本地会话时拒绝打开或新建。确认框默认拒绝，记录后应答只有确定按钮的消息。未答确认立即返回 in-progress 和已去敏的 running.dialog 及时间，忙碌回复和工作台也显示只读 running.window。GetPortalInfo 保留对话记录。worker 自启的 TIA 尚有打开工程时拒绝断开；ShowObjectInEditor 需要可见界面。
- 工作台环境页只读检查 worker 的 Openness 防火墙 AllowList，缺失时给出管理员步骤。每会话的原生工作串行，本地工具可并发。未安装匹配 TIA 或 Openness、或用户不在 Siemens TIA Openness 组时，宿主仍可启动；InitializeEnvironment 和环境页给出原因与修复方法，依赖 TIA 的调用在派发前返回 RESOURCE_UNAVAILABLE。宿主校验回复形状，畸形帧使会话故障。`doctor --fix` 可修复用户组，提示重新登录生效；`doctor --json` 输出同样结果。
- GetDeviceAddressing、GetDeviceIpAddress、GetDeviceItemIoAddresses、SetDeviceAddress 和 SetDeviceItemIoAddress 共用 Foundation 适配器。V14 SP1–V19 新增该族（F19，current / L5 NOT RUN）；V20/V21 仍在 full 档提供，契约及响应沿用原版。
- 按各版 API 扩展发现和批次（`CallTool`、`FindTools`、`PreviewToolCall`、`ApplyToolBatch`）、离线分析、文档及模板、设备与模块、网络和 CAx/AML、PLC 组、保护和删除、变量和常量、实例 DB、验证导入、外部源、交叉引用、PLC/HMI 编译、监控表、原因追踪、工艺对象和运动、软件单元、校验和与指纹、工程文本及语言、编译设置、事务、对象标识、反射及项目/全局库。缺少 API 的动作在原生调用前返回 UNSUPPORTED_CAPABILITY；只在 V20/V21 有证据的 Classic HMI 包及 SIMATIC SD 格式不向旧版提供。新增版本为 current / L5 NOT RUN；移植工具在 V20/V21 沿用既有契约和响应。

- ShowWorkbenchPage、ShowWorkbenchBlock、ShowWorkbenchCall、ShowWorkbenchLadder、ShowWorkbenchAtlas、GetWorkbenchState、GetWorkbenchSelection、PrefillWorkbenchForm 在八版均可展示工作台视图或预填待确认表单。只连接同用户同安装的工作台；不启动、不批准、不执行，不进入批次。工作台未运行时返回 RESOURCE_UNAVAILABLE。

- 工作台中英文、明暗主题采用同一组件。长调用、审批及审计列表使用虚拟化，审计页限制展示窗口；梯形图与程序册沿用同一视觉样式。GetToolUsage 示例包含 VM 核实的工程文件绑定、PLC 别名与精确路径、导出目录及导出再导入流程。程序与资源共用安装根定位，完整安装可在仓库外运行，安装根可写时数据与日志随该安装存储。

V14 SP1–V19 仅登记至少有一个可执行动作的移植工具；该版本缺少的动作在原生调用前拒绝。

租约在原生派发前写 BUSY，已知结果写 IDLE，未知结果写 UNCERTAIN。独占句柄关闭后可重新取得租约。ConnectPortal 通过 `data.previousOwner {leaseState, unsettledRequests}` 返回前持有者的状态与未决请求；BUSY、UNCERTAIN、旧 ACTIVE 触发 PREVIOUS_OWNER_UNCLEAN。正常断开的 `RELEASED <ids>` 记录仍携带未确认编号并在保存时提示。每项含 requestId 和 origin，已在本会话的编号为 this-session，新继承为 previous-owner。

会话结束、stdio EOF、Ctrl+C、控制台关闭或 HTTP 宿主关闭时，运行中的原生调用持有 worker 直至完成。优雅退出随后最多等 10 秒供非拥有方分离并释放租约，超时可按保护条件终止 worker。不会自动保存或关闭项目。未附着时 AttachOpenProject 和需要适配器 portal 的操作在派发前提示先 ConnectPortal。V20/V21 专有工具保留原有类型化拒绝和元数据；仅经审查、尚未发起原生写入却返回未知的旧包装器改用此前提拒绝，会话可继续使用。

### 结果与退出码

每个结果包含 schemaVersion、ok、data、error 和 meta。data 为工具数据或 null，error 为错误对象或 null。meta 标识版本、工具和请求，以及 outcome、execution、completeness、行为策略、分页和警告。outcome 为 succeeded、rejected-before-operation、read-failed、failed、partial 或 unknown。CLI 成功返回 0，操作前拒绝返回 2，读取或已确认的操作失败返回 3，部分结果返回 4，未知写入返回 5；语法错误为 64，建立工具上下文前的进程故障为 70。

错误码包括 INVALID_ARGUMENT、LIMIT_EXCEEDED、UNSUPPORTED_CAPABILITY、TOOL_NOT_FOUND、PROJECT_NOT_BOUND、NOT_FOUND、TARGET_AMBIGUOUS、IDENTITY_MISMATCH、ALREADY_EXISTS、CONFIRMATION_REQUIRED、PLAN_STALE、PRECONDITION_FAILED、OFFLINE_REQUIRED、AUTHENTICATION_REQUIRED、ACCESS_DENIED、RESOURCE_UNAVAILABLE、IO_FAILED、NATIVE_OPERATION_FAILED、COMPILE_ERRORS、CANCELLED、TIMEOUT、NOT_EXECUTED、PARTIAL_FAILURE、OUTCOME_UNKNOWN、INTERNAL_ERROR。COMPILE_ERRORS 携带 errorCount、warningCount 和叶错误 errors。[设计规范](https://github.com/asckye/TIA_Portal_Openness_MCP/blob/master/docs/standards/design.md)定义各错误详情。

meta.warnings 可报告 INCOMPLETE_DATA、NATIVE_WARNING、CANDIDATE_ONLY、UNVERIFIED_BEHAVIOR、CLEANUP_FAILED、NATIVE_CAPABILITY_LIMIT、DIAGNOSTIC_WRITE_FAILED、APPROVAL_DISABLED、RECOVERY_GUIDANCE、BACKUP_SKIPPED、APPROVAL_PRECHECK_REFUSED、STAGING_FOLDER_RETAINED。警告不改变失败结论。

### 工作台、审批与诊断

审批默认启用。关闭工作台时写入被拒绝，可打开工作台审阅，或在 MCP 菜单关掉审批。只读及预览不等待审批。WRITE、ONLINE-WRITE，以及归类 FILE/SESSION 的 StageImportFiles、CleanupStagedImportFiles、SaveProject、SaveProjectCopy（V20/V21 另存为）、CloseProject 等待审批；连接、附加、打开及断开无需审批。预检拒绝返回 APPROVAL_PRECHECK_REFUSED 并且不生成审批请求。关闭审批会反映于元数据，工具本身的确认与计划检查仍有效。

## English

This is an unpublished draft; its CHANGELOG entry is added in the release commit, because the delivery check compares the newest CHANGELOG entry with the packaged version. Version 4.0 is a breaking change to MCP tool names, input schemas, result envelopes, and the installed product layout. It does not provide 3.x tool aliases or an input conversion layer.

### Changes

- On all eight releases, ported tools check capability before TIA readiness. Without a TIA installation, `GetSessionState` returns `PRECONDITION_FAILED` and leaves a cold worker stopped. `--public-api` selects worker assemblies, and readiness checks the TIA installation separately.
- On V14 SP1 through V19, an explicit status read now leaves a cold bundled worker stopped if it cannot find the installation’s Openness API files. The doctor’s Openness check uses installation evidence on all eight releases.
- `GetToolUsage` applies V4 field names to index and example-library requests on every release. Named full-engine examples outside the ported usage path now report `summary` for the reply’s message on V20 and V21, matching earlier releases. Caller argument names are preserved.

- All eight releases share tool and action admission by API availability. Unknown actions are refused before dispatch. Block-document rendering and comparison accept native block paths on all eight releases; safety compilation passwords require V17+. V20 library document import accepts `SkipInactiveCultures` and `ActivateInactiveCultures`, retaining project-library and basename checks; native acceptance is NOT RUN.
- All eight releases add optional `ConnectPortal.takeOver`, default `false`, within schema version 4. An eligible idle attachment in the same host gives way after 10 minutes without requests or with `takeOver=true`. Calls, approval waits, Workbench sessions and worker-started TIA instances stay protected. The handover is audited and carries unsettled IDs. An eligible faulted holder gives way through the guarded worker stop. The previous session's other native calls receive `taken-over` until its own explicit `ConnectPortal`. Its `DisconnectPortal` settles locally with a taken-over warning. Cross-host lease refusals identify the host PID and release.
- Definite read-back settles eligible unknown writes without replay: root tag-table creation, tag/constant creation, external-source deletion and no-overwrite import, and single-file exports. The original envelope remains `OUTCOME_UNKNOWN`; `data.settlement` and `sessionState.settled` carry `applied` or `not-applied`. Settled calls stop the save warning. `not-applied` releases the identical-write guard; `applied` keeps it until `GetCallResult` is read. Ambiguous or failed reads, compile and overwrite imports stay unsettled. Native read-back has a separate request identity and a 5-second budget. Each rebind attempts one eligible entry and rotates through pending entries on later rebinds. External-source import settles only from presence of the requested basename. Project-text export settles only from absence of its target file. An unknown project-text export now records its write digest and warns `UNSETTLED_CALLS` when saving.
- Calls exceeding the client wait budget return `in-progress` with `OPERATION_IN_PROGRESS`. `GetCallResult(requestId)` is available in lite on all eight releases and returns the original final envelope. `running`, `lateResults` and `Busy` expose current work. Identical writes return `same-call-unsettled` until their result is read. Disconnect, worker reset and session disposal preserve running native calls. The unreleased contract keeps `schemaVersion=4`.
- The product is renamed **Automation Engineering Workbench** (formerly TIA Portal Openness MCP), and the workbench window title follows the new name. Executables (`TiaOpenness.exe`, `TiaMcp.*`), the Claude Code plugin ID `tia-portal-openness-mcp`, the MCP server name `tia-portal` and the repository address are unchanged, so the rename itself requires no client configuration change.
- Tool names are normalized by operation and domain, and equivalent guide and recipe lookups use `GetToolUsage`. This makes names more consistent and removes duplicate discovery entry points. The generated [release-key migration tables](../releases/v4.0.0-tool-migration.md) compare each archived 3.x catalog with its V4 baseline and list every old name with its destination, including unchanged names. They also mark merged, withdrawn and added tools and parameter changes, including JSON-string inputs replaced by typed objects or arrays.
- Inputs use the types in each tool's V4 schema, so clients can validate and send object structure without JSON-string encoding. V4-only safety parameters are not advertised while their behavior policy remains `current`.
- Results use one schema-version-4 envelope for direct calls, `CallTool` and batches so status, errors, and partial or unknown outcomes have one shape. `structuredContent` and the text representation contain the same envelope; `CallTool` does not wrap a successful target result in another JSON string. See [response and error rules](https://github.com/asckye/TIA_Portal_Openness_MCP/blob/master/docs/standards/design.md).
- All eight releases use the same MCP host and the same kind of Openness worker. Each release starts `TiaMcp.FoundationHost.exe --release-key <key>` from its own runtime folder, and the host starts that release's PLC worker, `runtime/v<key>/worker/TiaMcp.PlcWorker.<key>.exe`. Tools common to all eight releases share one implementation, input schema and usage; a session is bound with `ConnectPortal` and then `AttachOpenProject` on every release. Tools that exist only on V20/V21 keep their V4 names and input schemas. On V20/V21 the worker runs shared and V20/V21-only operations on one TIA connection and one MTA owner thread; on V14 SP1–V19 it keeps its STA owner thread.
- V20 and V21 no longer ship the engine executables `TiaMcp.Engine.V20.exe` and `TiaMcp.Engine.V21.exe`, their worker files or `tool-catalog.json`; the PLC worker runs their tools as on the other six releases. Without TIA Portal, the packaged V20/V21 hosts return the same answers as the engine did. The host refuses the retired `--engine-worker`, `--engine-catalog` and other `--engine-*` options with exit code 64. The package's build record is `manifest/multi-version-build.json`; `manifest/release-build.json` is no longer delivered.
- The command line runs on `TiaMcp.FoundationHost.exe` for all eight releases and keeps `doctor`, `audit verify`, `schema`, `version`, `config`, `install-plc-tools` and `help`. The engine commands `gen`, `patch`, `describe`, `compile`, `export`, `import` and `prewarm` are retired; use the MCP tools and the project generation framework instead.
- Every MCP session has its own worker. Over stdio that is one worker; over HTTP each live session has one, so plan client concurrency by worker memory and TIA instances. A protected session keeps its worker, staging and export handles through another session's disconnect, fault or restart. See the `ConnectPortal.takeOver` change above for eligible holders that give way. Ending a session defers disposal until its running call finishes. The host binds every worker to a Windows job object, so workers also end when the host is terminated; a TIA Portal instance a worker started keeps running. A worker that exits on its own while the host ends it counts as stopped, so `DisconnectPortal` and session end no longer report "Unable to verify or stop the owned worker" for it. The HTTP host serves `/mcp/ready` (same Bearer authentication as MCP calls) and reports `fileVersion` in `/mcp/health` on every release.
- Every release leases the selected TIA process to one MCP owner. A protected live holder produces an admission refusal with the holder's identity and the action that releases it. A released lease admits the next owner and carries previous unsettled request IDs. BUSY, UNCERTAIN and legacy ACTIVE records add `PREVIOUS_OWNER_UNCLEAN`. Tools that need a connected TIA process return `PRECONDITION_FAILED` naming `ConnectPortal` when no process is connected, and the session stays usable.
- An answered unknown write result affects that call. Later independent reads and writes run through normal approval and identity checks. `GetSessionState.data.sessionState.unsettled` lists request IDs, tools and UTC timestamps. `SaveProject` and `SaveProjectCopy` preview and apply results carry `UNSETTLED_CALLS`. The Workbench displays the unsettled count. Inspect the target before repeating an unknown call and never replay it automatically.
- All eight releases (V14 SP1–V21) share one worker channel timeout policy: 120 seconds by default, 300 seconds for the first attach of a worker generation, and 300 seconds for compile, download/upload, import/export, archive and library updates. `--worker-timeout-config` or `TIA_MCP_WORKER_TIMEOUTS` override these budgets; `--worker-timeout-seconds` sets the default budget. Previews and reads use the default; `DisconnectPortal` retains its bounded shutdown wait. Cancellation before dispatch returns `CANCELLED`; after dispatch the host waits for the real result. Requests over the 1 MiB frame are refused before dispatch, oversized replies are kept as export handles, and progress reaches the caller's progress token. Worker exit, hang, malformed frames or TIA process loss fault the worker generation with an unknown outcome; recover with `DisconnectPortal` or an explicit `RestartOpennessWorker`, then bind again. `RestartOpennessWorker` detaches an idle worker before starting the new generation. Disconnect and restart replies remove `requiresTiaRestart` and `recoveryMessage`. Disconnect also removes `priorUnknownRequestId`, restart removes `requiresExplicitRebind`, and disconnect reports `sessionState=disconnected`. Call `ConnectPortal` and `AttachOpenProject` in the same MCP session to reconnect.
- V20/V21 default to the generated lite profile. `--profile full` or `TIA_MCP_PROFILE=full` advertises the full catalog; `FindTools` and `CallTool` reach it from lite. The generated table below gives current counts.
- `ConnectProject` (3.x `ConnectToProject`) is withdrawn on V20/V21 as a duplicate of `ConnectPortal` followed by `AttachOpenProject`. The other V20/V21 lifecycle tools (`ConnectIsolatedPortal`, `SaveProjectCopy`, `RetrieveProjectArchive`, `ManageMultiuserSession` and `BuildProjectScaffold`) keep their V4 records and publish their portal, project and lease into the same shared session, so a session holds only one binding. The project lifecycle tools on every release are `ConnectPortal`, `AttachOpenProject`, `OpenProject`, `CreateProject`, `SaveProject`, `CloseProject`, `DisconnectPortal`, `GetSessionState`, `ListPortalProcessProjects` and `GetPortalConnectionReadiness`.
- Writes are checked before they reach the Workbench. With approval enabled, a write first runs its own preview with the same arguments; a refusal is returned without an approval request, a preview that reports no effect returns without approval, and the approved call is checked again before it runs. The approval timeout starts after that preview, so a slow preview does not shorten the time to decide. Previews (`dryRun: true` or `mode: preview`) never wait for approval.
- Refusals before an operation are typed and leave the session usable: argument and precondition errors are `INVALID_ARGUMENT` or `PRECONDITION_FAILED` with the parameter name, precondition messages written by this project are passed through on every release, missing caller files are `INVALID_ARGUMENT`, and caller input files that cannot be read are refused before the operation. Project paths are only checked for existence, so opening a project file that TIA holds open no longer reports an unknown outcome. `INVALID_ARGUMENT`, `PRECONDITION_FAILED` and `CONFIRMATION_REQUIRED` results carry a `RECOVERY_GUIDANCE` warning with the `GetToolUsage` lookup and, when one fits, example arguments for the connected release.
- Import, project and directory paths are passed to Openness as normalized full paths, so either slash works. A single XML import with `overwrite: false` refuses an object that already exists before the native call. Creating a PLC tag or user constant refuses a symbol that already exists in any tag table of that PLC and names the table. V20/V21 import and export tools check the file format, an existing parent directory and a new target before the native call; an export exception that wrote nothing is `NATIVE_OPERATION_FAILED` with the native message instead of an unknown outcome.
- On V20/V21, a tool that only writes files and whose native call reports an explicit error or failure state (for example alarm-text, CAx, document and unit exports and folder downloads) returns `NATIVE_OPERATION_FAILED` without locking the session; imports, uploads and downloads that may have changed the project still return an unknown outcome. Both carry the native state, the log path, the native messages, and whether the target file exists and its size.
- `SaveProjectCopy` (V20/V21) is TIA Save As: the open project and the MCP binding switch to the new location, unsaved changes are saved into the new copy, and the original project file keeps its last saved state. It is classified `SESSION` like `SaveProject` and `CloseProject`, and its result reports `previousProjectFile` and `newProjectFile`.
- Two TIA Portal crashes found in the V20 VM rounds are guarded. SiVArc block tools accept only FB and FC blocks. On V20/V21, CFC chart protection and CFC exports are refused before any CFC call because the API offers no safe chart inventory; CFC imports remain available.
- Native calls are journaled and flushed before they start, and `GetNativeInvocationLog` reads the journals of every session by time, so the last native call before a TIA crash can be found from a new session. `ManagePlcGitRepository` refuses a missing repository path with a typed error.
- A compilation that returns errors is a completed failure with the new `COMPILE_ERRORS` code: the error and warning counts and up to ten leaf error messages with object paths are in the error details, and the full diagnostics stay in `data`.
- `StageImportFiles`, `ListStagedImportFiles` and `CleanupStagedImportFiles` let a client on another machine send SCL, SimaticML, tag-table and UDT text to the TIA machine. Files are written under `<bundle-root>/staging/<session>/<batch>/` (4 MiB per file, 128 files and 32 MiB per session); the approval request shows the location and each file's name, kind, size and SHA-256. Batches record their MCP session; another session can clean a batch after its owner session or host has ended. `ListStagedImportFiles` lists the newest 200 batches; when more exist, it returns them with an `INCOMPLETE_DATA` warning instead of failing.
- `ImportPlcBlocksFromDirectory` and `ImportPlcProgramFromDirectory` accept `overwrite: true`. The preview lists each object as created or replaced in the plan hash; every replaced object is exported before the first import, and a failure stops the batch and restores known replacements in dependency order. Single XML imports make a best-effort backup and report `BACKUP_SKIPPED` when they cannot.

V14 SP1–V19 list a moved tool only when at least one of its actions can run on that release; actions the release lacks are refused before any native call.


All eight releases reserve the selected TIA process with a session lease. Requests persist BUSY before native dispatch, IDLE after a known result, and UNCERTAIN after an unknown result. A protected live holder refuses a competing attachment. An eligible idle holder in the same host gives way after 10 minutes without requests or with `takeOver=true`. A faulted attached holder follows the same eligibility rules and gives way through the guarded worker stop when it cannot acknowledge Disconnect. The lease is free once its exclusive file handle closes, including BUSY, UNCERTAIN and legacy ACTIVE records. ConnectPortal returns `data.previousOwner {leaseState, unsettledRequests}` and adds `PREVIOUS_OWNER_UNCLEAN` for BUSY, UNCERTAIN or legacy ACTIVE. Unsettled request IDs survive an acknowledged disconnect in `RELEASED <ids>`, and keep save warnings active. Each `unsettledRequests` entry contains its `requestId` and `origin`. Reconnecting reports an ID already held locally as `this-session` and newly inherited IDs as `previous-owner`.

On session end, stdio EOF, Ctrl+C, console close or HTTP host shutdown, a running native call retains its worker until completion. During graceful worker shutdown the host waits up to 10 seconds for non-owning detach and lease release. A shutdown timeout permits guarded termination. No project is saved or closed. AttachOpenProject and Foundation operations that require an adapter portal return PRECONDITION_FAILED with ConnectPortal guidance before dispatch when unattached. V20/V21-only tools retain their own typed refusal data and metadata; only reviewed legacy wrappers that report an unknown write without issuing a native call receive this connection precondition refusal, without requiring a session reset.

### Result envelope and errors

Every result has `schemaVersion`, `ok`, `data`, `error`, and `meta`. `data` contains the tool's result or is `null`; `error` is `null` or an error object. `meta` identifies the release, tool and request, and reports `outcome`, `execution`, `completeness`, behavior policy, paging and warnings.

The outcome values are `succeeded`, `rejected-before-operation`, `read-failed`, `failed`, `partial`, and `unknown`. The CLI exits with 0 for success, 2 for refusal before an operation, 3 for a read or confirmed operation failure, 4 for partial results, and 5 for an unknown write outcome. CLI syntax errors exit 64; process-level failures before a tool context exists exit 70.

The V4 error-code set is `INVALID_ARGUMENT`, `LIMIT_EXCEEDED`, `UNSUPPORTED_CAPABILITY`, `TOOL_NOT_FOUND`, `PROJECT_NOT_BOUND`, `NOT_FOUND`, `TARGET_AMBIGUOUS`, `IDENTITY_MISMATCH`, `ALREADY_EXISTS`, `CONFIRMATION_REQUIRED`, `PLAN_STALE`, `PRECONDITION_FAILED`, `OFFLINE_REQUIRED`, `AUTHENTICATION_REQUIRED`, `ACCESS_DENIED`, `RESOURCE_UNAVAILABLE`, `IO_FAILED`, `NATIVE_OPERATION_FAILED`, `COMPILE_ERRORS`, `CANCELLED`, `TIMEOUT`, `NOT_EXECUTED`, `PARTIAL_FAILURE`, `OUTCOME_UNKNOWN`, and `INTERNAL_ERROR`. The details each code carries and the outcome rules are defined in the [4.0 specification](https://github.com/asckye/TIA_Portal_Openness_MCP/blob/master/docs/standards/design.md); `COMPILE_ERRORS` carries `errorCount`, `warningCount` and the leaf `errors`.


The warning codes in `meta.warnings` are `INCOMPLETE_DATA`, `NATIVE_WARNING`, `CANDIDATE_ONLY`, `UNVERIFIED_BEHAVIOR`, `CLEANUP_FAILED`, `NATIVE_CAPABILITY_LIMIT`, `DIAGNOSTIC_WRITE_FAILED`, `APPROVAL_DISABLED`, `RECOVERY_GUIDANCE`, `BACKUP_SKIPPED`, `APPROVAL_PRECHECK_REFUSED`, and `STAGING_FOLDER_RETAINED`. A warning never turns a failure into a success.

### Product and bundle layout

| Entry | Bundle-relative path and role |
|---|---|
| `TiaOpenness.exe` | Root workbench launcher; starts `runtime/studio/TiaOpenness.exe`. |
| `TiaMcp.FoundationHost.exe` | `runtime/v<release-key>/` for all eight release keys `14sp1`, `15.1`, `16`, `17`, `18`, `19`, `20`, and `21`; the MCP server entry, started with `--release-key <key>`. |
| `TiaMcp.PlcWorker.<release-key>.exe` | `runtime/v<release-key>/worker/` for all eight release keys; the PLC worker the host starts for each MCP session. |

The package contains no engine executables: client configurations and the command line use `TiaMcp.FoundationHost.exe` for every release. The engine's former stdio/HTTP MCP host and isolation supervisor, including its `--isolate-openness` and `--no-isolate-openness` switches, have been removed; on every release Openness runs in the separate worker process.

The matching TIA Portal installation, Openness components, and licenses are installed separately. The Foundation hosts and the workbench use the bundled .NET 10 runtime; the per-release PLC workers and native Openness components require .NET Framework 4.8.

The Foundation hosts, including their command-line commands, accept `--bundle-root <absolute-path>` or `TIA_MCP_BUNDLE_ROOT`. The command-line option takes precedence. If an explicitly selected root is invalid, startup reports `RESOURCE_UNAVAILABLE` and does not search another root. See [runtime layout](https://github.com/asckye/TIA_Portal_Openness_MCP/blob/master/docs/standards/design.md).

When writable, software data is stored under `<bundle-root>/data`. The main process logs are under `data/logs/<releaseKey>` and workbench logs under `data/logs/studio`; native diagnostics and call-panel records are under `data/diagnostics`, the audit chain is under `data/logs/audit`, and the backups of overwrite imports are under `data/recovery`. Import staging is under `<bundle-root>/staging`, not under `data` or `%LOCALAPPDATA%`. An explicit `TIA_MCP_DATA_DIRECTORY` selects another absolute data root and fails if it is not writable. If the bundle data directory is unavailable, the existing per-purpose fallbacks include `%LOCALAPPDATA%\TiaMcp\diagnostics` for diagnostics, `%LOCALAPPDATA%\TiaMcp\logs\audit` for the audit chain, `%TEMP%\TiaMcp\logs\<releaseKey>` for process logs, `%TEMP%\TiaMcp\logs\studio` for workbench logs, `%LOCALAPPDATA%\TiaPortalMcp` for configuration, and `%LOCALAPPDATA%\TiaOpennessStudio` for UI preferences. Configuration and UI preference files are copied from their former user directories only when the corresponding bundle file is absent; old files are left in place. Logs and diagnostics are not migrated.

The companion Python default is `%LOCALAPPDATA%\TiaMcp\ecosystem-python\Scripts\python.exe`. `TIA_MCP_PLC_TOOLS_PYTHON` overrides it. The bundle does not create or reuse a Python environment beside the installation.

The workbench can migrate existing MCP client launch commands and arguments to the selected release's 4.0 host. It asks before writing, creates a timestamped backup beside each existing configuration file, and preserves server URLs, authentication fields, and unrelated entries. If the selected host is missing, it refuses to change that client's configuration. Restart the affected clients after migration.

### Upgrade from 3.x

Upgrading from 3.x to 4.0 is a fresh install. Download the complete 4.0 ZIP and unpack it into a new folder; do not unpack it over the 3.x folder. Keep the old folder until the 4.0 workbench and clients are confirmed working. The 3.3 workbench may display the 4.0.0 version number. Its PowerShell updater finds no compatible ZIP among the release assets and stops before downloading.

The 4.0 MCP entry points and tool names changed. Recreate each AI client's configuration from the new workbench and refresh the client's tool cache and schemas; do not reuse the 3.x launch commands. From 4.0 onward, use the bundled C# updater for subsequent releases.

The [3.3 to 4.0 migration guide (Chinese)](../guides/migrate-3.3-to-4.0.md) walks through the side-by-side installation, client and plugin configuration, approvals, tool renames and rollback to 3.3.

### Workbench write controls and diagnostics

MCP write approvals are enabled by default. With approvals enabled, MCP writes are refused while the workbench is closed; open the workbench to review a pending request, or turn approvals off in the MCP menu. Read-only MCP calls and previews do not wait for approval. `WRITE` and `ONLINE-WRITE` calls wait for approval, and so do `StageImportFiles`, `CleanupStagedImportFiles`, `SaveProject`, `SaveProjectCopy` (save-as, V20/V21) and `CloseProject`, although the tool catalog classifies these as `FILE` or `SESSION`. Other session calls such as connect, attach, open, and disconnect remain ungated. A write that its own preview refuses is returned with `APPROVAL_PRECHECK_REFUSED` and no approval request. Turning approvals off is visible in response metadata and does not remove a tool's own confirmation or plan checks.

The audit log records write requests, approvals, refusals, and outcomes; the request, decision and start/end rows of one call share the response's `requestId`. `tia audit verify` checks the audit chain. The call panel shows current calls and pending approvals. The environment page checks the local setup and can export a diagnostic bundle. Ladder rendering produces an SVG for an individual block; the program book collects rendered blocks and available check results into a self-contained HTML file.

### NO-LOCK Part 1 contract changes

The unreleased 4.0 contract keeps `schemaVersion=4` under ADR 0001. Unknown results no longer contain `data.recovery`. Session snapshots replace `requiresSessionReset` and `priorUnknownRequestId` with `unsettled[{requestId, tool, utc, fromPreviousOwner}]`. Operator snapshots omit `sessionLocked`, the `poisoned` state and the `session-locked` end reason. Save previews and executions add `UNSETTLED_CALLS` when requests remain unsettled.

In beta.5, `meta.requiresSessionReset`, `SessionResetRequiredDetails` and the `SESSION_RESET_REQUIRED` error code are removed as a hard cut under ADR 0001; `schemaVersion` remains 4. Read `meta.outcome` for this call and `GetSessionState.unsettled` for calls whose write outcome is unconfirmed. Worker replies use `OutcomeUnknown` only for a native write with an unknown result. Typed V4 results rename `data.requiresSessionReset` to `data.outcomeUnknown` for device add, document import and export, batch export, batch document import and export, external-source tools and special export; batch import keeps only `data.nativeOutcomeUnknown`, with all values unchanged. Later independent calls continue; inspect the target before repeating an unknown write and never replay it automatically.

Part 1 retains current timeout budgets, read draining and lease/disconnect behavior. Genuine worker transport faults return `PRECONDITION_FAILED` with `condition=worker-faulted` and guidance to call `RestartOpennessWorker`. In-progress results, same-call retry guards, automatic worker recovery, lease changes and result settlement follow in the remaining NO-LOCK parts. See [ADR 0034](https://github.com/asckye/TIA_Portal_Openness_MCP/blob/master/docs/standards/decisions/0034-no-session-lock.md).

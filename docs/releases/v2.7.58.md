# v2.7.58

引擎 **2.7.58.0**（V20/V21 均重建）。工具 **453**（+`GetRecipe`），默认 lite **59**。维护者 2026-09-21 的要求："需要规范 AI 对所有工具的调用，不能老是试错，这会增加 token 的消耗以及时间"。2.7.57 的 `PreflightToolCall` 要靠 AI 主动调、80 条示例只覆盖常用工具；本版把纪律放进引擎、自动执行、对全部工具生效。

## 1. 参数合法值进 `inputSchema`

`SchemaHintsLogic.Augment`（`McpServer.CallDiscipline.cs` 在注册时套一层 `SchemaHintedTool`）：每个参数描述里的备选值 → `enum`，C# 默认值 → `default`，人工示例里的值 → `examples`，没有描述的参数 → 词汇表文本填进 `description`。结果：会校验 schema 的客户端在发出前就拒绝无效值；模型看到的是精确选项。

备选值解析（`PreflightLogic.Alternatives`）只认**参数自己那句话里独立成段**的列表：`a | b | c`（任意位置）、冒号后的 `a/b/c`、`value (a, b, c)`；前面不能是 `=` / 引号 / 字母，后面必须是标点或结尾，前面不能有句号。真机核对时排除的误判：`password: … (setAccessPassword, protectMasterSecret)`（引用，不是取值）、`promptAnswersJson` 后一句的提示名列表、`folderPath: group/folder path`、`pgPcInterface: PG/PC interface`、`blockGroupPath: … kind=globaldb|fc`、`blockScope: 正则 'FC|Main'`、`version: catalog/firmware version`。本版 67 个 enum 落在 51 个工具上（全部人工核对）。字符串参数若示例是对象 / 数组（`devicePathJson`），schema 的 `examples` 用 JSON 文本，避免直接调用时把对象塞给字符串参数。

## 2. 失败自动预检

`ArgDiagnosticTool`（每个工具都经过的包装层）在内层返回后调用 `McpServer.AttachPreflightOnFailure`：`isError` 或工具 JSON 的 `meta.success=false`（经 `CallTool` 时看 `operationSuccess`，并对内层工具名与参数做预检）→ 把 `PreflightSummary` 写进 `meta.preflight`（`StructuredContent` 同步）：

```json
"preflight": {"unknown": ["regex (did you mean 'regexName'?)"], "caseFixes": ["SoftwarePath -> softwarePath"],
             "allowedValues": {"action": "read | create | delete"}, "prerequisite": "Not connected - Connect ... first.",
             "example": {"softwarePath": "PLC_1", "regexName": "FB_.*"}, "next": "Correct the argument problems listed here and call once more; ..."}
```

只放非空的项；参数没问题时 `next` 说"消息已点明原因，改那一处再调一次，不要试变体"。纯文本错误（参数诊断层的拒绝）追加一行 `preflight: {...}`；成功响应**一字不改**（同一对象引用）。本机在引擎上验证了三种形状（JSON 失败 / 纯文本 / `CallTool` 内层失败）与成功不动。

## 3. 参数词汇表与描述批次

`ParameterVocabulary`：79 个全表通用的参数名 → 描述（`dryRun`、`confirm*`、`softwarePath`、`devicePathJson` / `itemPathJson`、`propertiesJson`、路径类、分页类、`action` / `kind` 的通用说明……），`SpecsOf` 在参数没有自己的 `[Description]` 时使用并标记 `Synthesized`；通用文本刻意不写成列表，不会变成错误的 enum。手写批次 1（14 个工具 96 个参数，取值来自各 Logic 类的数组）：`ManagePlcProtection`、`CompileDevice`、`ManagePlcTableEntries`、`ManagePlcExternalSources`、`ManageHardwareObject`、`ManagePlcTagDefinition`、`ManageProjectLanguage`、`UploadStationFromPlc`、`ScanAccessibleDevices`、`ReadTransferRoutes`、`ReadPortalInfo`、`ManageCommunicationConnection`、`ReadCommunicationConnections`、`ManagePlcAlarmTextList`。统计：无自身描述 1488 → 1392（1002 由词汇表覆盖，199 个工具仍有缺口）；`manifest/tools-list.json` 的 `callDiscipline` 记录 `parameters` / `parametersUndocumented` / `parametersFromVocabulary` / `toolsWithEnumHints` / `enumHints` / `defaultHints` / `examplesCurated` / `recipes`，`Generate-ToolsListFromAssembly.ps1` 在数字回升时构建失败。

## 4. 示例覆盖全部工具

`ToolExamples.Derive`：必填参数 + 值来源依次为描述里的 `e.g. 'X'`、首个备选值、按名推断（`softwarePath` → `PLC_1`、`*PathJson` → `[]`、`*Json` → `{}`、路径 → `C:\\Temp\\<Tool>.<ext>`、`blockPath` → `Main`……），标注 derived。`FindOrDerive` 用于 `FindTools`、`CallTool` 缺参拒绝、`PreflightToolCall`（`Meta.exampleDerived`）与自动预检；描述装饰仍只用人工示例。

# 0019 check-all 复用输入未变的上次通过结果

- 状态：已采纳
- 日期：2026-10-18
- 决策者：维护者
- 相关：[ADR 0016](0016-architecture-decision-records.md)；[验证说明](../validation.md)；[重构计划](../refactor-plan.md) P8-72、P8-77

## 背景

每次合并后在 master 上运行一次完整的 check-all，即使大部分检查的输入没有变化，约 400 个检查也全部重跑。维护者问能否改为增量式测试，而不是每次从头测到尾。

## 选项

1. 维持每次全部重跑：最简单，但每次合并都要等完整时长。
2. 只在全部输入不变时复用上次通过结果：输入包括检查读取的源码与数据文件、测试与产品的输出字节、检查定义、SDK、运行时与机器标识；任何一项变化都重跑。

## 决定

采用选项 2（维护者 2026-10-18“改为增量式”）。

- 复用只针对同一台机器上、输入完全相同的一次干净通过。复用结果在报告中标为 passed (reused)，带上输入标识、原运行编号和证据路径，计入最低数量门禁。
- 计时敏感的用例、稳定性与浸泡测试、计时预算检查、读取机器状态的检查，以及上次没有干净通过的检查，始终重跑。
- GitHub CI、branch-gate、发布候选，以及带 `-Clean` 或 `-NoResultCache` 的运行，从不复用。

## 后果

- 正面：只改了文档、工作台或单个测试项目的合并，只重跑受影响的检查。
- 负面与取舍：读取范围无法静态确定的套件按整个仓库作为输入，任何改动都会让它们重跑；输入哈希本身有开销。
- 验证方式：CheckAllResultCacheTests 覆盖命中、各类输入变化、不可复用的检查和损坏缓存；合并后在 master 上连续两次 check-all，对比冷运行与复用运行的耗时。

# 0012 旧版只注册至少有一个动作能在该版 API 上运行的工具

- 状态：已采纳
- 日期：2026-10-09
- 决策者：维护者
- 置信度：高
- 相关：[阶段 8 迁移方案](../phase8-port-plan.md)“维护者决定：旧版注册规则”；[4.0 源码版本范围](../../reference/version-tools.md)；[官方 API 覆盖与逐版缺口](../../reference/openness-coverage.md)；[交接](../handoff.md)；[ADR 0009](0009-port-v20-v21-tools-to-foundation-adapters.md)、[0014](0014-tool-counts-follow-official-api.md)

回溯记录（写于 2026-10-11）。

## 背景

移植的能力族在旧版上按 API 启用。有的工具在旧版完全没有对应的 API，有的只缺部分动作。发布始终拒绝的目录项会浪费模型的上下文，也会误导客户端。

## 选项

1. 旧版发布与 V20/V21 相同的目录，缺 API 时一律拒绝：目录一致；大量条目始终失败。
2. 只注册至少有一个已实现动作可以运行的工具：目录如实反映能力；各版本的工具数量不同。

## 决定

采用选项 2（P8-03x）。V14 SP1–V19 只注册至少有一个已实现动作能在该版官方 API 上运行的工具；整项缺 API 的工具不进入目录；部分动作缺 API 的工具继续注册，并在原生调用前对该动作返回 `UNSUPPORTED_CAPABILITY`。判定依据是逐动作能力表、旧版适配器的重载与属性写入分支以及宿主格式门禁，族级的 yes/partial 不代替逐工具的决定。`PortedFamilies.ToolReleases` 是注册、发现、用法、桥接、被动诊断与标准包规划共用的唯一来源。

## 后果

- 正面：目录只列出可用的能力；同一张表驱动所有入口。
- 负面与取舍：各版本工具数量不同（见 ADR 0014）；部分动作被拒的工具仍需要客户端处理 `UNSUPPORTED_CAPABILITY`。
- 验证方式：`PortedFamilies` 表与八版契约快照；`GetToolUsage` 的八版检索与功能检查。

# 0023 4.0 正式版在全部 4.0 任务合并、检查通过、rc 与维护者确认后发布

- 状态：已采纳
- 日期：2026-10-30
- 决策者：维护者
- 置信度：高
- 相关：取代 [ADR 0013](0013-release-4-0-after-phases-7-and-8.md) 的放行部分；[ADR 0020](0020-prereleases-tested-by-users.md)、[0024](0024-ci-does-not-block-merges.md)、[0025](0025-release-evidence-nightly-and-verified-build-units.md)；[发布计划](../../status/release-plan.md)；[发布流程](../release-workflow.md)

## 背景

ADR 0013 规定 4.0 在阶段 7、8 全部完成后发布。之后阶段 8 的 P8-31f–i 与 P8-40 推迟到 4.1（维护者 2026-10-22），预发布改由测试者测试（ADR 0020）。2026-10-22 维护者曾定下正式版条件：全部 4.0 任务合并、master 上连续 20 次 CI 通过、最后一个 beta 公开至少 14 天、没有未决的 blocker、完整发布链生成的 rc、维护者确认。2026-10-30 维护者认为公测期和连续 20 次通过没有必要：测试反馈陆续进来，发布本身只是复制和打包。

## 选项

1. 保留 2026-10-22 的条件：更多等待时间换取更多反馈；发布时间不确定。
2. 只保留可以在本机验证的条件：全部 4.0 任务合并、检查通过、rc、维护者确认。

## 决定

采用选项 2（维护者 2026-10-30：“公测期取消，不需要，测试全部通过反馈来，我们只需要复制打包程序即可”）。4.0 正式版的条件：

- [发布计划](../../status/release-plan.md)中列为 4.0 范围的任务全部合并（包括修完 beta.2 真机测试发现的 VMFIX-1 和 DES-1..5）；
- 离线检查（check-all）与 GitHub CI 在发布提交上通过；
- 用完整发布链生成 rc；
- 维护者确认后发布。

取消“最后一个 beta 公开至少 14 天”和“master 上连续 20 次通过”（P8-91 的 20 次条件随之取消）。4.0 正式版起初不向 3.3 安装通过更新器提供，用户手动下载并按发布说明迁移；以后是否开启另行决定。发布说明继续列出未在真实 TIA Portal 上验证的项。

## 后果

- 正面：发布时间由任务完成情况决定，不再等待固定期限。
- 负面与取舍：正式版前的真机反馈只来自测试者和我们的 VM 回归（ADR 0020），没有公测期兜底。
- 后续工作：是否另加“没有未决的 blocker 报告”一条尚待维护者决定（发布计划 D-P1）。
- 验证方式：rc 的发布记录；发布前核对发布计划中的 4.0 任务全部为“已合并”。

# 0050 生成写入每次执行审批一次，审批绑定计划哈希与全部步骤

- 状态：已采纳
- 日期：2026-10-08
- 决策者：维护者
- 置信度：高
- 相关：[项目生成框架](../../archive/development/design/project-generation-framework.md)第 1.5 节 G6、第 6.5 节、第 8 节 Q6 与“维护者决定（2026-10-08）”；[设计规范](../design.md) 第 8.2 节；[ADR 0003](0003-workbench-approval-for-mcp-writes.md)；由 [ADR 0052](0052-staged-generation-execution.md) 细化；提交 `2fc60da13`

回溯记录（写于 2026-11-25，待补写编号 B24）。

## 背景

每一步一次审批时，上百步的生成无法操作（缺口 G6）。

## 选项

1. 每一步单独审批（当时的现状）。
2. 每次 Apply 审批一次，绑定计划哈希与全部步骤，可只选部分阶段，逐步审计。
3. 固定按阶段（硬件、PLC、HMI、保存）各审批一次。

## 决定

采用选项 2：审批看到的就是全部将执行的内容，步骤参数摘要逐一核对。批准后逐步执行、逐步审计，失败即停；需要阶段间检查时按阶段分次 Apply。

## 后果

- 正面：生成可操作，人批准的是完整计划。
- 负面与取舍：执行中没有逐步的人工确认，须分阶段 Apply 取得中间检查点。
- 后续变化：ADR 0052 修订为“决定性参数预先确定，`expectedPlanHash` 等见证由工具预览迟填”，每次 Apply 仍只审批一次。
- 验证方式：设计规范第 8.2 节 S2、S4、S6；`GenerationExecutionTests`、`StagedGenerationTests`。

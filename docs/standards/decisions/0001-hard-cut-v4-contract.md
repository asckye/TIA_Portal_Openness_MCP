# 0001 4.0 硬切换到 V4 契约，不提供 3.x 兼容层

- 状态：已采纳
- 日期：2026-10-03
- 决策者：维护者
- 置信度：高
- 相关：[阶段 6 契约规范](../phase6-review.md) 第 1–3 节与第 6 节（决策 1–3、11）；[重构计划](../refactor-plan.md) 阶段 6；[4.0 发布说明草稿](../../releases/v4.0.0.md)；[新旧工具对照表](../../releases/v4.0.0-tool-migration.md)；[V4 工具协议规范](../design-spec/v4-protocol.md)

回溯记录（写于 2026-10-11）。

## 背景

3.x 的工具名称、参数和返回结构是逐步增加形成的：同一操作有多个入口，参数中混有 JSON 字符串，直接调用、`CallTool`、批次和 CLI 的结果形状不同，错误语义依赖消息文本。4.0 要统一八个版本的契约，并为审批、审计和结果未知后的处理提供稳定的结构。保留兼容层意味着每个工具要维护两套契约和两倍的测试面。

## 选项

1. 保留 3.x 工具别名和输入转换层：现有客户端不必修改；但新旧契约并存，转换层本身需要测试和文档，旧的不一致继续存在。
2. 硬切换：4.0 只发布 V4 契约，旧名称只出现在迁移文档中；客户端必须按对照表重建配置，但契约只有一套，可以一次清理全部不一致。

## 决定

采用选项 2，4.0 放弃 3.x 兼容：

- 工具统一按“动词 + 对象”命名，全部不符合项改名，合并同义的入口；
- 输入使用强类型对象，参数不再携带 JSON 字符串，真正动态的属性用受约束的字典；
- 直接调用、`CallTool`、批次和 CLI 使用同一个 V4 信封；
- 发布说明附生成的新旧名称与参数对照表，仅作为文档，不提供运行时别名或转换层。

## 后果

- 正面：八个版本只有一套契约，由契约快照冻结；错误使用稳定的错误码，消息文本不再承担功能。
- 负面与取舍：3.x 客户端升级到 4.0 时必须按对照表重建配置。4.0 发布前是修改名称和结构的最后一个免费窗口，发布后的改名都是破坏性变更（见 [V4 协议偏差清单](../design-spec/deviations/protocol.md) 开头的说明）。
- 后续工作：4.x 的演进与弃用政策在 4.0 前写入协议规范（API-11，P8-60）。
- 验证方式：契约快照 `manifest/contracts/v4/baseline/*.json` 与响应快照；对照表由生成器从契约基线生成。

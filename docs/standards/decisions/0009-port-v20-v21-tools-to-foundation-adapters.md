# 0009 V20/V21 专有工具按能力族移入 Foundation 适配器，之后引擎退役

- 状态：已采纳
- 日期：2026-10-08
- 决策者：维护者
- 置信度：高
- 相关：[路线图](../roadmap.md)“阶段 8”；[重构计划](../refactor-plan.md) P8-02–P8-04；[阶段 8 迁移方案](../phase8-port-plan.md)；[ADR 0005](0005-v20-v21-on-foundation-host.md)、[0006](0006-engine-exe-as-v20-v21-worker.md)、[0012](0012-old-release-tool-registration.md)、[0014](0014-tool-counts-follow-official-api.md)

回溯记录（写于 2026-10-11）。

## 背景

ADR 0006 之后，V20/V21 专有工具仍由引擎代码在引擎 worker 中执行，V20/V21 与其他六个版本在 worker 形态、线程和代码位置上仍然不同。旧版缺少的不少能力，在它们自己的官方 API 中其实可用。

## 选项

1. 4.0 之后再考虑合并：改动少；两套执行路径长期并存。
2. 按能力族移植：共用逻辑与版本 API 差异分开维护，每族迁移后删除引擎实现并按 API 在旧版启用，最终 V20/V21 改用 PLC worker。

## 决定

采用选项 2（维护者确认的阶段 8 方向）。V20/V21 专有工具按能力族（F01–F35）移入 Foundation 适配器：

- 共用逻辑与版本 API 差异分开维护；
- 每族迁移时，V20/V21 的契约与响应基线逐字节不变，并删除对应的引擎代码；
- 同一族在 V14 SP1–V19 中按官方 API 支持启用；
- 全部族迁完后，V20/V21 改用与其他六个版本同结构的 PLC worker，引擎程序与引擎 worker 退役（P8-04）。

## 后果

- 正面：八个版本最终使用同一套写法；旧版获得其官方 API 支持的能力。
- 负面与取舍：迁移期间两条执行路径并存；每批需要真机复验，新启用的旧版能力在验收前为 `current / NOT RUN`。
- 后续工作：批次与闸门见迁移方案；当前进度见 [架构概览](../design-spec/architecture.md) 第 9 节。
- 验证方式：每族的契约与响应零差异门禁；`PortedFamilies` 逐工具、逐版表；各批次的真机复验并入最终验收（ADR 0013）。

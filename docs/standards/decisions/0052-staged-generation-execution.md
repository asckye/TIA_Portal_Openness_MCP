# 0052 完整工程生成按 D3 分阶段执行：预览比对、写栅栏、事实链、效果核对、发散即停、同次换绑

## 背景

八版的外部源导入、生成与清理工具在执行时重算预览哈希，哈希包含进程号、工程文件、源清单和会话内源标识；P8-31e 不能在规划时给出这些参数，含这些步骤的阶段被标为不可用，完整 PLC 生成无法执行。

## 选项

1. A 分阶段执行，工具预览后比对再执行：不改写工具，但步骤之间有监管空隙。
2. B 每阶段审批一次：导入与生成互相改变对方的哈希，退化为约每步一次审批。
3. C 写工具接受计划授权代替预览哈希：每个写工具多一条准入路径，且旧版靠该哈希防止覆盖已有块。
4. D1 哈希预测（与八版内部公式强耦合，否决）；D2 组合批量工具（新的原生调用序列，4.0 不做）。
5. D3：A 加会话写栅栏、跨步骤运行事实链和写后效果核对。

## 决定

采用 D3；Q1–Q14 全部按推荐：

- 需要预览哈希的写步骤先调用该工具自己的只读预览，按逐工具规则投影后与已批准的预期比较，一致才填入唯一迟填参数 `expectedPlanHash`，以单步授权执行；工具照常重算哈希。
- “计划内参数全部预先确定”改为“决定性参数预先确定，见证由预览迟填”。
- 写栅栏拒绝同一会话中不属于本次运行的写调用，含工作台面板；取消只在步骤之间生效。
- 发散只停止，重新规划后再审批；新建工程在同一次运行内换绑。
- 首版规划只用 READ 工具；批准后不过期，另设 4 小时与 10,000 步上限；`PlanJson` 内联在审批帧中。
- 结果未知的对象报冲突，由人核对后显式 `adopt`；编译成功后删除本运行导入的外部源。
- 记录文件放在工程文件夹内、与 `.apXX` 同级；旧版对象见证用块与类型信息的修改时间；4.0 只做 `current` 形态。

## 后果

- 正面：写工具自身的预检与哈希保留；每次 Apply 仍只审批一次。
- 负面与取舍：原生读取约为原来的 2–3 倍；逐工具投影规则与结果形态耦合。
- 待真机确认：记录位置对归档、恢复与 VCI 的影响，修改时间见证的稳定性；不成立时按设计改用备选方案（Q5、Q7）。
- 后续变化：SafeV4 候选实现已归档删除，e6、h1 推迟到 4.1；取消会话锁后，结果未知停止本次运行并记入未确认调用（ADR 0034）。
- 验证方式：`GenerationExecutionTests`、`StagedGenerationTests`。

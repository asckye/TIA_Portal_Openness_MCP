# 0047 工作台控制通道与审批管道分开，只能显示、读取和预填

- 状态：已采纳
- 日期：2026-10-08
- 决策者：维护者
- 置信度：高
- 相关：[工作台控制设计](../../archive/development/design/workbench-control-and-shared-session.md)第 0、2、4 节与“维护者决定（2026-10-08）”；[设计规范](../design.md)“工作台控制通道”；[安全标准](../security.md) SEC-02；[ADR 0003](0003-workbench-approval-for-mcp-writes.md)；提交 `f10870671`、`4f713bd42`、`846feba47`

回溯记录（写于 2026-11-25，待补写编号 B17）。

## 背景

P8-20 让 AI 在工作台上显示页面、定位对象和预填表单。审批由同一工作台处理，通道不能批准写调用或改变审批开关。

## 选项

1. 新的命名管道，复用审批管道的安全原语（同用户、拒绝远程、双向 SID 核对）：不开端口，AI 在远端时同样成立。
2. 在审批管道上加消息类型：违反“与审批管道分开”，控制消息与审批决定共用解析器。
3. 工作台开本机 HTTP 监听：需要 URL 预留与鉴权密钥，暴露面更大。
4. COM 或窗口消息：无法核对 SID，测试困难。

“允许 AI 控制界面”选默认开启而不是默认关闭的原因没有记录。

## 决定

采用选项 1：

- 管道 `TiaMcp.Workbench.v1.<sha256>`，工作台为服务端，协议、DTO 和管道名与审批完全分开。八版相同的 8 个宿主工具：5 个显示、2 个读取、1 个预填。
- 操作是封闭枚举，没有审批、审批开关、服务启停和工程执行；处理器只拿到窄接口。
- 控制调用不派发 worker、不进审批、不写审计链。
- “允许 AI 控制界面”默认开启，只能由人修改；人正在操作时优先，切页后短时间内忽略执行与审批按钮的点击。
- 浏览器只打开本会话渲染且哈希一致的文件。

## 后果

- 正面：AI 能显示和预填，但协议中没有批准。
- 负面与取舍：信任边界是同一 Windows 用户，不防本机已能执行代码的代理；每版目录多 8 个工具。
- 落实：P8-20a–d。
- 验证方式：设计第 4 节的反射、封闭枚举与源码扫描测试；`WorkbenchControlHostTests`。

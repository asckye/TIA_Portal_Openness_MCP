# 0038 HTTP 传输不设访问密钥，局域网使用由用户在可信网络中自行启用

- 状态：已采纳
- 日期：2026-11-19（移除）、2026-11-23（复核后维持）
- 决策者：维护者
- 置信度：中
- 相关：单独记录 [ADR 0035](0035-workbench-native-ide-dual-accent.md) 中“移除 HTTP 共享密钥与 DPAPI 凭据保管库”一条；[安全标准](../security.md) SEC-05、SEC-16 与第 6 节；[ADR 0042](0042-accepted-risks-for-4-0.md)；桌面规范 SEC-16；任务 REV-SEC

## 背景

beta.6 之前，HTTP 传输用 Bearer 访问密钥，凭据可存放在 DPAPI 保管库中以 `vault:<名称>` 引用。2026-11-19 的 ADR 0035 为简化局域网和虚拟机直连，把两者一起移除，但这一安全决定只写成视觉设计 ADR 中的一条。2026-11-22 的全面审查（安全 SEC-H1、文档 DD-02）指出：免密钥 HTTP 是桌面规范 SEC-16 的 MUST 例外，需要单独的 ADR、偏差登记和威胁说明。

审查给出的威胁：能访问绑定地址的设备（同一 VLAN、虚拟机仅主机网络中的其他机器、VPN 对端，以及防火墙规则覆盖公用网络时的同一子网）可以建立 MCP 会话，调用全部只读工具读取块源码、工程文本和硬件配置；可以提交写请求，审批卡上与用户自己的 AI 发出的请求看起来相同；用户关闭审批后，离线写工具会直接执行。链路是明文，监听者能读到工程数据和直接传入的 PLC 密码。

## 选项

1. 恢复 Bearer 密钥，回环和局域网都要求：最安全；每个客户端都要配置和轮换密钥，正是 0035 想去掉的负担。
2. 回环免密钥、非回环地址要求密钥：降低局域网暴露；维护者 2026-11-23 考虑后否决，局域网直连仍需配置密钥，与产品“连接不设密码”的定位不符。
3. 全部免密钥，用默认关闭、绑定限制、请求校验、审批和明确警告约束风险：使用最简单；局域网暴露由用户自行承担。

## 决定

采用选项 3。MCP 连接不设密码或访问密钥，回环和局域网相同；DPAPI 保管库同样不恢复。接受的风险和缓解措施如下：

- HTTP 默认关闭，默认传输是 stdio；启用 HTTP 时默认前缀是 `http://127.0.0.1:8735/`。
- 从 rc.2 起，宿主拒绝通配地址（`0.0.0.0`、IPv6 任意地址）和公网绑定地址（REV-SEC）。此前只有工作台配置器拒绝 `0.0.0.0` 和广播地址。
- 每个请求校验 Host 和 Origin，不符返回 403 并写审计，防止 DNS rebinding。
- 写工具默认在工作台审批；物理在线写入即使关闭审批也须由人确认。
- 工作台配置网络时添加的入站防火墙规则只允许本地子网（`RemoteAddresses=LocalSubnet`），对全部网络配置文件生效（`Profiles=-1`，含公用网络）。
- 用户文档、发布说明和迁移指南警告：局域网 HTTP 没有认证且是明文，只在可信局域网或虚拟机仅主机网络中启用；3.3 依赖密钥的用户须知道密钥已经取消。

## 后果

- 正面：客户端配置不含密钥，局域网和虚拟机直连只需地址和端口。
- 负面与取舍：可达端点的任何设备都能调用工具；审批卡不显示请求来源地址；明文链路暴露工程数据和 PLC 密码。防火墙规则含公用网络配置文件，笔记本换到公用网络时同一子网的设备可以访问。
- 后续工作：REV-SEC 实现宿主侧绑定地址拒绝；防火墙规则是否限于域和专用网络、审批卡是否显示来源地址，留待后续评估（待核对）。
- 验证方式：`HttpHostOptionsTests` 覆盖绑定地址拒绝（REV-SEC 合并后）；`HttpRequestBoundaryTests` 覆盖 Host/Origin；偏差登记见[标准说明](../README.md)。

# 0049 项目生成用可替换的标准包和规范 JSON 机器描述

- 状态：已采纳
- 日期：2026-10-08
- 决策者：维护者
- 置信度：高
- 相关：[项目生成框架](../../archive/development/design/project-generation-framework.md)第 1.5、3、4、8 节（Q1–Q4、Q7–Q10）与“维护者决定（2026-10-08）”；[设计规范](../design.md) 第 8 节；[ADR 0050](0050-generation-approved-once-per-apply.md)、[0052](0052-staged-generation-execution.md)；提交 `92e8064b1`、`f4aef0ff6`、`4d5c358e2`、`bfacd7727`、`2fc60da13`

回溯记录（写于 2026-11-25，待补写编号 B22）。

## 背景

当时没有“标准包”概念，规则散在模板、文档和 AI 上下文；没有规范的机器描述，不能从多台设备展开；没有对已有工程的差异计划；风格检查只有通用规则。

## 选项

1. 标准包形态：A 目录加 JSON 清单与分部文件、分发时打 zip；B 只用单个 zip（Git 中是二进制）；C 以 TIA 全局库为主体加旁注规则（绑定库格式，无法离线校验）。
2. 书写格式：A 只用 JSON；B 另收 YAML；C 只用 YAML。
3. 规则表达：A 声明式加受限占位符；B 通用模板引擎；C 包内脚本。
4. 设备清单：A 规范 JSON 为唯一生成输入，表格和表单编辑同一 JSON；B 只收 JSON；C 以表单为主。
5. 执行器：A 宿主内编排器；B 只给计划，由 AI 逐个调用；C 复用批次工具（当时只有 V20/V21 且限 50 步）。
6. 已有工程：A 只补缺；B 备份后覆盖；C 删除后重建。

## 决定

各项采用 A：

- 标准包是“目录 + JSON 清单与分部文件”，以 zip 分发，只用 JSON，按 JSON Schema 2020-12 校验；规则为声明式加受限占位符，不执行包内代码。
- 规范 JSON 机器描述是唯一的生成输入，另收由标准包导出的 xlsx/CSV 模板。
- 编排器在 Foundation 宿主内；已有工程遇到不同对象只补缺并报告冲突；生成记录写在工程目录旁的 `.tiagen.json` 并进审计。
- 首版离线部分与 PLC 执行覆盖八个版本，其余能力随迁移批次开放；仓库内的包放在 `templates/standards/`。

## 后果

- 正面：第三方包导入后不执行代码，结果确定、可离线校验。
- 负面与取舍：规则的表达能力有限，复杂逻辑放进包的 SCL 源或库类型；不覆盖已有的不同对象。
- 后续变化：首批标准包的范围另见待补写 B23；记录文件位置由 ADR 0052 细化；P8-31f–i 推迟到 4.1。
- 验证方式：`reference/schemas/standards/v1` 的 schema 与 `src/Logic/Generation` 的测试。

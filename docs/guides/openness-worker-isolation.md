# Openness workers and recovery

Every MCP session has a version-matched worker. All eight releases start `runtime/v<key>/TiaMcp.FoundationHost.exe --release-key <key>`, and the host starts the release's PLC worker, `runtime/v<key>/worker/TiaMcp.PlcWorker.<key>.exe`. The package no longer contains the V20/V21 engine. The host owns MCP transport, authentication, approvals and diagnostics. Workers serialize native calls on their owner thread: STA for V14 SP1–V19, MTA for V20/V21.

`--isolate-openness` and `--no-isolate-openness` have been removed. Use the Workbench-generated FoundationHost command. Worker separation is part of the architecture and has no on/off switch.

## Timeouts and cancellation

The shared budget is 120 seconds by default, 300 seconds for the first attach in a worker generation, and 300 seconds for compile, transfer, import/export, archive and library updates. `--worker-timeout-config` reads category budgets; `TIA_MCP_WORKER_TIMEOUTS` overrides the file, and `--worker-timeout-seconds` sets the default. Previews and reads use the default. Cancellation before dispatch returns `CANCELLED`. A dispatched call continues to its actual result. When its wait budget ends, MCP returns `in-progress` with `OPERATION_IN_PROGRESS`, `ok=false` and the `activeRequestId`. Read `GetCallResult(requestId)` to retrieve the final envelope.

A running call keeps its worker and native execution lane. Other native calls receive `PRECONDITION_FAILED` with `condition=worker-call-running`, naming the tool, request and start time. `GetSessionState` reports `running` and `lateResults`, and worker status reports `Busy`. `DisconnectPortal` and `RestartOpennessWorker` refuse while a native call is unanswered. Session disposal waits for the original invocation to finish its binding updates, audit and approval completion. Worker exit or a malformed reply remains a real transport fault. Requests are never replayed automatically.

## Inspect an unknown result

An answered `OUTCOME_UNKNOWN` affects that call. Read `GetCallResult(requestId)` and inspect its target before repeating it. `GetSessionState.data.sessionState.unsettled` lists its request ID, tool and UTC timestamp. Later independent calls run through normal admission and approval. `SaveProject` and `SaveProjectCopy` previews and executions carry `UNSETTLED_CALLS` while entries remain.

The host carries the legacy `meta.requiresSessionReset` field until its planned removal. Admission and the unsettled list use the final call outcome. Result mapping retains legacy flags as unknown evidence for writes until Part 8 reclassifies each producer. Reads ignore those flags. The Workbench displays the number of calls with an unknown outcome.

After worker exit, a malformed reply, a failed host probe or reported portal loss, the next native call starts a new worker generation and attempts to rebind the recorded TIA PID, process start time and exact project. A new PID is eligible only when exactly one process of that release has the exact project open and its `AttachedSessions` is empty. Recovery never replays the failed call. Missing TIA, an unavailable project or a failed rebind produces a precondition refusal and the following call tries again. `ConnectPortal` can explicitly select another process.

The session retains its last 16 completed call results in completion order and every running result in memory. Unknown IDs return `NOT_FOUND`. After eviction, summaries survive only for unread writes and unread unsettled IDs. These summaries contain tool, outcome and time, plus a notice that the full payload is unavailable. Reading a summary releases its guard and removes the summary. Later lookups return `NOT_FOUND`. Read full results remain queryable while they are among the latest 16 completed results. Inner unknown batch-write IDs resolve to the enclosing result when retained. Reading the outer result or summary acknowledges all its inner unknown writes. An identical write returns `same-call-unsettled` while it is running or its result remains unread. Reading its completed result releases that guard. Previews and different arguments continue through the usual checks. Cancellation after the in-progress response leaves the original call running, and its progress notifications stop when the response detaches. Invalid progress is logged once per call and further progress is dropped while the worker continues waiting for the real reply. Reply-level faults and process exit trigger recovery on the next native call.

The accepted design and implementation stages are recorded in [ADR 0034](https://github.com/asckye/TIA_Portal_Openness_MCP/blob/master/docs/standards/decisions/0034-no-session-lock.md).

After an acknowledged `DisconnectPortal`, call `ConnectPortal` and `AttachOpenProject` in the same MCP session. The explicit connection starts a new worker generation. A live lease handle still prevents a second writer. Once the handle closes, BUSY, UNCERTAIN and legacy ACTIVE records add `PREVIOUS_OWNER_UNCLEAN` and disclose `data.previousOwner {state, requests}`. The next session inherits unsettled IDs, including those retained by an acknowledged disconnect, and save continues to report `UNSETTLED_CALLS`.

## Automatic worker recovery

`WORKER_RESTARTED` reports the previous and current generation, reason, lost worker-held state and whether rebind completed. `GetSessionState.data.sessionState.workerRecovery` retains that record. Automatic recovery preserves export handles, import staging, generation records, unsettled calls and late results. Preview plans, approval identity, engineering transactions and worker-held read handles must be obtained again. Rebound projects are borrowed. Explicit `RestartOpennessWorker` clears the rebind target and export handles.

`GetSessionState` and other host-only tools report cached state while recovery is pending. An automatic restart leaves the Workbench session active. An unanswered native request keeps `worker-call-running`. A live worker that started its TIA instance returns `worker-owns-portal` when automatic recovery would stop it. Save in TIA, then use `RestartOpennessWorker`. A person can end a non-returning native call in TIA or through the Workbench's existing host force-stop.

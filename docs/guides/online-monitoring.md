# 在线读取 PLC 实时值

本页工具属于 V20/V21 完整引擎。它们通过 S7 或 OPC UA 读取 CPU；TIA 工程中的变量定义、离线初始值和实时值是不同数据。

## 选择读取方式

| 工具 | 用途 | 是否需要打开 TIA 工程 |
|---|---|---|
| `GetPlcLiveValuesS7` | 按绝对地址和类型读值 | 地址已知时不需要 |
| `GetPlcLiveValuesOpcUa` | 按实际 OPC UA NodeId 读值 | NodeId 已知时不需要 |
| `MonitorPlcWatchTableS7` | 从工程监控表取地址，再通过 S7 读值 | 需要 |
| `ProbeS7CpuIdentity` | 查询目标 CPU 身份 | 不需要 |
| `TraceTagCause` | 从程序分析变量写入和条件 | 需要；分析本身不是实时测量 |

`GetPlcWatchTableCurrentValuesReadOnly` 获取的是 Openness 监控表条目定义，不能因为名称含 CurrentValues 就把它当作实时读值。

## 第一次读取

1. 确认目标 CPU 地址、型号以及允许使用的通信方式。
2. 读取所选工具的 `GetToolUsage(toolName="...")`，按其参数准备一个少量点位的请求。
3. S7 地址使用实际 DB 偏移或 M/I/Q 地址；选择正确的数据类型。OPC UA 使用浏览或服务器导出得到的实际 NodeId 和安全配置。
4. 检查每个点的状态、值、类型及采样时间，失败点单独保留原因。
5. 需要与 TIA 或另一通道比较时，注意采样时刻不同和正在变化的值。

S7 地址形状示例：`M0.0`、`MW12`、`DB10.DBD0:REAL`、`DB10.DBD4:DINT`。这些不是现场地址，实际偏移与长度必须来自目标程序。标准访问 DB 具有固定偏移；优化 DB 不应据名称猜测偏移。

OPC UA NodeId 包含命名空间和标识符，如 `ns=...;s=...` 或 `ns=...;i=...`。命名空间索引、符号暴露范围和标识符由服务器配置决定，不能仅用 PLC 符号拼接固定 `ns=3`。PLC/OPC UA 可以暴露符号信息，是否需要工程取决于所选读取路径。

## 环境与结果

S7 读取需要目标允许相应通信；OPC UA 需要启用服务器、适用许可和匹配的访问/证书设置。具体要求依 CPU、固件和项目组态而变，不为排查读取直接改 CPU 配置。由负责该设备的工程人员核对现有设置。

| 现象 | 检查 |
|---|---|
| 通道连不上 | 实际 IP/端口、路由、访问配置和服务器状态 |
| S7 地址越界 | DB 是否存在、是否标准访问、偏移与字宽 |
| 数值不合理 | 有符号/无符号、整数/浮点解释与目标声明 |
| OPC UA Bad 状态 | 实际 NodeId、变量暴露、用户权限及状态码 |
| 监控表为空 | 工程是否正确、表是否有条目、地址是否可解析 |

上述读值工具不提供写值、强制或 CPU 模式切换；读取仍应按设备允许的通信和采样频率执行。返回只读标志说明调用种类，不替代现场运行影响的判断。工程接口限制见[Openness 能力边界](../troubleshooting/openness-limitations.md)。

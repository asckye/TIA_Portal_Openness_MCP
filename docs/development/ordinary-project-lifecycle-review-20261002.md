# Ordinary-project lifecycle: scoped manual reconciliation

Review: 2026-10-02. Read-only review of `/workspace/scratch/a672c63c3460/cloud-resume/exact-source`; no code or ledger changes, no Git, no native execution, no new test execution.

## Decision

The ordinary standalone Project paths of OpenProject, CreateProject, SaveProject and CloseProject have a coherent documented workflow across 14sp1, 15.1, 16, 17, 18, 19, 20 and 21. Their manual scope can be closed independently of LocalSession. Connect can likewise be closed as **explicit currently enumerated PID attachment**, but not as stale-PID-safe attachment. Native acceptance remains NOT RUN. The existing reported eight-reference builds are supporting evidence, not rerun by this audit. A new consolidated signature/hashes ledger is not supplied here.

A future broad/full-contract completion label must not erase the constraints below. Protected-project authentication, secondary/read-only writes, upgrade, archives, server sessions, commit and server locks are outside this closure. The code's explicit .als execution gate remains appropriate and is not an ordinary-project defect.

## Per-tool disposition

- **Connect / Attach(int processId)**: closeable for one explicit positive PID selected from this release's current `TiaPortal.GetProcesses()` enumeration, then `TiaPortalProcess.Attach()`. No launch, automatic selection or Portal ownership. Rejects repeated attachment. Connection prerequisites remain installed matching runtime/options/HSP, Windows Openness permission and any user-controlled firewall prompt. Source has a separate NoInlining Run method after resolver registration. Limitation: the foundation tracks only PID, not OS process start time. Do not claim it verifies the historical process selected earlier or prevents PID reuse. Adding that guarantee requires a real API/identity design change, not substituting AcquisitionTime.
- **OpenProject / OpenProject(string path,bool dryRun=true)**: closeable for existing current-release ordinary `.apXX` files, with attachment and no existing binding. Executes `portal.Projects.Open(new FileInfo(path))`; no OpenWithUpgrade or authentication delegate. Exact expectedProjectFile/confirmation checked by worker for execution. Same-instance duplicate path is rejected. Cross-instance exclusion, actual version and effective permission are enforced by Siemens; preview does not prove these. File suffix alone does not establish internal project version. Native success grants worker project ownership.
- **CreateProject / CreateProject(string directoryPath,string projectName,bool dryRun=true)**: closeable for existing parent and new child name. Executes `portal.Projects.Create(DirectoryInfo,string)` and reports the resulting Project.Path; preview uses parent/name/name.apXX. No LocalSession API dependency. Filesystem races/native failure are propagated, not silently converted to success.
- **SaveProject / SaveProject(bool dryRun=true)**: closeable for the exact bound ordinary writable project, including a borrowed writable project when explicitly confirmed. Calls Project.Save(), not SaveAs, close or server commit. The manual requires an open project, not ownership by this worker. Scope must not promise secondary-project saving: secondary projects are read-only; BindProject does not check IsPrimary, so native Save permission/read-only rejection can occur. This is an unvalidated precondition and diagnostic limitation, not evidence that writes bypass Siemens protections.
- **CloseProject / CloseProject(bool dryRun=true)**: closeable for the bound ordinary unmodified project opened/created by this worker. Requires ownership and `!IsModified`; otherwise rejects. Calls Project.Close(), never implicitly Save. Clear binding only after native success. The owned/unmodified restriction is deliberately stricter than the manual, not a missing LocalSession feature. Concurrent external edits between IsModified and Close remain a native-concurrency acceptance issue; do not promise atomic no-discard under concurrent editors.
- **Disconnect**: no public FoundationTools/worker operation exists. Do not count it as an implemented/closed member of the 62-tool profile. Internal engine Dispose calls TiaPortal.Dispose; worker normal EOF exits its using block, while host disposal only closes its own stdin/process handle. No TiaPortalProcess.Dispose or process kill. Existing-process attachment is non-owning, matching documented disconnect semantics. Acknowledged explicit public disconnect is a separate feature if requested.
- **GetProject / ListProjects** and **AttachToOpenProject / BindProject**: ordinary project branches are separable from LocalSession. The former enumerates portal.Projects and reads Name, Path and attributes; the latter matches exact Name plus full Path and records borrowed ownership. No server lock is required merely to bind this ordinary Project. This review does not independently close their entire response/attribute-read contracts. LocalSession path/kind identity uncertainty must remain attached to their session branch only.
- **GetProjectTree**: not independently audited here. Do not carry lifecycle/multiuser uncertainty as an automatic blocker to an otherwise proven ordinary tree traversal, but traversal/response contract needs its own evidence.

## Snapshot/process identity distinction

Siemens TiaPortalProcess.AcquisitionTime describes when a diagnostic snapshot was acquired. It is not evidence for OS process creation time, a stable instance token, or UTC. `System.Diagnostics.Process.StartTime.ToUniversalTime()` plus PID is an independent wrapper identity mechanism found in the modern Portal binding code, not in this foundation Attach method. TiaPortal.Dispose, TiaPortalProcess.Dispose and TiaPortalSession.Dispose have different targets and must not be conflated. Reviewed manuals allow termination through TiaPortal.Dispose when the application itself started a no-UI instance and is its sole client; otherwise disposal disconnects the application.

# Exact-root external source deletion candidate

Source-only candidate for exact releases 14sp1, 15.1, 16, 17, 18, 19, 20 and 21. V14/V15 are not aliases. Siemens/native execution, current eight-SDK compilation, backup/recovery and filesystem effects have NOT RUN. No project or source has been deleted during implementation.

The candidate uses it for logical identity across recreated proxies. Session-local GUIDs identify these logical objects, not their names. Object reference identity is deliberately not used: repository native observations show Create/Find can return different proxies. Equality failures propagate without name fallback. Retained deleted proxies can make subsequent equality fail; if that occurs during post-delete readback the outcome is unknown and the session is poisoned, never replayed. Fake-proxy tests exercise equality, replacement and equality failure; exact-release native behavior still needs acceptance.

## Contract and limits

DeletePlcExternalSource retains softwarePath and externalSourceName and requires groupPath="". dryRun defaults true. No extension-insensitive or case-insensitive fallback. Inventory enumerates at most4097 and rejects more than4096, any read failure, duplicate exact names/identities or wrong parent. Root and source identities, exact release/PID/project/software/name and full sorted inventory bind the SHA256 preview hash. A newly created same-name object has a different logical identity and invalidates review. Identity-token budget8192 per engine prevents unlimited retention; exhaustion requires a new explicit session.

Apply requires confirm=true, expectedProjectFile and expectedPlanHash. Existing native-session opt-in and selected standard-provider/offline gates remain. Local sessions, unsupported roots and aliases fail closed. Fresh complete inventory and exact Find/Name/Parent/logical identity are checked before entering Delete. It invokes Delete once, verifies the complete root inventory equals the prior inventory minus exactly that source, and never retries. No blocks are generated, compiled, saved or downloaded. Original ImportPlcExternalSource remains pending and PlanPlcExternalSourceImport apply remains blocked.

Results distinguish planned, not-found-not-deleted, deleted-verified and outcome-unknown. Missing target is explicitly not deleted. Stale confirmed target disappearance is a changed-plan refusal, not an idempotent success. Any exception or readback mismatch after native entry produces unknown outcome and poisons host and worker sessions; transport loss or malformed result also poisons the host. Explicit inspection/new session is required. No automatic backup, save, undo or rollback is promised. Missing-target behavior is wrapper policy, not a Siemens guarantee.

The API evidence does not establish filesystem consequences or recovery. A reviewed preview is not a backup. Native acceptance must use authorized disposable projects, characterize retained block/source-file effects, verify identity across proxies, offline gating, exact-name variants, lost responses and post-delete inventory. Only then can production support be considered.

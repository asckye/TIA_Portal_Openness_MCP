- 遇到过一次 `.git/refs/heads/master` 被写成 41 个空白字符（`git status` 报 "No commits yet"、push 报 "cannot be resolved to branch"）：提交对象与 reflog 都完好，`rm .git/refs/heads/master` 后 `git update-ref refs/heads/master <reflog 里最后的 sha>` 即恢复，`git fsck` 干净。再遇到照此处理，不要重新 clone。
- `Build-Release.ps1` 的 tools-list 闸门要求每个 `[McpServerTool]` 描述的 `[L2][<域>]` 标签已在 `ModelContextProtocol/ToolTaxonomy.cs` 注册（2.7.38 用 `[PLC]` 被拒，改 `[PLC-Software]`；2.7.39 的在线驱动工具用 `[Hardware][ONLINE]` / `[Hardware][ONLINE-WRITE]`，写保护钩子按操作标签拦截；现有域名看 `grep -o '\[L2\]\[[A-Za-z-]*\]' ModelContextProtocol/Tools/*.cs | sort | uniq -c`）；`Check-DeadToolReferences.py` 会把描述里点名的 API 成员名（`CreateOptions`、`GetLayoutFields`…）当成未注册工具名，加进它的 `ALLOWED` 并写明理由。
- 引用多个 Siemens 命名空间时同名类型会撞（`Siemens.Engineering.SiVArc.CreateOptions` vs `Library.Types.CreateOptions`；`MC.Drives.Enums.EncoderType` vs `HW.EncoderType`；V20 的 `MC.Drives.Enums.ConnectOption` vs `Motion.ConnectOption`）：用 `using X = ...;` 别名，不要去掉 `using`。在 `namespace TiaMcpServer.Siemens` 里写 `Siemens.Engineering.X` 会被解析成 `TiaMcpServer.Siemens.Engineering`——要 `global::Siemens.Engineering.X`。
- 工具名不分大小写必须唯一（`CallTool` 的 `AllToolMethods` 用 `OrdinalIgnoreCase`）：`Check-DeadToolReferences.py` 自 2.7.39 起拦截，本地和 `offline-checks` CI 都跑。
- 官方文档站：`POST https://docs.tia.siemens.cloud/api/khub/clustered-search` 体 `{"query":"<类型名>","contentLocale":"en-US","paging":{"page":1,"perPage":10}}` 回 `results[].entries[].topic{mapId,contentId,title,mapTitle}`；`GET /api/khub/maps/<mapId>/toc` 回目录树（`title` / `contentId` / `children`）；`GET /api/khub/maps/<mapId>/topics/<contentId>/content` 回 HTML。GET 的 clustered-search 是 404。脚本模板在会话草稿里没留，照上面三个 URL 重写即可。
- 快速对比 V20 / V21 某命名空间成员（不用装 TIA）：PowerShell `[Reflection.Assembly]::LoadFrom(<dll>)` 后 `GetExportedTypes()` 按 `Namespace` 过滤、`GetMembers(Public|Instance|Static|DeclaredOnly)` 列属性 / 方法签名，两版各存一份文本再 `diff`（2.7.38 用这个发现 V20 的 SiVArc 标记接口与 V21 的 `IEngineeringObject` 差异）。

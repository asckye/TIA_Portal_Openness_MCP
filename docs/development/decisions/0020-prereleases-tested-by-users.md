# 0020 我们不做真机验收，4.0 以 GitHub 预发布交给其他用户测试

- 状态：已采纳
- 日期：2026-10-20
- 决策者：维护者
- 置信度：中
- 相关：取代 [ADR 0013](0013-release-4-0-after-phases-7-and-8.md) 中“真机验收最后集中进行一次”的部分；[ADR 0002](0002-native-behavior-by-family-acceptance.md)；[重构计划](../refactor-plan.md) P8-04、P8-90；[真机台账](../../reference/real-machine-ledger.md)；[发布流程](../release-workflow.md)

## 背景

ADR 0013 定下：4.0 在阶段 7 与阶段 8 完成后发布，并在最后对八个版本集中做一次真机验收。P8-04 的设计另外要求：V20/V21 默认切换到 PlcWorker 之前，先用最后一个引擎测试包在 V20、V21 虚拟机上各跑一次基线（D8）。这两项都需要维护者照看虚拟机：D8 每台约 1.5–2 小时，最终验收覆盖八个版本。开发机上没有 TIA Portal，离线检查无法证明原生行为。

## 选项

1. 保留 D8 和最终八版真机验收：发布前有真机证据；发布要等维护者安排虚拟机时间。
2. 不做我们自己的真机测试，把预发布包交给其他用户测试，离线检查照常执行：更早拿到真实使用反馈；原生行为在发布时仍未经我们验证。

## 决定

采用选项 2（维护者 2026-10-20：“直接发布包，测试的问题就交给其他使用的人来测试了，我们都不进行测试”）。

- 取消 D8 和最终八版真机验收；P8-04j2 合并不再等待 D8。
- 包以 GitHub 预发布发布，版本号形如 `v4.0.0-beta.N`：标为预发布，且不设为最新版。3.3 的三条更新路径都只查询最新版，因此不会向现有用户提示。第一个预发布在 P8-04j2 之后发布。
- 预发布说明附“Not verified on a real TIA Portal”清单，由真机台账与审计虚拟机清单生成。
- 每次发布到 GitHub 前由维护者确认。
- 构建、离线套件、check-all 与 GitHub CI 照常执行，所有检查保留。

## 后果

- 正面：不占用维护者的虚拟机时间；预发布更早到达用户。
- 负面与取舍：
  - 原生行为在发布时仍为 `NOT RUN`，真机回归由使用者发现。
  - V20/V21 切换到 PlcWorker 时没有引擎基线可对照。
  - 按 ADR 0002，D1 行为族在没有真机验收时保持 `current`。
- 后续工作：
  - 发布工具支持预发布（P8-90）。
  - 定义测试者反馈的收集方式。
  - 决定正式 4.0 以哪些反馈为放行条件（重构计划“待维护者决定”第 3 项）。
- 验证方式：
  - 发布工具测试证明预发布带 prerelease=true 且 make_latest="false"。
  - 更新器测试证明正式安装不会被提示预发布。
  - 预发布说明缺少未验证清单时，发布命令拒绝执行。

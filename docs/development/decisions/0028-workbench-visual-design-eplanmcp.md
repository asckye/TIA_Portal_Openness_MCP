# 0028 工作台视觉设计采用 EplanMcp 设计系统

- 状态：已采纳
- 日期：2026-11-01
- 决策者：维护者（提出者：4.0 项目评审报告 3 与 4.1 界面重新设计笔记）
- 置信度：高
- 相关：取代 [ADR 0018](0018-workbench-ant-design.md) 与 [ADR 0021](0021-workbench-eplanmcp-font-and-style.md) 的视觉部分；保留 [ADR 0003](0003-workbench-approval-for-mcp-writes.md) 及[工作台界面设计规范](../design-spec/workbench-ui.md) §11 的审批与 AI 控制红线；共用设计系统“EplanMcp Workbench 设计规范”（https://claude.ai/artifact/Kbjk7iPWb7cMGxdVLbaQsg）；原型 https://claude.ai/artifact/CheYfH18JmAd38q9dkxfvR ；任务 UI-2a…UI-2d

## 背景

工作台（WPF，`src/Studio/Gui`）先按 Ant Design v5 重画（ADR 0018），后来采用 EplanMCP 的 Maple Mono CN 字体和审批按钮规则（ADR 0021）。2026-11-01 的 4.0 项目评审发现：

- 规范正文叠了三层，互相矛盾。
- 正文用等宽字体。
- 深色底色是 #000000。
- 信息架构有重复入口：环境、日志、连接信息、待批请求各出现两处以上。
- 56 epx 顶栏塞了 11 类元素，安全提示没有优先级。
- 一个设置抽屉把安全开关和外观、目录混在一起。

维护者把完整的重新设计排在 4.1，随后决定与 EplanMCP 共用一套设计系统。这套系统基于 Apple HIG：

- token：强调色 #0071E3、系统字体、4 px 网格、圆角 8/12。
- 布局：侧边栏 232 / 列表 320 / 详情。
- 交互：每个决策区一个默认按钮、风险等级、确认面板、撤销提示条、倒计时环。

该系统只有浅色和深色两套主题，部分规则与本项目的红线不一致。维护者于 2026-11-01 逐条裁定了这些冲突（下文 C1–C17）。

## 选项

1. 保留 Ant Design v5（ADR 0018/0021），只整理信息架构：测试改动最少；但两个产品外观不同，评审指出的字体和深色底色问题仍在。
2. 采用共用的 EplanMcp 设计系统，把本项目的红线和无障碍规则写成明确的例外与补充：两个工作台使用同一套视觉语言；需要重写主题，并按批准更新设计值类测试断言。

## 决定

采用选项 2。工作台的视觉设计以共用的 EplanMcp 设计系统为准；本 ADR 写明的例外优先。

**token 与主题**

- 浅色与深色的颜色、字体、间距、尺寸、圆角、阴影和时长 token 取自共用系统。
  - 强调色为 #0071E3（白字 4.7:1）。
  - 链接和文字按钮用 `accent-text`（浅色 #0066CC，深色 #409CFF）。
  - 不再使用 Ant 蓝（#0958D9/#1677FF）和 #000000 深色窗口底色。
- 新增 token，共用系统也采纳（C12、C13）：
  - `border-control`：输入框和控件边界，在所有底色上 ≥3:1。浅色 #86868B，深色 #8E8E93，高对比为 WindowText。
  - `focus-ring`：线宽 2 px，偏移 2 px。浅色 #0071E3，深色 #409CFF，高对比为 WindowText。
  - `hc-outline`：浅色和深色下透明，高对比下为 WindowText。
- 为两个产品新增一套高对比 token。
  - 运行时每个值都映射到 `SystemColors` 键：Window、WindowText、Highlight、HighlightText、HotTrack、GrayText、ButtonFace。
  - 所有卡片、按钮、输入框和提示条加 1 px WindowText 描边。
  - 阴影一律为 none。
  - 状态只靠图标形状和文字表达。
- 工作台照旧自动跟随 Windows 高对比设置。设置 › 外观仍只有“自动 / 浅色 / 深色”。4.0 不提供手动选择高对比：手动选择需要一套固定调色板，不在本决定范围内。
- 字体（C9）：
  - 正文：Segoe UI Variable Text、Segoe UI、Microsoft YaHei UI。
  - 等宽：Cascadia Mono、Consolas、Microsoft YaHei UI。
  - 等宽只用于工具名、路径、ID、日志和时间。
  - 移除 Maple Mono CN 及其随包文件。
- 字号阶梯采用共用系统的 large-title 28、title-1 22、title-2 17、headline/body 14、callout 13、footnote 12、mono 13/12；16 个 `Ui.FontSize.*` 别名并到这些值上。

**尺寸与布局**

- 控件高 32 epx；表格和列表行高保持 36 epx（LAY-12），不采用共用系统的 44 px 行高下限（C11）。审批决策按钮和确认面板按钮用共用的 `control-lg`（44 epx）。
- 圆角：控件 8，卡片、确认面板和提示条 12，开关和徽标全圆。
- 窗口结构：
  - 侧边栏 232 epx，窗口宽度小于 1200 epx 时收为 64 epx 图标栏（C11）。
  - 工具栏放页名（large-title）和本页操作，窗口按钮在其右侧。
  - 工具栏下方是持续显示的提示条。
  - 内容区按页面类型选用列表 320 + 详情、分组列表或表格。
- 图标：暂时沿用产品自己的 16 网格图标，按 18 epx 绘制（C16）。

**导航与信息架构**

- 一级页面 8 个，Ctrl+1…Ctrl+8 与视觉顺序一致：审批、项目、版本控制、AI 调用、审计日志、环境体检、日志与诊断、MCP 与客户端。设置（Ctrl+,）固定在侧边栏底部。
- NAV-01 的上限改为 8（C14）。删除隐藏的导航别名（概览、程序块）。`WorkbenchPage` 协议枚举不变，`Blocks` 保留为项目页的别名，MCP 契约因此不变。
- 侧边栏当前项同时有选中底色、指示条和 SemiBold 文字（C17）。
- 每类只有一个主入口：
  - 待批请求 → 审批页，取代审批抽屉。
  - 环境 → 环境体检页。其他页面只显示一条链接到该页的提示条。
  - 日志和诊断包 → 日志与诊断页。
  - 连接信息 → MCP 与客户端页。
- 设置改为页面，分三区。其中 AI 控制区仅人可改。
  - 外观：主题、语言。
  - 服务：版本、更新、目录、关于。
  - AI 控制：允许 AI 控制工作台界面、写操作审批与超时、原生交叉引用。
- 侧边栏底部只显示状态：MCP 服务、TIA Portal 与项目、写操作审批开/关。写操作审批开关只在 设置 › AI 控制（C7）。
- 安全提示优先级（同时出现时合并为一条）：
  1. 待批计数（侧边栏徽标，永不隐藏）。
  2. 审批已关。
  3. 工作台控制通道不可用。
  4. AI 预填，待确认。
  5. “AI 操作了界面”（短暂显示）。
- AI 可定位的页面白名单是一个 `WorkbenchPage` 枚举列表，不含审批页和设置页（MCP 与客户端页照旧不含）。审批页或设置页处于当前页时，拒绝 AI 的显示和预填（C15）。
- 界面用词：MCP 宿主叫“服务 / Service”，不叫“引擎 / Engine”；TIA 项目叫“项目 / Project”，不叫“工程”。

**审批与确认**

- 风险等级（窄定义）：
  - 破坏性：ONLINE-WRITE 工具（例如下载到设备）、`Delete*` 工具，以及设置了 `confirmDelete` 或 `deleteAtTarget` 参数的调用。
  - 写入：其余需要审批的调用，包括带 overwrite 的导入。
  - 判定不使用 MCP 的 `destructiveHint` 注解。等级在宿主侧生成审批项时计算；生成计划取各步骤中的最高等级。
- 每个写请求单独决定，没有“全部批准”。
- 写入请求：拒绝与批准视觉权重相同（同样的底色、尺寸，等宽单元格）。两者都不是默认按钮或取消按钮，Esc 不会拒绝（C1）。
- **对 KEY-05 的明确例外**：回车永远不批准写入请求，即使焦点在“批准”上也不批准；只有空格或鼠标点击能批准。
- 破坏性请求：
  - “拒绝”是默认按钮（强调色底，响应回车）（C1）。
  - “批准并……”用 `destructive-text`，点击后打开确认面板。
- 写入、破坏性审批以及所有确认面板中，“拒绝”或“取消”都在左侧（C5）。
- 破坏性确认按钮可以用 Tab+空格或它的 Alt 访问键触发，永远不响应回车；“取消”是确认面板的默认按钮并响应 Esc（C6）。
- 审批两个按钮不加访问键（C4）。其他对话框、确认面板和页面按钮及主要表单字段保留访问键（KEY-06），并在标签中显示。
- 审批自动打开时焦点放在标题上，绝不放在决策按钮上。AI 切页后的 500 ms 输入保护覆盖两个按钮。
- 倒计时用环加文字显示，读屏只在 30 秒和 10 秒时播报。超时即拒绝。
- 拒绝后不提供撤销（C8）：MCP 调用立即返回，审计链立即记录。反馈是一条短提示：“已拒绝……”或“已批准，正在 TIA Portal 中执行”。

## 后果

- 正面：
  - 两个工作台共用一套设计语言。
  - 正文改用比例字体。
  - 入口更少、更清楚。
  - 安全提示有明确优先级。
  - 两个产品共用一套经过测试的高对比主题。
- 负面与取舍：
  - 主题和布局要整体重写，现有截图和钉住布局的 GUI 断言都会变化。
  - 一级页面从 7 个变成 8 个。
  - 审批页和设置页不再是临时浮层：拒绝 AI 的判定改为看当前页。
  - 对 KEY-05 增加一处例外。
- 测试规则：维护者于 2026-11-01 批准把编码设计值（尺寸、宽度、页数、颜色、字体）的 GUI 测试断言改为新值。行为、无障碍、键盘、审批和 AI 红线类断言不得放宽。新规则需要新增断言：破坏性默认按钮是“拒绝”、回车永不批准写入请求、按当前页拒绝 AI、风险等级在宿主侧计算。
- 后续工作：
  - UI-2a：token、主题、字体、焦点环。
  - UI-2b：窗口外框、导航、设置页、提示条。
  - UI-2c：审批页。
  - UI-2d：其余页面与用词。
  - UI-2b 与 UI-2d 都合并后才能发布：UI-2b 移除的诊断包入口由 UI-2d 重新加上。
  - 更新 workbench-ui.md：NAV-01、NAV-03、NAV-08、KEY-05（例外）、KEY-07、APR-04、AI-01、LAY-12、§4–§6 与附录 A；同步更新工作台偏差清单。
  - 把 ADR 0018 和 0021 标为“部分被 0028 取代”（视觉部分）。0018 中“对话框确认按钮在右”的表述保留，与 C5 一致。
- 验证方式：
  - ThemeSurfaceTests 与 AccessibilityTests 固定浅色、深色和高对比的新 token 与对比度。
  - 新增测试覆盖：破坏性默认按钮、写入审批时的回车与 Esc、风险等级。
  - WorkbenchControlTests 覆盖页面枚举白名单。
  - 渲染测试和截图覆盖 1024×640 与 1366×860、中英文、浅色/深色/高对比。

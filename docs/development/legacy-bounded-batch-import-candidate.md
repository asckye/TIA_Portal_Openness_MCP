# Bounded batch imports: source candidate (2026-10-02)

`ImportBlocksFromDirectory` and `ImportPlcProgramFromDirectory` are registered in the LegacyHost source-preview catalog. These are application loops over documented single-file composition imports, not a Siemens directory import API. They are **partial safe-contract candidates**, not full baseline parity, native acceptance, schema validation or an eight-release SDK build. The new files are `PlcBatchImportPolicy.cs`, `PlcBatchImport.cs` and `BatchImportContract.cs`.

## Scope and intentional compatibility differences

- Blocks tool scans the top directory. Program tool scans recursively. Both require an absolute existing source directory; no temp files, directory creation or target group creation occurs.
- Only one root per file: ordinary `SW.Blocks.FC`, FB, OB, GlobalDB, InstanceDB, `SW.Types.PlcStruct` or `SW.Tags.PlcTagTable`. Blocks tool accepts only block roots. Multiple/mixed/unknown roots are errors, not skipped. Language allowlist is LAD/FBD/STL/SCL/DB; unsupported/protected/Safety XML is refused. V14 SP1 SCL is always refused; other SCL must contain implementation elements rather than interface alone. Presence is a minimum check, not schema/completeness certification.
- Exact Engineering producer matches selected release. No version rewrite, cross-release migration, renumber, XML repair, software-unit/technology/system object traversal or source generation.
- Preview defaults true. `overwrite=false` is the only supported mode and maps directly to `ImportOptions.None`. `overwrite=true` is refused before file/native lookup; it never becomes Override or Rename.
- Program `compileAfter=false` is the safe default. `compileAfter=true` is refused before any import because project-wide compile coverage remains blocked. `stopOnImportFailure=false` and nonempty technology destination are also refused. Imports never compile, save, switch offline, download or roll back.
- `Imported` contains names from successfully verified native returned objects. `Failed` contains `Path`/`Error` summaries; `ImportedCount`, `FailedCount` and complete `Items` add explicit progress. This still is not full pinned-V17 response parity.

## Planning and execution

1. Preview validates a full bounded selection: default 128, hard maximum 256 files; at most 4 MiB each and 32 MiB total, 4096 filesystem entries, 1024 scanned directories, 1024 native groups per block/type/tag family and 4096 total target objects. DTD/external entity resolution is disabled; XML depth 64, character and regex length/time budgets apply. Case-insensitive path aliases, input links/reparse ancestors, duplicate logical names and known cross-group/name/number collisions refuse the whole plan. FC/FB numbers remain separate; global and instance DB share a number namespace. No silent deduplication or truncated success.
2. Manifest order is caller-provided `importOrder` (exact relative slash-separated file paths). Preview without order suggests ordinal path order. Apply must contain every selected file exactly once. This is **not dependency analysis**. Recognized quoted UDT and instance-of references must already exist or precede the consumer; recognized cycles/missing references fail. Quoted Datatype dependencies require UDT identity, while InstanceOfName requires FB identity; one kind cannot satisfy the other. Quoted FB multi-instance Datatype is conservatively outside this recognized subset. Other dependency coverage remains unknown, reported as `unverified-caller-order-required`. Native missing-reference bypass flags, synthesized instance DBs and automatic reorder/retry are absent.
3. Hash binds ordered paths, original file bytes, XML identities, exact release/PID/project/software/groups, selection directory/regex/recursion, target inventory, None and stop-on-first-failure. Apply requires `confirm=true`, exact `expectedProjectFile`, complete `importOrder` and `expectedPlanHash` from reviewed preview. All inputs are opened with `FileShare.Read` and remain read-locked through every import; hash is recalculated before any mutation and the selection is rescanned. No output write occurs in preview.
4. Immediately before each native call, adapter rechecks bound project/PID, exact software owner and destination group references, and positively identified standard OnlineProvider Offline state. LocalSession, R/H and ambiguous/unknown targets refuse. No claim is made that these checks lock an external TIA UI session or prevent every external project race. Native None remains the final collision boundary.
5. Every returned object is retained. Null/empty/multiple/unexpected identities or fixed-number mismatch are uncertain outcomes, never success inferred from filenames. One-root wrapper expects exactly one matching return. Native automatic numbering is recorded from returned blocks when input omits Number. The native Parent check is source-reviewed only; all-release SDK/native confirmation is still pending. Returned group labels require native Parent reference agreement with the exact selected group; mismatches/unreadable ownership are retained as unverified evidence and fail. Non-block Number fields are refused during planning because their returned-number validation is outside this slice. Unknown native kinds/null entries on failed calls remain visible in the host partial response.
6. First failed check/import/verification returns earlier successful outcomes, one failed entry, and later `not-attempted` entries. No rollback or replay. `RequiresSessionReset=true` poisons the host session; raw worker stays alive and refuses further mutations while allowing read-only inspection. Input files remain original. Any native mutation on a failed call may have occurred; the result does not pretend otherwise.

Filesystem ancestry checks and Windows sharing are not an atomic adversarial no-follow proof. Use trusted, owned, stable export directories on Windows. Linux tests demonstrate policy/fake callback behavior, **not Windows file locking or Siemens import acceptance**. Execution remains explicitly gated by `--native-session` in the source-preview host.

## Verification and remaining gates

`BatchImportTests` covers options-before-I/O rejection, dry-run no callback/write, XML logical names versus filenames, reviewed order/hash changes, input additions/changes, bounds, DTD/depth, mixed/unknown roots, release/Safety/V14 SCL refusal, duplicate/cross-group/name/number conflicts, UDT dependency ordering/cycles, missing instance FB, native return verification, partial outcomes, target change, poison/no replay and unchanged input bytes. `BatchImportDispatchTests` invokes both MCP facades with fake worker/native callbacks, checks string-array schema, safe defaults and pre-dispatch gates, and preserves partial outcomes before refusing replay. No Siemens assembly or worker process is loaded.

Final integrated Linux aggregate: **2251 passed, 0 failed, 3 explicit skips**. An independent source review reproduced this result; the final bounded-read length hardening was rerun with the same result. LegacyHost managed build passed with zero errors and two existing TiaVersionCatalog nullable warnings. These are source/offline checks only. Current-source Windows eight-release typed compilation, installed-schema validation, Windows lock behavior and authorized disposable-project native acceptance are **NOT RUN**. `PlcBuildAndImport` remains unimplemented: offline V21 builders are candidate generators, not automatically import-ready outputs.

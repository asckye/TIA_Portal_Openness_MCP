# V20/V21 document import: bounded implementation decision

Research date: 2026-10-02. Read-only source and official-manual inspection; no Siemens runtime, project, native acceptance, commit or push. This document proposes wrapper policy, not a statement that the API is already safe or implemented.

## Decision

Implement a bounded single-document preview and source-only apply candidate using the now-verified `ImportDocumentOptions.None` contract. Exact V20/V21 SDK XML says None means “Throw if exists”; Override means “Override existing.” This resolves the initial no-overwrite-option evidence gap. The native call requests rejection of existing objects, but does not prove collision normalization, timing, atomicity or rollback. Those unknowns do not alone block a source candidate when every attempted failure reports possible partial mutation and poisons the session. The remaining implementation gate is a defensible single-declared-block admission scanner: filename or a regex match must not stand in for document identity. Exact builds and authorized native acceptance remain separate. Native execution is not authorized in this work.

## Verified API evidence

Both [V20 import API](https://docs.tia.siemens.cloud/r/en-us/v20/tia-portal-openness-api-for-automation-of-engineering-workflows/export/import/importing/exporting-data-of-a-plc-device/blocks/importing-program-block-from-document) and [V21 import API](https://docs.tia.siemens.cloud/r/en-us/v21/tia-portal-openness-api-for-automation-of-engineering-workflows/export/import/importing/exporting-data-of-a-plc-device/blocks/importing-program-block-from-document) describe `PlcBlockComposition.ImportFromDocuments(DirectoryInfo, string fileNameWithoutExtension, ImportDocumentOptions)` returning `DocumentImportResultForBlocks`. Relevant result members are `State`, `Messages`, `ImportedPlcBlocks`; the imported association may contain multiple blocks. Prerequisites include an attached Openness application and open project. The pages list None, Override and two culture options, but contain enum spelling, namespace and result-type inconsistencies. Use exact SDK metadata, not the prose spelling, for compilation. Existing full-engine source uses `None`, `Override`, `SkipInactiveCultures`, `ActivateInactiveCultures`; only None should be admitted by the proposed candidate. The later exact SDK/XML evidence below resolves its meaning as rejection when an object exists. Do not infer the library-import culture restrictions apply identically to block import.

The [V20 base format manual](https://docs.tia.siemens.cloud/r/en-us/v20/creating-and-managing-blocks/exporting-and-importing-blocks-in-simatic-sd-format-s7-1200-s7-1500/exporting-and-importing-blocks-in-simatic-sd-format-s7-1200-s7-1500) documents LAD, DB and PLC-type support for S7-1200/1500. It describes code/resource pairs and assigns imported block identity from the declaration inside the code file. Filename is not proof of block name. It warns of same-name overwrite, excludes know-how protection and does not support mixed languages in that original release description.

The [V20 Update 4 STEP 7 notes](https://docs.tia.siemens.cloud/r/en-us/v20-updates/tia-portal-updates-readme/improvements-in-step-7/improvements-in-update-4) extend SD to SCL, FBD and LAD/FBD with SCL networks through Openness and VCI. Pure SCL cannot contain other network languages; STL is unsupported. Textual SCL interfaces have a data-loss warning. Older LAD exports must be regenerated after the format change. MLC inconsistencies can require the separately installed SimaticSdEnabler add-in. Do not run or install it implicitly. SDK major version cannot establish installed update level.

The [V21 format manual](https://docs.tia.siemens.cloud/r/en-us/v21/creating-and-managing-blocks/exporting-and-importing-blocks-in-simatic-sd-format-s7-1200-s7-1500-s7-1200-g2/exporting-and-importing-blocks-in-simatic-sd-format-s7-1200-s7-1500-s7-1200-g2) supports LAD/FBD/SCL/DB/types and optional `.s7res` when multilingual comments exist. Resource text is YAML 1.2.2, referenced by MLC IDs; preserve quoting and bytes. Preserve block and network pragmas including language/editor mode, optimization, version and optional manual block number. OB event type is lost and import creates a cycle OB with an automatically assigned three-digit number. Protected blocks are excluded; supervisions, alarms, SiVArc, AT and some attributes are unsupported or omitted. Same-name overwrite is again warned about. These constraints preclude a lossless-project-backup claim.

## Implementable candidate policy (wrapper design, intentionally narrower)

1. Exact releases 20/21, one existing local Windows directory, one bounded basename, one exact PLC software and existing ordinary root/user group. No root fallback, group creation, software units, safety/system blocks, OBs, UDT/type documents, preservePath or batch recursion. Do not call a directory a single block solely because it has one basename.
2. Require `.s7dcl`; for conservative V20 policy require the matching `.s7res`, even though that restriction is wrapper policy rather than proof every valid V20 document needs it. For V21 preserve an optional resource; if code references MLC IDs, missing resources must not be accepted as complete. Reject symbolic/reparse paths, ambiguous case/stem files, alternate same-basename source formats and unbounded files. Hold read handles against write/delete and hash exact bytes. Never normalize or rewrite BOM, newline, pragmas, resources or code.
3. The first implementable admission subset is one ordinary LAD FC/FB or global DB. Use a comment/string-aware structural scanner for exactly one top-level matching declaration/end, declared identity and all network language pragmas. Reject unknown constructs, extra declarations, conflicting language, unknown identity, OB/TYPE, explicit block-number pragmas and instance DB references in this narrow subset. A regular-expression hit alone is not a single-block proof. Scanner acceptance is wrapper eligibility, not Siemens syntax validity.
4. Require declared block name to exactly equal requested basename as an explicit wrapper simplification. Parse identity before collision inventory. Inventory all applicable ordinary block groups with explicit caps; reject incomplete/ambiguous traversal and name collisions anywhere in scope, including case-fold matches. Recheck inventory and exact project/session identity at the apply boundary. A preflight inventory is not race protection.
5. Preview writes no staging files, takes no offline action and invokes no native import, compile, save, download or repair. Report input hashes, resource presence, declared identity/language, version/update provenance (unknown remains unknown), target and collision snapshot, validation limits and a deterministic plan hash. Bind all these fields, policy version and accepted option to the hash. For LAD provenance, expose the pre-Update-4 incompatibility rather than manufacturing certainty from text.
6. Source-candidate apply with verified native None requires exact preview hash/project confirmation, fresh target resolution, offline prerequisite, stable input files and no overwrite/rename/fallback. Isolate one typed native call. Any callback start means attempted=true and mayHaveChanged=true on exception, null, partial state, Failure or readback failure. Never assert zero mutation from a non-Success state. Poison and stop; retain diagnostics and input evidence; never retry/rollback/delete automatically.
7. Success requires native Success plus exactly one returned imported block with the declared identity and exact target-group existence check. Return native messages and imported identities. ExistsVerified is not contentVerified; compilation/save/download remain notRun. Do not restore number or other attributes after import. A later explicit readback can compare SD artifacts but cannot certify all project attributes.
8. Batch import should reuse this single-item contract only after it exists. Use bounded deterministic manifests, cross-item identity collision detection, separate notAttempted/attempted/succeeded/failed statuses and stop after the first ambiguous/native failure. Do not copy the full wrapper's continue-after-failure semantics.

## Current full wrapper differences that must not leak into candidate

`Portal.Blocks.cs:1118` implements the single call, resolves the target without fallback, requires native Success, and records native imported names. The null/non-Success check at 1192 and message at 1195 claim the document set was not imported. Additional number-restoration writes occur at 1208–1215. Neither behavior belongs in the candidate.

`Portal.Blocks.cs:1277` batches top-level `.s7dcl` files and treats resources as optional. Nullable target resolution occurs at 1302; lines 1330–1332 fall back to root whenever resolution yields null, including an unresolved nonempty groupPath. Lines 1347–1348 claim the whole document was not imported after a non-Success result. Catches 1351–1359 append errors without breaking the 1317–1361 loop; the outer catch 1364–1367 also logs and returns successful items at 1369. That is not evidence for transactional batch safety. `Portal.EngineeringAudit.cs` provides exact existence checking and optional SD readback; content completeness remains unknown.

The local reference skill `reference/siemens-openness/skills/simatic-sd/SKILL.md` has older generalizations (V21-only framing, mandatory pair, deleting exports first, accepting anything except Failure). Official versioned evidence and current no-overwrite policy take precedence.

## Exact SDK/XML evidence received after initial web research

The parent reported a read-only static inspection of exact V20 and V21 SDK/XML bytes, child task `01a0fca8-2831-76f4-a8a9-0bd5a1cc1027`, turn `01a0fd90-818e-7007-95ae-eb26f4c1c275`. Evidence SHA-256: `3f11b56aae6452b6834de6090c81704e09749353e8446e98ed521f170beecbb8`. This is attributed static evidence, not an independent runtime check by this research worker.

- Both versions: `None=0`, XML “Throw if exists”; `Override=1`, XML “Override existing”; `SkipInactiveCultures=2`; `ActivateInactiveCultures=4`.
- Both versions: the exact three-argument ImportFromDocuments overload returns DocumentImportResultForBlocks; State/Messages are inherited from DocumentImportResult.
- ImportedPlcBlocks has exact type `Siemens.Engineering.SW.Blocks.PlcBlockAssociation`. It has a read-only indexer, Count, IsReadOnly, Parent, typed IEnumerator<PlcBlock>, Contains and IndexOf. V21 directly exposes Any; V20 does not. Neither association exposes Find. Use enumeration or indexer for results, and the target composition's Find for exact existence checking.
- Result-state numeric values reported: Success=0, partial state=1, Failure=2. Use the actual enum identifier in the typed build; success-only acceptance need not reference the partial identifier explicitly.

The XML does not establish normalization, race timing or rollback. The candidate can now be implemented with None as the documented reject-existing option and conservative possible-mutation reporting. Do not hold functional source progress waiting for a claim of atomic no-change on failure. A restricted structural scanner, unchanged bytes, complete collision preflight, exact returned identities, and poison/stop on ambiguity are still required.

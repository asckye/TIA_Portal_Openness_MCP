# P8-04 引擎退役与八版统一设计

状态：现行（设计）· P8-04b、P8-04d1 已合并，其余任务状态以 [重构计划](../refactor-plan.md) 为准 · 最后核对：2026-10-13，master `69229795`

[设计规范索引](../design-spec/README.md) · [架构决策记录](../decisions/README.md) · [阶段 7 设计](p7-host-worker-split.md)（历史记录） · [阶段 8 迁移方案](../phase8-port-plan.md)

本设计记录 2026-10-13 的两次调研及维护者的决定：

- 第一次调研以 master `5635887c` 为基线，盘点 V20/V21 引擎仍承担的职责，拆出 P8-04 的任务。
- 第二次调研以 master `d0849871` 为基线，从版本差异、剩余工作、架构、检查体系、发布就绪五个方面审查整个项目。

详细的文件与行号清单留在维护者本机的调研记录中，不进仓库。本页只记录结论、决定和任务，代码位置写到文件和类型。

## 1 原则

维护者于 2026-10-13 决定：**除注册的工具集合与官方 API 要求的差异外，V14 SP1、V15.1、V16、V17、V18、V19、V20、V21 八个版本使用同一套逻辑与流程。**

- 工具集合：某个工具只有在官方 API 至少支持它的一个操作时才在该版本注册。部分支持的工具拒绝缺少 API 的操作，返回 `UNSUPPORTED_CAPABILITY`。
- API 要求的差异：同一功能在不同版本的 API 写法不同，用 `src/Shared/TiaFeatures.props` 的特性符号区分；V21 的 Siemens 程序集拆成多个文件。
- 除此之外，按版本走不同逻辑、不同默认值、不同文字或不同包装，都要统一。不再推荐 API 未要求的按版本行为。

## 2 现状结论

1. 35 个能力族已全部迁到 Foundation 适配器（B1–B12）。V20/V21 上已没有工具经 `engine.invoke` 进入引擎代码；`ToolExecution` 表里的 `"worker"` 只是标签。
2. 引擎在 V20/V21 上仍提供：承载 `PlcFoundationEngine` 的进程及约 49 个回调；`engine.status` 与 `engine.observe`；`worker/tool-catalog.json`；引擎通道配置（请求关联号、超大回复落盘、结果暂存）；`TiaMcp.Engine.V2x.exe` 命令行。
3. PlcWorker 已能为 20/21 编译，打包时跳过。
4. 第二次审查发现，除引擎路径本身外，八个版本之间还有约 30 处 API 未要求的差异（第 5 节），以及若干已影响用户的缺陷（第 6 节）。

## 5 统一项

替换 worker 期间（P8-04c 至 P8-04l）契约与响应保持零差异。下列统一在 P8-04n 中进行，旧版的行为变化逐项列出，由最终真机验收覆盖。

- **n1 目录与呈现**
  - 八个版本都提供精简工具清单，并默认启用，`--profile full` 切换。
  - 统一服务器说明、提示词与资源（按版本的工具集合过滤）。
  - 统一档案名和 `--catalog` 字段；退役 `IsFullEngine`、`SupportState`、`WorkerKind`。
  - 工具发现元数据、行内示例和 `GetToolUsage` 都按会话版本取值。
- **n2 调用流程**
  - 包括迁移工具在内的全部工具走同一条准入、审批与审计路径，审计只有一个宿主标签。
  - 一条行为披露规则和一段文字，由真机台账驱动。
  - 共享会话语义在八个版本上一致。
  - 准入统一由能力表驱动，`ToolVersionPolicy` 的内容并入能力表。
  - 统一可在无 TIA 时运行的工具分类。
- **n3 文字**：工具描述与错误消息中的“engine”字样，以及写错版本号的提示。
- **n4 工作台与插件**
  - 版本控制页在 V16–V21 经 MCP 读写，退役只读桥接。
  - 环境检查与修复按所选版本进行；统一默认版本。
  - 插件的版本选择与说明。
- **n5 适配器与其他**
  - 可选产品（SiVArc、Startdrive、DCC）在有强类型 API 的版本上都用强类型实现。
  - 防崩溃保护在所有存在该类型的版本上生效。
  - 生成记录的见证方式按工具注册选择。
  - 技术对象导出、DCB 库导入、另存为等按 API 实际范围开放。
  - 版本号和缺数据字段的表示方式统一。
  - 线程模型（第 3 节）。

需要证据后才能定的项目：

- V20 库导入选项限制；
- V18/V19 是否确有文档导出 API；
- 只输出 V21 格式的构建工具；
- `PROJECT_SCAFFOLD` 的版本范围；
- `.s7res` 文件在 V20 上是否必需；
- V14 SP1 的 SCL 是否只有接口。

## 7 真机验收

最终八版真机验收至少覆盖：

- 安装、只读安装与迁移；环境检查与 `doctor`。
- 精简与完整清单；提示词与资源；stdio 与 HTTP。
- 连接与附着、各族读与预演、每族一次经确认的写入（只写测试项目）。
- 审批与审计；租约、恢复与 TIA 进程丢失；D6。
- V20/V21 PlcWorker 路径与 D8 基线对照，包括 V21 可选产品。
- 生成框架；工作台控制与 AI→人接力；更新器升级与回滚。

估计需要 60–85 小时虚拟机时间。所需的虚拟机、TIA 补丁级别、许可和可选产品由维护者准备。哪些台账行阻塞 4.0，在阶段 4 由维护者确认。

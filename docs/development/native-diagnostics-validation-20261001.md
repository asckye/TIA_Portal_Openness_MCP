## 完成的实现

发布构建自动清点并包装引擎侧 Openness 调用，覆盖直接方法、属性、构造器、反射、集合遍历/释放以及对象虚方法。每个边界使用唯一调用 ID，写入执行前后阶段、调用位置、对象访问链、缓存工程绑定、进程/线程、公寓模型和异常类型链。日志不读取原生属性来补充上下文，不记录密码、脚本或变量值。

构建会拒绝未包装的受检边界和不支持的动态调用方式。包装器独立按调用点生成，修复了早期集中生成类型导致纯本地租约操作提前加载 Siemens DLL 的问题。`ReadNativeInvocationLog` 同时读取当前及 `.previous` 轮转记录，仍保持有界读取和截断记录统计。

延长压力测试还发现早期生成器存在私有嵌套类型访问错误：`MigrationPages.Expire` 的一分钟定时清理触发 `MethodAccessException`，导致本地测试 worker 退出。Windows 应用程序事件 1026 给出了生成调用点，问题属于本次候选诊断代码，并非 TIA。包装器随后移入原调用者作用域，并增加私有类型、嵌套泛型、直接执行定时清理路径的回归检查。该失败运行保留在 `bin-build`，不计入最终通过证据；压力脚本也改为失败时仍保存 stderr 和异常桥接响应。

集合语义补查还复现了已类型化集合经过 `Cast<T>()` 后失去原有计数/复制快捷路径的问题。已修正为保留原引用，只对真正需要惰性转换的非泛型来源加适配，并用专门拒绝枚举的替身验证没有额外遍历。

## 范围与限制

覆盖的是本项目引擎发起的 Openness 边界，不是改写 Siemens SDK 或遍历服务进程的内部实现。构建期覆盖清单并不代表这些原生 API 都已在 TIA 上执行过；开放泛型有通用行为测试，不能当作每一种真实类型组合均已执行。

原生阶段每次写入并刷盘会有开销，真实工程上的耗时、长时间运行和 Windows/TIA 硬崩溃诊断仍需获准后在虚拟机验收。日志路径是观察到的访问链，不能视为额外查询确认过的规范工程路径。PLC 原生交叉引用继续默认关闭；本次没有确认此前崩溃的服务端根因。

使用及机制见[细粒度诊断说明](native-call-diagnostics.md)。先前会话保护与 HMI 删除验收记录见[历史记录](session-stability-validation-20261001.md)。
